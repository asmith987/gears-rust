# Durable-execution engines vs in-house multi-tenant task engine

Research date: 2026-10-28. Systems: **Temporal** (OSS server + Temporal Cloud), **Restate** (OSS server + Restate Cloud/BYOC), **DBOS** (Transact library + Conductor/DBOS Cloud).

Support levels: Yes / Partial / No / N/A. "not found" = could not verify in docs. Where a "how" is from general product knowledge rather than a page fetched for this report, the source is the canonical docs page for that feature. Treat those as lower confidence and re-check before quoting.

---

## 1. Temporal

Recent changes (2025–2026):
- **Task Queue Priority & Fairness: GA on 2026-05-05** (Cloud + Server, all SDKs). In Cloud, Fairness is a paid per-namespace toggle.
- Worker Versioning, multi-region/multi-cloud replication and Capacity Modes are GA (Replay 2026).
- In preview or pre-release: Standalone Activities, Serverless Workers (pre-release), External Storage for large payloads, Rust SDK, Workflow Pause (pre-release). The Workflow Streams library is new.
- Workflow History Export (Cloud) is GA.

## 2. Restate

Recent changes (2025–2026):
- v1.6: retry policy can **pause** an invocation (now the default) or kill it when max attempts are exhausted.
- **v1.7.0 (2026-06-18):** scope-based **concurrency limits** (experimental at launch, behind `experimental_enable_vqueues`) and `restate rules` commands.
- **v1.8.0 (2026-10-14):** **VQueues on by default**, scopes and limit keys GA-path, service protocol v7, and a node-wide invoker concurrency limit (default 24,000).
- v1.8.1 (2026-10-21): opt-in recording of **signals for not-yet-started invocations**.
- Restate Cloud: SOC 2, HIPAA and SSO (Feb 2026); BYOC (Jul 2026).
- **Still planned (not shipped):** rate limits/throttling, invocation priorities, backlog limits.

## 3. DBOS (Transact + Conductor / DBOS Cloud)

Recent changes (2025–2026):
- Partitioned queues are now **10× faster** (Aug 2026), and partitioned plus queue-wide limits can be set on one queue (Sep 2026).
- Debouncer; `fork_workflow` and `rewind_workflow`.
- Schedules API (`create_schedule`, backfill, pause).
- Streams (`write_stream`/`read_stream`).
- Patching (`DBOS.patch`).
- Go and Java SDKs.
- SQLite system DB (default in Python, supported in Go).
- Conductor CLI.

## Cross-system takeaways for the in-house design

1. **Weighted per-tenant fairness:** only **Temporal** ships it natively (GA May 2026): fairness keys with weights, stride scheduling, and per-key RPS. It is paid in Cloud, applies per partition, and keeps state for only the top 100 keys across restarts.
2. **Per-tenant concurrency caps:**
   - **DBOS** has `partition_concurrency` and `partition_limiter`.
   - **Restate** (1.7/1.8) has hierarchical scope/limit-key concurrency rules, but no rate limits or priorities yet.
   - **Temporal** has no native per-key concurrency limit; users build semaphore workflows.
3. **Priorities:** Temporal 1–5 tiers (strict) and DBOS integer priority. Restate has none (planned).
4. **Authorization:** all three are coarse.
   - Temporal: namespace-level roles (custom Authorizer if self-hosted).
   - Restate: request signing plus Cloud API keys, nothing per scope.
   - DBOS: DB credentials plus Conductor RBAC (paid).
   - None offers per-task or per-tenant ACLs on start/signal/cancel.
5. **Dependency model:** none has declarative DAG edges added after creation; all express dependencies imperatively in code (child calls, signals, awakeables, promises).
6. **Waits declared before start:**
   - Temporal: SignalWithStart and UpdateWithStart.
   - Restate: 1.8.1 opt-in signals to not-yet-started invocations.
   - DBOS: send-by-ID buffering is unverified.
7. **"Latest wins" semantics:** Temporal `TERMINATE_EXISTING` and DBOS Debouncer (last inputs win). Restate has none.
