# Flow: arm a wait, start the action, then park

A worker that triggers the event it waits for (here: it asks the payment service to charge order `o-17`, whose reply is an `orders.paid` event) must not miss a fast reply. It **arms** the group first (`park: false`): the condition starts matching at once while the task keeps running under the same lease. Then it starts the action and **parks**. Wait timeouts start at park, not at arm.

## Setup
- Event fixtures as in [waits/event 1.01](../event/1.01-positive-matching-event-resumes-task-with-header-only.md): waitable topic `gts.cf.core.events.topic.v1~acme.orders._.order_events.v1`, event type **orders.paid** `gts.cf.core.events.event.v1~acme.orders._.paid.v1~` with the single subject type `gts.acme.orders._.order.v1~`; `{worker_a}` has broker `consume` on all three in tenant A.
- `{task_1}` (**render**, queue **reports**) is `running` under lease `{lt_1}`.

## Exchange 1 — arm (`T0`)

```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "mode": "all",
  "park": false,
  "conditions": [
    { "kind": "event", "event_type": "gts.cf.core.events.event.v1~acme.orders._.paid.v1~",
      "subject_id": "o-17", "timeout_secs": 3600, "on_timeout": "fail" }
  ]
}
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "wait_group": { "id": "{wg_1}", "mode": "all", "parked": false,
    "conditions": [ { "id": "{wc_1}", "kind": "event", "state": "pending", "timeout_at": null } ] },
  "task_state": "running" }
```

- The call returns once the condition is committed; from then on every event the consumer processes is matched against it (DESIGN.md:914).

## Exchange 2 — the worker asks the payment service to charge `o-17` (not shown), then parks (`T0+2m`)

```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions/park HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "checkpoint": { "charge_requested": true } }
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "parked": true, "task_state": "waiting" }
```

## Side effects
- After Exchange 1: task `{task_1}` state is `running`; `{lt_1}` stays valid; `te_wait_conditions({wc_1})` is present with `parked_at = NULL`, `timeout_at = NULL`, `event_subject_type = gts.acme.orders._.order.v1~`; the event-wait places in `te_tenant_wait_counters` for tenant A are reserved (DESIGN.md:814); `{task_1}` does not join the deferred set (arming does not count, DESIGN.md:813); no `wait` timer is armed; history of `{task_1}` gains `waitConditionSet` with `wait_condition_id = {wc_1}`, `kind = event`, `parked = false`.
- After Exchange 2: task `{task_1}` state is `waiting`; lease `{lt_1}` is invalid (later calls get LEASE_LOST); `{wc_1}.parked_at = T0+2m`, `timeout_at = T0+1h2m`; timer `wait` for `{task_1}` is armed at `2026-11-03T11:02:00Z`; `{task_1}` joins the deferred set; `queue_global(reports)` and `queue_tenant(reports, {tenant_a})` used change by −1; task `{task_1}.context` is `{ "charge_requested": true }`; history gains `taskCheckpointed` (G-WAI-15) and `taskWaiting` with `mode = all`, `conditions = [{ wait_condition_id: {wc_1}, kind: event }]`, and no second `waitConditionSet` (G-WAI-12).
- The engine's broker subscription is unchanged by both calls (DESIGN.md:911).

## Notes
- If the reply had arrived between the two calls, park would not park: see [1.03](1.03-positive-park-returns-result-when-already-satisfied.md).
- A park after an arm writes only `taskWaiting`; `waitConditionSet` was written once per condition at arm (G-WAI-12).
- Arm works for every kind (G-WAI-17); the p1 version of this flow arms a timer: see [1.03](1.03-positive-park-returns-result-when-already-satisfied.md) case `armed_timer`.
