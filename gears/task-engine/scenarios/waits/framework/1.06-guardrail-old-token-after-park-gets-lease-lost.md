# The lease token of a parked task is dead

Parking ends the worker's lease. A call that still carries the old token — here a late `complete` from the same worker — is refused with `LEASE_LOST` and changes nothing. The worker must abandon the task; it comes back later as a fresh claim.

## Setup
- Run [A worker sets a wait and the task is parked](1.01-positive-set-wait-parks-task.md). `{task_1}` is `waiting`; `{lt_1}` was its lease token.

## Request

```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-42.pdf"} }
```

## Expected response
- `409 Conflict`, category `aborted`, `context.reason = "LEASE_LOST"`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.aborted.v1~",
  "title": "Aborted",
  "status": 409,
  "detail": "The lease token is not the current lease of task {task_1}",
  "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>",
  "context": { "reason": "LEASE_LOST" }
}
```

## Side effects
- task `{task_1}` state is still `waiting`; `te_wait_conditions({wc_1})` is unchanged.
- subsequent `POST /tasks/heartbeat` listing `{ task_id: {task_1}, lease_token: {lt_1} }` returns `200` with `{ "task_id": "{task_1}", "outcome": "lease_lost" }` for that lease.

## Notes
- The SDK and any retry middleware must not retry `LEASE_LOST` (DESIGN.md:703); the SDK consumes the `Lease` on `set_wait`, so a well-behaved worker never sends this call.
