# An armed group is dropped when the run ends without parking

An armed group belongs to the run that armed it. If the task stops running without parking — a voluntary release, or a completion — the armed conditions go in the same transaction. A later event cannot wake a task that is not waiting for it, and the event-wait places are freed.

## Setup
- Run Exchange 1 of [Flow: arm a wait, start the action, then park](1.11-flow-arm-then-park.md): `{wc_1}` (**orders.paid**, `subject_id: o-17`) armed on `{task_1}` at `T0`, task `running` under `{lt_1}`.

## Request (case `release`)

```http
POST /api/task_engine/v1/tasks/{task_1}/release HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```

## Expected response
- `200 OK`, task resource with `state: queued` (CONVENTIONS §5.4).

## Cases

| Case | Request | Expected | Side effects that differ |
|---|---|---|---|
| `release` | `POST /tasks/{task_1}/release` with `{ "lease_token": "{lt_1}" }` | `200`, `state: queued` | task `{task_1}` is `queued` with `resume_pending = true`; lease `{lt_1}` is invalid (later calls get LEASE_LOST); `{wc_1}` is `cancelled` in the release transaction (DESIGN.md:546, :822); subsequent claim of `{task_1}` returns `resumed: null` and `attempt` unchanged (release continues the attempt, PRD.md:661); subsequent `POST /tasks/{task_1}/wait-conditions` by the new holder with a new group returns `200` (the new group becomes current, G-WAI-14) |
| `complete` | `POST /tasks/{task_1}/complete` with `{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-42.pdf"} }` | `200`, task resource with `state: completed`, `result.result_code: success` | task `{task_1}` is `completed`; `{wc_1}` is `cancelled` in the completion transaction and stays stored until retention (Proposals › Waits; replaces `finalize()` step 5, DESIGN.md:2943, and "live-only", DESIGN.md:1766); subsequent `GET /tasks/{task_1}/wait-conditions` returns `200` listing `{wc_1}` with `state: cancelled` |

## Side effects
- The event-wait places `{wc_1}` held in `te_tenant_wait_counters` are freed (DESIGN.md:814; on complete, `finalize()` step 1, DESIGN.md:2932).
- An `orders.paid` event for `o-17` delivered afterwards matches nothing for `{task_1}`; it writes no `te_event_inbox` row for tenant A (no candidate; only matched events write inbox rows, DESIGN.md:925).

## Notes
- The same rule applies to lease loss and cancel (DESIGN.md:822).
- Arm works for every kind in p1 (G-WAI-17), so the same rule can be tested in p1 with an armed timer condition.
