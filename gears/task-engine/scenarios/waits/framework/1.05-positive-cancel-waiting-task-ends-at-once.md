# Cancelling a waiting task ends it at once

A `waiting` task holds no lease, so there is no worker to ask: `requested` and `graceful` cancel end it at once with `cancelled`. Its conditions and timers go with it and its deferred place is freed.

## Setup
- Run [A worker sets a wait and the task is parked](1.01-positive-set-wait-parks-task.md): `{task_1}` is `waiting` on timer `{wc_1}` (`resume_at` `T0+1h`).

## Request

```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "mode": "requested", "reason": "report no longer needed" }
```

## Expected response
- `200 OK`, task resource with `state: cancelled`, `result.result_code: cancelled` (CONVENTIONS §5.5).

## Side effects
- task `{task_1}` state is `cancelled`; task `{task_1}` result_code is `cancelled`.
- `{task_1}` leaves the deferred set (DESIGN.md:2931).
- `{wc_1}` is `cancelled` and stays stored until retention (Proposals › Waits, G-WAI-14); timer `wait` for `{task_1}` is removed; the lifetime timer for `{task_1}` is removed.
- history of `{task_1}` gains `taskCancelled` with `actor = {creator_a}`, `mode = requested`, `result_code = cancelled`; no `taskCancelRequested` (the task was not leased, G-RTY-15).
- At `T0+1h` nothing happens to `{task_1}`.
