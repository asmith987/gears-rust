# A timer condition without `resume_at` is refused

`resume_at` is the only field of a timer condition. A timer condition without it is invalid; the whole group is refused and the worker keeps its lease.

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-timer` (PRD.md:570) · DESIGN.md:374-376 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-SEC-21 |

## Setup
- `{task_1}` is `running` under `{lt_1}`.

## Request

```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "mode": "all", "park": true,
  "conditions": [ { "kind": "timer" } ] }
```

## Expected response
- `400 Bad Request`, category `invalid_argument`, `REQUIRED` on `/conditions/0/resume_at`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "resume_at is required for a timer condition",
  "instance": "/api/task_engine/v1/tasks/{task_1}/wait-conditions",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/conditions/0/resume_at", "description": "required for kind timer", "reason": "REQUIRED" } ] }
}
```

## Side effects
<!-- No side effects: the request is refused before any write. -->
- `{task_1}` is still `running`; `{lt_1}` stays valid.

## Notes
- A timer condition that also carries `timeout_secs` or `on_timeout` is refused too: see [framework 1.07](../framework/1.07-negative-set-wait-refusals.md) cases `timeout_on_timer` and `on_timeout_without_timeout` (G-WAI-09, G-WAI-32).
