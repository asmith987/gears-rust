# A pending timer wait survives an engine restart

Waits are durable: the condition and its timer are rows in the task's domain database, not in memory. If every engine instance restarts while a task is parked, the task still resumes on time.

## Setup
- At `T0` `{task_1}` was parked on timer `{wc_1}` with `resume_at = 2026-11-03T10:15:00Z` (as in [1.01](1.01-positive-timer-resumes-at-resume-at-past-returns-at-once.md)).
- From `T0+5m` to `T0+6m` every engine instance is stopped; at `T0+6m` they start again and finish startup recovery (timers re-read, DESIGN.md:1053).

## Request

```http
GET /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

(sent at `T0+7m`)

## Expected response
- `200 OK`; the condition is still there and still `pending`.

```json
{ "items": [ { "id": "{wc_1}", "kind": "timer", "state": "pending", "timeout_at": null, "result": null } ],
  "page_info": { "next_cursor": null, "prev_cursor": null, "limit": 25 } }
```

## Side effects
- `te_wait_conditions({wc_1})` is present; `{task_1}` is `waiting`; timer `wait` for `{task_1}` is still armed at `T0+15m` (a `te_timers` row, G-WAI-09).
- At `T0+15m` (within 1 s): `{task_1}` state is `queued`; history of `{task_1}` gains `waitConditionSatisfied` and `taskResumed` exactly once.

## Notes
- A restart that spans `resume_at` resumes the task as soon as the timer wheel runs again; the 1 s bound applies "under normal load" only (PRD.md:1260).
