# Flow: an armed children condition is checked only when parked

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-children` (PRD.md:619) · `cpt-cf-task-engine-fr-wait-conditions` (PRD.md:554-559) · DESIGN.md:822, :1096, :3008, :3010 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-WAI-12, G-WAI-13, G-WAI-17 |

A running parent may still create children, so an **armed** children condition is not evaluated (DESIGN.md:3010): "no live child" while the parent runs means nothing yet. Park runs the check (DESIGN.md:3008). If by then every child has ended, park answers with the result and the parent keeps running under the same lease (DESIGN.md:1096).

## Setup
- Parent `{task_1}` (**reports**) is `running` under `{lt_1}` (epoch 1), held by `{worker_a}` / `reports-7f9c-1`. It has no children. Clock: T0.

## Exchange 1 — arm with no children (T0)
```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "mode": "all", "park": false, "conditions": [ { "kind": "children" } ] }
```
```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "wait_group": { "id": "{wg_1}", "mode": "all", "parked": false,
    "conditions": [ { "id": "{wc_1}", "kind": "children", "state": "pending", "timeout_at": null } ] },
  "task_state": "running" }
```
- Not satisfied although the parent has no live child.

## Exchange 2 — create a child while armed (T0+1m)
- `POST /tasks` with `parent_task_id: {task_1}`, `parent_lease_token: {lt_1}` → `201`, child `{task_2}` (see [hierarchy/children](../../hierarchy/children/)). Arming does not block children: the parent is `running`, not `waiting` (DESIGN.md:2628).
- `{task_2}` runs and completes `success` at T0+3m. Its `children_check` timer finds no **parked** condition and does nothing (DESIGN.md:3001); `{wc_1}` stays `pending`.

## Exchange 3 — park (T0+4m)
```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions/park HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```
```http
HTTP/1.1 200 OK
Content-Type: application/json

{ "parked": false,
  "result": { "wait_group_id": "{wg_1}", "outcome": "satisfied",
    "conditions": [ { "id": "{wc_1}", "kind": "children", "state": "satisfied",
      "result": { "counts": { "completed": 1, "failed": 0, "cancelled": 0, "dead_lettered": 0 } } } ] } }
```

## Side effects
- task {task_1} state is running throughout; lease {lt_1} stays valid; task {task_1} lease_epoch is 1
- history of {task_1} gains waitConditionSet (`wait_condition_id = {wc_1}`, `kind = children`, `parked = false`) at T0 and waitConditionSatisfied at T0+4m; no taskWaiting, no taskResumed (G-WAI-12)
- `{wg_1}` is consumed by the park (G-WAI-13): its conditions stay stored and `GET /tasks/{task_1}/wait-conditions` lists them as `satisfied` (G-WAI-14), but the group is not current, so no claim returns it in `claims[].resumed`
- subsequent `POST /tasks/{task_1}/progress` with `{lt_1}` returns `200`

## Notes
- An armed children condition is evaluated at park (G-WAI-17, DESIGN.md:3010); a group satisfied by that check is not parked: park answers `parked: false` with the result and the lease is kept (G-WAI-13).
- With a live child at park time the parent parks as in [1.05](1.05-flow-parent-resumes-after-last-child-with-counts.md).
