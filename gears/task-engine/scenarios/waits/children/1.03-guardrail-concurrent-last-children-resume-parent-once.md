# Two last children ending at the same moment resume the parent once

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-children` (PRD.md:619) · PRD.md:1528 · DESIGN.md:2994-3005 · ADR-0004:77, :85 |
| Phase | p2 |
| Test level | Integration — race |
| Gaps | G-SEC-25, G-WAI-08 |

Each child's terminal transaction inserts its own `children_check` timer for the parent. When the last two children end together, two checks can both see "no live child". The check takes the parent's condition with a guarded update on `state = pending` (DESIGN.md:3001), so only the first one resolves it; the second matches nothing and is a no-op. The parent resumes exactly once.

## Setup
- Parent `{task_1}` is `waiting` on children condition `{wc_1}` (group `{wg_1}`, mode `all`), parked at T0.
- Its last two live children, `{task_2}` and `{task_3}`, are `running` under `{lt_2}` and `{lt_3}` on two worker processes (`reports-7f9c-1`, `reports-7f9c-2`).
- At T0+10m both workers send `complete` with `result_code: success` concurrently; both return `200`.
- Clock: T0+10m+2s.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1}/events?$filter=event_type eq 'taskResumed' HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK` with exactly one `taskResumed` item.
```json
{ "items": [ { "id": "{evt_9}", "event_type": "taskResumed", "actor": null,
    "payload": { "task_id": "{task_1}" }, "timestamp": "2026-11-03T10:10:00Z" } ],
  "page_info": { "next_cursor": null, "prev_cursor": null, "limit": 25 } }
```

## Side effects
- task {task_1} state is queued
- history of {task_1} gains exactly one waitConditionSatisfied for `{wc_1}`
- `te_timers(children_check for {task_1})` is absent after both timers ran
- subsequent claim of {task_1} returns `resumed.conditions[0].result.counts.completed = 2` (both children counted)

## Notes
- The `actor` of an engine-caused event is absent (event schema `actor` description); written `null` here.
- Counts are read in the resolving transaction (DESIGN.md:3003), after both children committed, so both are counted whichever timer wins.
- No `limit` is sent, so the page uses the default 25 (G-SEC-25).
