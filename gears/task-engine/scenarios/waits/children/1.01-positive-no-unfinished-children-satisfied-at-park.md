# A children wait with no unfinished child is satisfied at once

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-children` (PRD.md:619) · DESIGN.md:820, :3008 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-WAI-08, G-WAI-12, G-WAI-13 |

If none of the parent's children is still live when it parks (it created none, or all have already ended), the condition is satisfied at once (PRD.md:619): park runs the same check as a child's end (DESIGN.md:3008). A one-step set (`park: true`) whose group resolves at once behaves like parking a satisfied armed group (G-WAI-13): it returns the result, the worker keeps its lease and the task stays `running`. The parent never sits in `waiting` waiting for nothing.

## Setup
- Parent `{task_1}` (**render**, **reports**) is `running` under `{lt_1}` (epoch 1, attempt 1), held by `{worker_a}` / `reports-7f9c-1`.
- It created two children, `{task_2}` and `{task_3}`; both ended `completed` before T0.
- Clock: T0.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "mode": "all", "park": true, "conditions": [ { "kind": "children" } ] }
```

## Expected response
- `200 OK`. The group resolved at once: it is not parked, the result is returned, and the task stays `running` under `{lt_1}`.
```json
{ "parked": false,
  "result": { "wait_group_id": "{wg_1}", "outcome": "satisfied",
    "conditions": [ { "id": "{wc_1}", "kind": "children", "state": "satisfied",
      "result": { "counts": { "completed": 2, "failed": 0, "cancelled": 0, "dead_lettered": 0 } } } ] } }
```

## Side effects
- task {task_1} state is running; lease {lt_1} stays valid; task {task_1} lease_epoch is 1
- no deferred admission and no change to concurrency counters
- history of {task_1} gains waitConditionSet (`wait_condition_id = {wc_1}`, `kind = children`) then waitConditionSatisfied; no taskWaiting, no taskResumed
- `{wg_1}` is consumed in that call (G-WAI-13): its conditions stay stored and `GET /tasks/{task_1}/wait-conditions` lists them as `satisfied` (G-WAI-14), but the group is not current, so no claim returns it in `claims[].resumed`
- subsequent `POST /tasks/{task_1}/progress` with `{lt_1}` returns `200`

## Notes
- Decided by G-WAI-13: a set whose group resolves at once under its mode returns `200 { parked: false, result }`, keeps the lease and passes no deferred admission. The same answer for a separate park is [1.06](1.06-flow-armed-children-condition-evaluated-only-at-park.md).
- `waitConditionSet` is written once per condition at set (G-WAI-12); `taskWaiting` only when the task really parks.
