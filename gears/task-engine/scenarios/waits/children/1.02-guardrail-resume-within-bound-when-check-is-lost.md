# A parent still resumes on time when its last child ends while it is parking

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-children` (PRD.md:619) · `cpt-cf-task-engine-nfr-timer-accuracy` (PRD.md:1258-1262) · DESIGN.md:2991-3009, :2206 |
| Phase | p2 |
| Test level | Integration — lost check race |
| Gaps | G-WAI-09 |

The child → parent check must not lock the parent in the child's transaction (lock order parent before child, DESIGN.md:2991). So a child that ends while the parent is in the middle of parking can be missed by both checks: the park sees the child still live, and the child's `children_check` timer fires before the parked condition is committed. PRD.md:619 still requires the parent to resume within the timer-accuracy bound "even if a check is lost".

## Setup
- Parent `{task_1}` (**reports**) is `running` under `{lt_1}`; its only live child `{task_2}` is `running` under `{lt_2}`.
- `children_check_sweep_secs: 1` (DESIGN.md:2206).
- At T0 two transactions overlap:
  1. the parent's set-wait `{ "lease_token": "{lt_1}", "mode": "all", "park": true, "conditions": [ { "kind": "children" } ] }` reads `{task_2}` as live and commits `{wc_1}` as parked and `pending`;
  2. `{task_2}` completes `success`; its `children_check` timer fires and finds no parked `pending` children condition yet, so it does nothing.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
(sent at T0+1s, after the sweep interval)

## Expected response
- `200 OK`, `state: queued`: the maintenance sweep found the parked condition with no live child and resumed the parent.
```json
{ "id": "{task_1}", "state": "queued", "assignment": null, "…": "other fields as in CONVENTIONS §5.1" }
```

## Side effects
- task {task_1} state is queued no later than T0+1s (99% within 1 s, PRD.md:1262)
- history of {task_1} gains exactly one waitConditionSatisfied and one taskResumed
- subsequent claim of {task_1} returns `resumed.conditions[0].result.counts.completed = 1`

## Notes
- DESIGN.md:3009 re-checks **every** parked pending children condition each second. The scenario asserts only the bound, so a narrower sweep would meet it too.
- The timer-accuracy NFR (PRD.md:1260) lists queue, assignment, execution, heartbeat, lifetime and SLA deadlines; G-WAI-09 adds wait timeouts, timer conditions and children-wait resumes to it (99 % within 1 s).
- A test reproduces the race by holding the parent's park transaction open (e.g. a fault hook) while the child completes.
