# A run-time error in the expression is no match and does not touch the failure counter

Events of one type differ in shape. An expression that hits a missing field or a type mismatch fails at run time; that event does not match and nothing is recorded for it. A run-time error neither adds to the condition's `eval_failures` nor resets it; only a budget overrun adds one. Any evaluation that finishes within budget, `true` or `false`, resets the counter. So a condition whose expression fails on every event waits until its timeout (G-WAI-35; PRD.md:598, DESIGN.md:917, ADR-0007:67, :89).

## Setup
- `{task_1}` is `waiting` on `{wc_1}` from Exchange 1 of [positive-1.2](1.02-positive-match-expression-checked-after-field-match.md) (`match_expression: "data.amount >= 100.0"`), with `eval_failures = 3` (seeded: three earlier budget overruns).

## Exchange 1 — `{bev_1}`: tenant A, subject `o-17`, `data { "status": "pending" }` (no `amount`)
- The expression fails at run time (no such key) → no match; `eval_failures` stays `3`.

## Exchange 2 — `{bev_2}`: tenant A, subject `o-17`, `data { "amount": "a lot" }`
- Type mismatch at run time → no match; `eval_failures` stays `3`.

## Exchange 3 — `{bev_3}`: tenant A, subject `o-17`, `data { "amount": 40 }`
- The expression returns `false` within budget → no match; `eval_failures` is reset to `0`.

## Expected outcome
- After each exchange `{wc_1}` stays `pending` and `{task_1}` stays `waiting`; `eval_failures` is `3`, `3`, then `0`.
- Any number of run-time errors in a row leave `{wc_1}` `pending`; it never resolves with `reason: eval_budget_exceeded` from them (that takes ten overruns, [1.12](1.12-guardrail-eval-budget-exhaustion-resolves-condition.md)); it ends at its timeout.

## Side effects
- No `te_event_inbox` rows for `{bev_1}`, `{bev_2}` or `{bev_3}`; no history entries.

## Notes
- G-WAI-35 follows ADR-0007:67, :89: a run-time error is not counted, and it does not reset the counter either.
- Whether a run-time error also increases `te_event_wait_eval_budget_exceeded_total{outcome="no_match"}` is not stated; this scenario does not assert the metric.
