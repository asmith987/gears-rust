# Flow: incident — hold a queue, producers keep creating, running work finishes, release, claims resume

| | |
|---|---|
| Requirement | Proposals › Queue operations › Admin queue hold · `cpt-cf-task-engine-fr-queue-introspection` (PRD.md:491) |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › Queue operations › Admin queue hold |
| Gaps | G-OPS-02, G-OPS-03, G-OPS-04, G-OPS-05, G-OPS-06, G-OPS-07 |

The PDF renderer's font service starts returning garbage. The on-call operator holds **reports** so no new renders start, while producers keep submitting and the renders already in progress finish. After the fix the operator releases the hold and the backlog drains.

Single-step detail: [queues/](../queues/) 2.01–2.04.

---

## Setup
- **reports**: 3 `running` tasks (`{task_1}`…`{task_3}`) held by `reports-7f9c-1`, 2 `queued` (`{task_4}`, `{task_5}`). Workers `reports-7f9c-1` and `-2` long-poll **reports**.

## Exchange 1 — `T0`: hold
```http
POST /api/task_engine/v1/admin/queues/gts.cf.core.tasks.queue.v1~acme.reports._.render.v1/hold HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "reason": "INC-4711 font service corrupt" }
```
- `200 OK`, `hold: { "since": "2026-11-03T10:00:00Z", "by": "{admin}", "reason": "INC-4711 font service corrupt", "until": null }`.
- history of queue **reports** gains `queueHeld { queue, actor: "{admin}", reason }`, readable at `GET /queues/{id}/events` (G-OPS-04, G-OPS-05).
- The serving node applies the hold at once; every other node within `runtime_config_poll_secs` (5 s), so no claim starts anywhere after `T0+5s` (G-OPS-03).

## Exchange 2 — `T0+10s`: a producer creates
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-60

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-60", "format": "pdf" } }
```
- `201 Created`, `{task_6}` `queued`.

## Exchange 3 — `T0+20s`: a worker's long poll ends empty
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-2", "session_id": "{session_2}",
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 1, "timeout_secs": 10 }
```
```http
HTTP/1.1 204 No Content
```
- The claim names only held queues, so it long-polls and ends `204`; the queue watcher skips held queues (G-OPS-06).

## Exchange 4 — `T0+30s`: a running render finishes
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-10.pdf"} }
```
- `200 OK`, `completed`. `{task_2}` and `{task_3}` also finish (or fail and are scheduled for retry; the retries become `queued` and stay held).

## Exchange 5 — `T0+5m`: the dashboard
```http
GET /api/task_engine/v1/queues/gts.cf.core.tasks.queue.v1~acme.reports._.render.v1 HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```
```json
{ "id": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "kind": "dispatch",
  "…": "settings omitted",
  "domains": ["default"],
  "limits": { "global_concurrency_limit": 50, "per_tenant_concurrency_limit": 5,
              "queue_max_queue_depth": 1000000, "tenant_max_queue_depth": 100000 },
  "counts": { "queued": 3, "running": 0, "claimed": 0, "scheduled": 0, "blocked": 0, "waiting": 0 },
  "sampled_at": "2026-11-03T10:04:55Z",
  "hold": { "since": "2026-11-03T10:00:00Z", "by": "{admin}", "reason": "INC-4711 font service corrupt", "until": null } }
```
- `counts` and `sampled_at` are returned because `{admin}` holds `configure` on the queue; a caller with only queue `read` gets the queue without them (G-OPS-02).

## Exchange 6 — `T0+40m`: release
```http
POST /api/task_engine/v1/admin/queues/gts.cf.core.tasks.queue.v1~acme.reports._.render.v1/release HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```
- `200 OK`, `"hold": null`; history of queue **reports** gains `queueReleased { queue, actor: "{admin}", automatic: false }` (G-OPS-04).
- The releasing node signals its waiters at once; other nodes resume within one refresh plus one poll interval (G-OPS-06).

## Exchange 7 — Claims resume
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-2", "session_id": "{session_2}",
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 3, "timeout_secs": 30 }
```
- `200 OK` with `{task_4}`, `{task_5}`, `{task_6}` in queue order (oldest first within tenant A).

## End state
- No task was cancelled or lost its lease because of the hold; every create was accepted.
- Held time counts toward the queue timeout (G-OPS-07): `{task_4}`, queued since `T0-5m` on **reports** (3600 s), had used 45 of its 60 minutes at release. Had the hold lasted past `T0+55m`, it would have ended `timed_out` (`timeout_type: queue`) while held ([timeouts/1.01](../timeouts/1.01-positive-queue-or-lifetime-timeout-ends-task-timed-out.md)).

## Notes
- A hold also does not stop the per-tenant depth limit; during a long incident producers get `429` ([2.02](../queues/2.02-positive-held-queue-stops-claims-only.md), case "long hold fills the depth limit").
