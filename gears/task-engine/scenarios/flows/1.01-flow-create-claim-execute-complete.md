The canonical lifecycle of one task, every exchange inline. A reporting service creates a render task; a worker claims it, starts it, heartbeats, reports progress, and completes it. The history records every step; the broker gets the `lifecycle` preset.

Single-step detail: [create](../tasks/create/), [claim](../worker/claim/), [sessions](../worker/sessions/), [execution](../worker/execution/), [events](../events/).

---

## Exchange 1 — Create
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-42

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42", "format": "pdf" }, "tags": [{ "key": "project", "value": "q4" }] }
```
```http
HTTP/1.1 201 Created
Location: /api/task_engine/v1/tasks/{task_1}
```
```json
{ "id": "{task_1}", "state": "queued", "attempt": 0, "priority": 100, "urgency": "normal",
  "…": "other fields as in CONVENTIONS §5.1" }
```

## Exchange 2 — Claim (`T0+1s`)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 1, "timeout_secs": 30 }
```
```http
HTTP/1.1 200 OK
```
```json
{ "session_id": "{session_1}", "domain": "default", "heartbeat_interval_secs": 10,
  "claims": [ { "task": { "id": "{task_1}", "state": "claimed", "attempt": 1, "…": "…" },
                "lease": { "lease_token": "{lt_1}", "lease_epoch": 1, "attempt": 1, "lease_secs": 30, "domain": "default" },
                "authority": { "mode": "creator_verified", "checked": [], "checked_at": "2026-11-03T10:00:00Z" },
                "resumed": null } ] }
```
- `heartbeat_interval_secs` = 30 / 3 = 10. Assignment deadline `T0+61s` (60 s). The claim sets `assignment.execution_deadline` = `T0+901s` (900 s from the claim, G-EXE-10).

## Exchange 3 — Start (`T0+2s`)
```http
POST /api/task_engine/v1/tasks/{task_1}/start HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```
- `200 OK`, `state: running`. Assignment deadline cleared; `execution_deadline` stays `T0+901s` (`start` never moves it, G-EXE-10).

## Exchange 4 — Heartbeat (`T0+12s`)
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```
```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "results": [ { "task_id": "{task_1}", "outcome": "ok", "state": "running", "cancel_requested": false } ] }
```
- Session lease renewed to `T0+42s`; no task row is written (DESIGN.md:806).

## Exchange 5 — Progress (`T0+15s`)
```http
POST /api/task_engine/v1/tasks/{task_1}/progress HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "percent": 60, "current_stage": "rendering", "completed_units": 6, "total_units": 10 }
```
```http
HTTP/1.1 200 OK
```
- Buffered; flushed within `progress_flush_interval_secs` (5 s). Progress mode is `none` (queue and type set nothing), so no `taskProgressed` is recorded.

## End state
- task {task_1} state is completed; `terminal_at = T0+30s`; kept for 100 days from then ([retention](../retention/1.01-positive-finished-task-removed-after-retention.md)).
- queue_global(reports) and queue_tenant(reports, {tenant_a}) used went +1 at claim and -1 at complete.
- Published to the task-events topic under the default `lifecycle` preset: `taskCreated`, `taskCompleted`. Not published: `taskClaimed`, `taskStarted` (excluded by the preset, PRD.md:898).
- Heartbeats and progress add no history events.

## Notes
- A create records only `taskCreated` with `initial_state`, never `taskQueued` (decided: G-OPS-36, G-SEC-23).
- `start` is optional (G-EXE-11); the execution deadline counts from the claim either way.
