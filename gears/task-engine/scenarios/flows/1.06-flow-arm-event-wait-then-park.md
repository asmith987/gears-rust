# Flow: arm an event wait, start the external action, the event arrives, park returns at once

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-wait-event` (PRD.md:577) · PRD §8 "Task Waits for External Event" (PRD.md:1430) · PRD.md:1527 · DESIGN.md:822, :1095-1096 |
| Phase | p2 |
| Test level | E2E — suite must include event-broker |
| Depends on | Proposals › Waits › Event waits after the others (accepted: event waits follow timer, input and children) |

A worker asks the payment service to charge an order and must wait for `orders.paid`. If it started the charge first and then set the wait, a fast reply could be missed. So it **arms** the wait first, starts the charge, then **parks**. The event arrived in between, so the park returns the event at once and the task keeps running under the same lease.

Single-step detail: [event waits](../waits/event/).

---

## Setup
- `{task_1}` (**render**, used here for an order-confirmation document) is `running`, held by `reports-7f9c-1` with `{lt_1}`.
- `gts.cf.core.events.topic.v1~acme.orders._.order_events.v1` is in `waitable_topics`; `{worker_a}` may `consume` the topic, `gts.cf.core.events.event.v1~acme.orders._.paid.v1~` and the subject type `gts.acme.orders._.order.v1~`.

## Exchange 1 — Arm (`park: false`)
```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "mode": "all", "park": false,
  "conditions": [ { "kind": "event", "event_type": "gts.cf.core.events.event.v1~acme.orders._.paid.v1~",
                    "subject_type": "gts.acme.orders._.order.v1~", "subject_id": "o-17",
                    "timeout_secs": 3600, "on_timeout": "resume" } ] }
```
```json
{ "wait_group": { "id": "{wg_1}", "mode": "all", "parked": false,
                  "conditions": [ { "id": "{wc_1}", "kind": "event", "state": "pending", "timeout_at": null } ] },
  "task_state": "running" }
```
- The condition matches from the moment this call returns. `timeout_at` is `null` while armed (timeouts start at park, DESIGN.md:822).

## Exchange 2 — The worker starts the charge (payment service, outside the engine)

## Exchange 3 — The payment service publishes `orders.paid` (Event Broker)
```http
POST /v1/events HTTP/1.1
Host: broker.example.com
Authorization: Bearer <payments-service-token>
Content-Type: application/json

{ "id": "{evt_9}", "type": "gts.cf.core.events.event.v1~acme.orders._.paid.v1~", "tenant_id": "{tenant_a}",
  "source": "payment-service", "subject": "o-17", "subject_type": "gts.acme.orders._.order.v1~",
  "occurred_at": "2026-11-03T10:00:02Z", "data": { "amount_cents": 4299 } }
```
- `202 Accepted`. The engine's consumer matches `{wc_1}`: `state: satisfied`, header stored; the task stays `running`.

## Exchange 4 — Park
```http
POST /api/task_engine/v1/tasks/{task_1}/wait-conditions/park HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```
```json
{ "parked": false,
  "result": { "wait_group_id": "{wg_1}", "outcome": "satisfied",
              "conditions": [ { "id": "{wc_1}", "kind": "event", "state": "satisfied",
                                "result": { "id": "{evt_9}", "type": "gts.cf.core.events.event.v1~acme.orders._.paid.v1~",
                                            "subject": "o-17", "subject_type": "gts.acme.orders._.order.v1~",
                                            "time": "2026-11-03T10:00:02Z", "topic": "gts.cf.core.events.topic.v1~acme.orders._.order_events.v1",
                                            "partition": 3, "offset": 1042 } } ] } }
```
- `{lt_1}` stays valid; the group is deleted. The event `data` is not returned (header only, DESIGN.md:839).

## Exchange 5 — Complete
- `complete` with `{lt_1}` and `success` → `200`, `completed`.

## End state
- task {task_1} was never `waiting`, never lost its slot, and `attempt` stayed 1.
- History: …, waitConditionSet (`parked: false`), waitConditionSatisfied, taskCompleted. No taskWaiting or taskResumed.

## Notes
- Had the event not arrived yet, the park would answer `{ "parked": true, "task_state": "waiting" }`, start the one-hour timeout and release the lease; the task would resume through a new claim.
