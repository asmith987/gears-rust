# Flow: a worker process dies, its task is requeued and claimed elsewhere, and the zombie is fenced

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-heartbeat` (PRD.md:676-678) · `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:722) · PRD.md:1477, :1516, :1520 · DESIGN.md:539, :2744-2798 · ADR-0011 · ADR-0017:55-59 |
| Phase | p1 |
| Test level | Both — E2E with short heartbeat timeout; integration for precise requeue |
| Gaps | G-EXE-05, G-RTY-02, G-EXE-09 |

Process `reports-7f9c-1` freezes (long GC pause, then network loss). Its session expires; the task goes back with liveness backoff, not with a retry; `reports-7f9c-2` claims it with a higher epoch. When the frozen process wakes up and tries to complete, its write is rejected, and the new holder's result is kept.

Single-step detail: [sessions](../worker/sessions/), [fencing](../worker/fencing/), [timeouts](../timeouts/).

---

## Setup
- `{task_1}` on **reports** is `running`, held by `reports-7f9c-1` in `{session_1}` (lease 30 s) with `{lt_1}`, `lease_epoch: 1`, `attempt: 1`. Last heartbeat at `T0`, so `lease_until = T0+30s`.

## Exchange 1 — Nothing arrives; at `T0+31s` the session scan runs
- `{session_1}` is marked `expired` (guarded on `lease_until < now`).
- `{task_1}` → `scheduled`, `liveness_requeues: 1`, `retry_count: 0`, `run_after` ∈ [`T0+35s`, `T0+36s`] (backoff base 5 s on the liveness count).
- History gains taskRetrying with `cause: liveness`, `timeout_type: heartbeat` and `run_after` (G-EXE-05, G-RTY-02).
- One blacklist strike for `reports-7f9c-1` on **reports** (p3), metric te_worker_sessions_expired_total +1.

```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
```json
{ "id": "{task_1}", "state": "scheduled", "attempt": 1, "retry_count": 0, "liveness_requeues": 1,
  "run_after": "2026-11-03T10:00:36Z", "assignment": null, "…": "other fields as in CONVENTIONS §5.1" }
```

## Exchange 2 — `T0+37s`: another process claims it
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-2", "session_id": "{session_2}",
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 1, "timeout_secs": 30 }
```
```json
{ "session_id": "{session_2}", "heartbeat_interval_secs": 10,
  "claims": [ { "task": { "id": "{task_1}", "state": "claimed", "attempt": 2, "…": "…" },
                "lease": { "lease_token": "{lt_2}", "lease_epoch": 2, "attempt": 2, "lease_secs": 30 },
                "authority": { "mode": "creator_verified", "checked": [], "checked_at": "2026-11-03T09:59:00Z" }, "resumed": null } ] }
```
- `attempt` +1 (a new run, not a resume). The worker reads `context` to resume from the last checkpoint.

## Exchange 3 — `T0+40s`: the zombie wakes and completes
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-42-stale.pdf"} }
```
```http
HTTP/1.1 409 Conflict
Content-Type: application/problem+json
```
```json
{ "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.aborted.v1~", "title": "Aborted", "status": 409,
  "detail": "Lease is no longer held", "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>", "context": { "reason": "LEASE_LOST" } }
```
- A stale token always gets `409` `LEASE_LOST`, never `404` (G-EXE-09). The zombie's SDK fires `lease.lost` and stops the handler. Its next claim opens a new session (the old one is expired, ADR-0017:55).

## Exchange 4 — The new holder completes
```http
POST /api/task_engine/v1/tasks/{task_1}/start HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_2}" }
```
- `200 OK`, `running`. Then `complete` with `{lt_2}` and output `r-42.pdf` → `200`, `state: completed`.

## End state
- task {task_1} result output is `r-42.pdf` (the zombie's output was never stored); `attempt: 2`, `retry_count: 0`, `liveness_requeues: 1`.
- metric te_lease_fencing_rejections_total{op="complete"} increased by 1; te_lease_expired_total{cause="session"} by 1.
- History: …, taskClaimed (`reports-7f9c-1`, attempt 1), taskStarted, taskRetrying (`cause: liveness`, `timeout_type: heartbeat`), taskClaimed (`reports-7f9c-2`, attempt 2), taskStarted, taskCompleted. The rejected complete adds nothing.
- External side effects the zombie made between `T0+31s` and `T0+40s` are not undone; downstream systems use `lease_epoch` (1 vs 2) to reject them (ADR-0011).
