# Flow: cancel a running task in `graceful` mode, end to end

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:344-352) · PRD.md:674 · DESIGN.md:535, :549, :551, :2155 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-OPS-38, G-RTY-15, G-RTY-17, G-RTY-19, G-WAI-23, G-WIRE-06, G-WIRE-08 |

A user cancels a long render. The worker learns of it on its next heartbeat, stops at a safe point and ends the task as `cancelled` within the grace period. A second run of the same flow shows what happens when the worker ignores the request: the engine force-cancels at the end of the grace period.

Single-step detail: [cancel](../tasks/cancel/).

---

## Setup
- `{task_1}` on **reports** is `running`, held by `reports-7f9c-1` in `{session_1}` with `{lt_1}`, created by `{creator_a}`.
- Engine config `cancel_grace_period_secs = 60` (engine-wide in p1, G-RTY-19).

## Exchange 1 — `T0`: the user cancels
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "mode": "graceful", "reason": "wrong report period" }
```
```http
HTTP/1.1 202 Accepted
```
```json
{ "id": "{task_1}", "state": "running", "cancel_requested": true,
  "cancel_request": { "mode": "graceful", "requested_by": "{creator_a}", "requested_at": "2026-11-03T10:00:00Z",
                      "reason": "wrong report period", "grace_until": "2026-11-03T10:01:00Z", "superseded_by": null },
  "…": "other fields as in CONVENTIONS §5.1" }
```
- timer cancel_grace for {task_1} is armed at T0+60s; history gains taskCancelRequested with `mode: graceful`, `actor: "{creator_a}"` (recorded because a leased task is flagged, G-RTY-15).

## Exchange 2 — `T0+8s`: the worker's heartbeat carries the request
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```
```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "results": [ { "task_id": "{task_1}", "outcome": "ok", "state": "running", "cancel_requested": true,
                 "cancel_request": { "mode": "graceful", "requested_by": "{creator_a}", "requested_at": "2026-11-03T10:00:00Z",
                                     "reason": "wrong report period", "grace_until": "2026-11-03T10:01:00Z", "superseded_by": null } } ] }
```

## Exchange 3 — `T0+12s`: the worker stops and ends the task as cancelled
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "cancelled" }
```
```json
{ "id": "{task_1}", "state": "cancelled", "cancel_requested": true,
  "result": { "result_code": "cancelled", "output": null, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:00:12Z", "…": "other fields as in CONVENTIONS §5.1" }
```
- timer cancel_grace for {task_1} is removed; slots freed; history gains taskCancelled with `result_code: cancelled`, `actor: "{worker_a}"`.

## Variant — the worker ignores the request
- No acknowledgement arrives. At `T0+60s` the `cancel_grace` timer fires and applies the forced-cancel transition: `state: cancelled`, `result_code: forcibly_cancelled`, no `actor`.
- The worker's next heartbeat for `{task_1}` returns `outcome: lease_lost`; a late `complete` with `{lt_1}` returns `409 LEASE_LOST`.

## End state
- No retry: a cancelled task is terminal, and `cancelled` tasks cannot be re-enqueued (PRD.md:803).
- Children of `{task_1}`, if any, would be cancelled too in the parent's mode (`graceful`), ending `cancelled` (`propagate_cancel: true`, G-WAI-23).

## Notes
- The worker acknowledges with `complete` `result_code: cancelled`, allowed only after a cancel request; it ends the task `cancelled` and deletes the grace timer (G-OPS-38).
- Other codes after a cancel request: `success` or `warning` (work already done) end the task `completed`; any `error`, retryable or not, ends it `cancelled` with the error recorded, no retry, no dead-lettering (G-RTY-17).
