# Entries have no update or delete route

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-entries` (PRD.md:642: "clients can only create, read, and list them. Only retention removes them") · DESIGN.md:988, :1087-1089 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-22 |

Entries are audit records. The API offers create, list and get only; there is no client verb that changes or removes one, and the `delete` action maps to no endpoint (DESIGN.md:988). Not even an administrator can rewrite an entry through the API.

## Setup
- `{task_1}` has `{entry_1}`.

## Exchange 1 — update
```http
PATCH /api/task_engine/v1/tasks/{task_1}/entries/{entry_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "payload": { "action": "nothing_happened" } }
```

- `405 Method Not Allowed` (the path exists for `GET`), with an `Allow: GET` header and no problem body. `PUT` gets the same.

## Exchange 2 — delete
```http
DELETE /api/task_engine/v1/tasks/{task_1}/entries/{entry_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```

- `405 Method Not Allowed`, `Allow: GET`, no problem body.

## Side effects
<!-- No side effects: no such operation exists. -->
- `GET /tasks/{task_1}/entries/{entry_1}` returns the original payload.

## Notes
- `405` with `Allow` and no problem body is the axum method-router default (G-EXE-22).
