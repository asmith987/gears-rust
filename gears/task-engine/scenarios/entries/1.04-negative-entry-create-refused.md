# An entry whose type is unknown, whose payload fails its schema or is over 64 KB, or that would exceed the per-task entry limit is refused and nothing is stored

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-entries` (PRD.md:632: "at most 64 KB (larger is rejected, `413`)") · `cpt-cf-task-engine-fr-gts-entry-type` (PRD.md:1055) · `cpt-cf-task-engine-nfr-payload-size` (PRD.md:1276) · DESIGN.md:263, :1209, :1212, :2142, :2255 · `schemas/types/gts.cf.core.tasks.entry.v1~` ("the engine validates it against the resolved entry type's schema at creation"), `…entry_issue.v1~`, `…entry_work.v1~` |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-07, G-CRT-23, G-EXE-19, G-EXE-21, G-SEC-21 |

Before an entry is stored the engine checks that `type` resolves to a registered GTS type derived from `gts.cf.core.tasks.entry.v1~`, that `payload` matches that type's schema, and that the payload is at most 64 KB of uncompressed JSON, independently of the task's own payload, and that the task holds fewer than `max_entries_per_task` (1000) entries. A failure is `invalid_argument` (`413` for the size), except too many entries, which is `failed_precondition` because no body field is at fault (G-EXE-21); no row is stored, and a worker's lease is kept.

## Setup
- `{task_1}` (`running`), held by `reports-7f9c-1` with `{lt_1}`. `gts.cf.core.tasks.entry.v1~acme.reports._.audit.v1~` is not registered.

## Request
Representative case (**unknown entry type**):
```http
POST /api/task_engine/v1/tasks/{task_1}/entries HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "type": "gts.cf.core.tasks.entry.v1~acme.reports._.audit.v1~", "payload": { "what": "x" } }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/type` with `UNKNOWN_ENTRY_TYPE`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "unknown entry type",
  "instance": "/api/task_engine/v1/tasks/{task_1}/entries",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/type", "description": "must be a registered entry type visible to the caller", "reason": "UNKNOWN_ENTRY_TYPE" } ] }
}
```

## Side effects
<!-- No side effects: refused before any write. -->
- In every row: no `te_task_entries` row; lease `{lt_1}` stays valid.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| unknown entry type | (representative) | `400`, `UNKNOWN_ENTRY_TYPE` on `/type` | The same for a type hidden from the caller or outside the entry base (for example a task type); entry types resolve with the caller's context (G-EXE-19) |
| registry unreachable | registry down, entry type not cached | `503`, `service_unavailable`, `Retry-After: 5` | G-EXE-19, G-CRT-23 |
| payload fails its schema | `{ "lease_token": "{lt_1}", "type": "gts.cf.core.tasks.entry.v1~cf.core.tasks.entry_issue.v1~", "payload": { "severity": "fatal", "msg": "font missing" } }` | `400`, `detail: "the entry payload does not match its type's schema"`, three violations: `{ "field": "/payload/severity", "description": "failed keyword: enum", "reason": "SCHEMA_VIOLATION" }`, `{ "field": "/payload/message", "description": "failed keyword: required", "reason": "SCHEMA_VIOLATION" }`, `{ "field": "/payload/msg", "description": "failed keyword: additionalProperties", "reason": "SCHEMA_VIOLATION" }` | `entry_issue` requires `severity` and `message` and allows no other properties. Every user-schema failure is `SCHEMA_VIOLATION`; the description names the keyword, never the value (G-SEC-21) |
| payload over 64 KB | `{ "lease_token": "{lt_1}", "type": "gts.cf.core.tasks.entry.v1~cf.core.tasks.entry_work.v1~", "payload": { "action": "dump", "details": { "log": "<70,000 characters>" } } }` | `413 Payload Too Large`, `invalid_argument`, `detail: "the entry payload exceeds 65536 bytes"`, violation `{ "field": "/payload", "description": "an entry payload must not exceed max_payload_size_bytes (65536)", "reason": "PAYLOAD_TOO_LARGE" }` | Entries are not a place for logs or blobs (PRD.md:1276). `entry_work.details` allows any properties, so the schema alone does not stop this; the size check does. The size is measured before compression (DESIGN.md:263); limit `max_payload_size_bytes` (DESIGN.md:2142), status override DESIGN.md:1209 |
| too many entries | `{task_1}` already has 1000 entries | `400`, `failed_precondition`, `context: { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}", "violations": [ { "type": "STATE", "subject": "TOO_MANY_ENTRIES", "description": "a task holds at most max_entries_per_task (1000) entries" } ] }` | Counted with the task's `entry_count` under a row lock (G-EXE-21). The same for an API-consumer entry |
