# A subject that may only read the task cannot add an entry

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-authz` (PRD.md:918: "`403` is returned only when the caller may read the task but not perform the action") · DESIGN.md:984, :1016, :1087 |
| Phase | p1 |
| Test level | Integration — read-only grant |
| Gaps | G-SEC-01, G-SEC-19 |

An API-consumer entry needs `create` on the task. A reader sees the task, so the refusal is `403`, not `404`.

## Setup
- `{task_1}` (`running`) of `{tenant_a}`. `{reader_a}` holds task `read` only.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/entries HTTP/1.1
Host: api.example.com
Authorization: Bearer <readonly-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.entry.v1~cf.core.tasks.entry_note.v1~", "payload": { "text": "looks stuck" } }
```

## Expected response
- `403 Forbidden`, `permission_denied`, reason `ACTION_DENIED`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "the caller may not add entries to this task",
  "instance": "/api/task_engine/v1/tasks/{task_1}/entries",
  "trace_id": "<trace>",
  "context": { "reason": "ACTION_DENIED", "resource_type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~", "resource_name": "{task_1}" }
}
```
