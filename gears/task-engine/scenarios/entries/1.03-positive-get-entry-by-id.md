# One entry is read by its ID

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-entries` (PRD.md:632) · DESIGN.md:1089, :1199 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-18, G-WIRE-15 |

A reader with `read` on the task fetches one entry. An entry ID that does not belong to the task, or a task the caller may not read, gives the same `404` as a missing entry (DESIGN.md:1199).

## Setup
- `{task_1}` has `{entry_1}` (as in [Worker creates an entry](1.01-positive-create-entry.md)).
- `{task_2}` is another task of `{tenant_a}` with no entries.

## Exchange 1 — the entry
```http
GET /api/task_engine/v1/tasks/{task_1}/entries/{entry_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <readonly-a-token>
```

- `200 OK`, the entry exactly as returned by its create.

## Exchange 2 — the same entry under the wrong task
```http
GET /api/task_engine/v1/tasks/{task_2}/entries/{entry_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <readonly-a-token>
```

- `404 Not Found`, `not_found`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "entry not found",
  "instance": "/api/task_engine/v1/tasks/{task_2}/entries/{entry_1}",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.entry.v1~", "resource_name": "{entry_1}" }
}
```
