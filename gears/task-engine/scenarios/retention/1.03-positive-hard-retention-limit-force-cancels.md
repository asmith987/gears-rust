# Past the hard retention limit an unfinished task is force-cancelled first

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retention` (PRD.md:1101) · PRD.md:1546 · DESIGN.md:549, :853 · ADR-0009:87 |
| Phase | p1 |
| Test level | Integration — days of clock + cleanup jobs |
| Gaps | G-OPS-33 |

Live tasks are bounded too: on every maintenance pass the engine ends every non-terminal task in the domain whose `created_at` is more than `hard_retention_days` (365) ago, with `forcibly_cancelled` and no actor. From then on it is an ordinary finished task, kept for its normal retention from `terminal_at` (G-OPS-33).

## Setup
- Shipped retention config (`hard_retention_days: 365`, global retention 100).
- `{task_1}` (**render** on **default**, no lifetime timeout) was created at `T0-366d`; it is `waiting` on a timer condition `{wc_1}` with `resume_at` at `T0+30d`.
- At `T0` the maintenance leader runs a pass in the `default` domain.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, `state: cancelled`, `result.result_code: forcibly_cancelled`, `terminal_at` = the time of the pass.

```json
{ "id": "{task_1}", "state": "cancelled",
  "result": { "result_code": "forcibly_cancelled", "output": null, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:00:00Z", "…": "other fields as in CONVENTIONS §5.1" }
```

## Cases

| Case | Differs from the representative | Expected | Notes |
|---|---|---|---|
| waiting task past the limit | (representative) | `cancelled` / `forcibly_cancelled` at the pass | G-OPS-33 |
| queued task past the limit | `{task_2}` created at `T0-366d`, `queued` on **default** (no worker claims it) | `cancelled` / `forcibly_cancelled` at the same pass; {task_2} leaves the queued set | every non-terminal state, not only the slot being recycled |
| just under the limit | `{task_3}` created at `T0-364d`, `waiting` like `{task_1}` | unchanged at the `T0` pass; ended by the first pass after `T0+1d` | measured from `created_at` |

## Side effects
- task {task_1} state is cancelled; task {task_1} result_code is forcibly_cancelled.
- {wc_1} is cancelled; timer wait for {task_1} is removed; the live-only rows of `{task_1}` are deleted in the same transaction.
- history of {task_1} gains taskCancelled with `result_code: forcibly_cancelled` and `actor: null` (engine-caused).
- {task_1} leaves the deferred set.
- The task's data is then kept until `terminal_at + 100d`.

## Notes
- The hard limit is one value per domain; it cannot be set per tenant or per type (G-OPS-33).
- The trust limit `max_retention_days` (365) is "never above `hard_retention_days`" (DESIGN.md:2198), but that bounds retention of finished tasks, not of live ones.
