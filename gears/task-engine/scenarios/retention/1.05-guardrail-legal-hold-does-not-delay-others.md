# One tenant's legal hold does not delay cleanup of other tenants

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retention` (PRD.md:1093) · ADR-0009:46, :105, :119 · DESIGN.md:851, :856 |
| Phase | p1 |
| Test level | Integration — days of clock + cleanup jobs |
| Gaps | G-OPS-34 |

Tenant C is under legal hold and keeps everything as long as the platform allows (365 days, the `max_retention_days` cap). Tasks of tenants A and B in the same creation bucket are removed on the normal schedule; tenant C's are rescued and truncation goes ahead.

## Setup
- Retention config: `global_retention_days: 100`; runtime config (`POST /admin/config`, applied in `default`) sets `retention.per_tenant: { "{tenant_c}": { "retention_days": 365 } }` (G-OPS-34).
- In one creation bucket (days `T0-112d`…`T0-105d`) tenants A, B and C each have 1,000 tasks, all completed within an hour of creation.
- At `T0` the maintenance leader recycles that bucket's slot.

## Request
```http
GET /api/task_engine/v1/tasks/{task_a_old} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `404 Not Found` for tenant A's and tenant B's tasks of that bucket.
- Tenant C's tasks of that bucket return `200 OK` to a tenant C reader.

## Side effects
- The slot is truncated in every history table in the same pass (it is not skipped because tenant C has rows in it).
- metric te_retention_rescued_total{domain="default", table="te_tasks"} increases by 1,000 (tenant C's rows only).
- metric te_retention_removed_total{domain="default", table="te_tasks", how="truncate"} increases.

## Notes
- `{task_a_old}` is one of tenant A's tasks in that bucket. If tenant C's share of the data is large, DESIGN recommends routing it to its own domain (DESIGN.md:864); not needed for correctness.
- A legal hold is a long per-tenant retention in runtime config, capped at `trust_limits.global.max_retention_days` (365). A longer hold is not possible: a larger value is refused `400 OUT_OF_RANGE` when the config is saved (G-OPS-34; [1.04](1.04-positive-retention-policy-precedence.md) case `per-tenant value over the cap`).
