# A finished task, with its entries and history, is removed after its retention

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retention` (PRD.md:1087-1104) · DESIGN.md:845-866, :2161-2169 · ADR-0009:72-91 |
| Phase | p1 |
| Test level | Integration — days of clock + cleanup jobs |
| Gaps | G-OPS-32, G-OPS-44, G-OPS-45 |

With no tenant or type policy, a finished task is kept for the global default of 100 days, counted from `terminal_at`. Its data is gone by `created_at + N × W` (119 days at the defaults, G-OPS-32): the task, its entries and its event history, and reads answer `404` as for a task that never existed.

## Setup
- Retention config as shipped: `global_retention_days: 100`, ring `bucket_days: 7`, `ring_slots: 17`, no `per_type` match for **render**, no `per_tenant` entry for tenant A. Every maintenance step runs on the paced tick (no `cleanup_time`, G-OPS-32).
- `{task_1}` (**render** on **reports**, tenant A) was created at `T0-1h`, wrote two entries, and completed at `T0` (`terminal_at = T0`).

## Exchange 1 — At `T0+99d`
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200 OK`, `state: completed`. `GET /tasks/{task_1}/entries` and `/events` return their items.

## Exchange 2 — At `T0+120d` (after `created_at + 119d`)
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `404 Not Found`, `not_found`, same body as for an unknown ID.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "Task with ID {task_1} not found",
  "instance": "/api/task_engine/v1/tasks/{task_1}",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}" }
}
```
- `GET /tasks/{task_1}/entries` and `GET /tasks/{task_1}/events` also return `404`.

## Side effects
- The ring slot of `{task_1}`'s creation bucket `B` is truncated in every history table (`te_tasks`, `te_task_results`, `te_events`, `te_task_entries`, `te_tags`, `te_resource_refs`).
- In the same step `te_ring_state` sets that slot `active` for bucket `B + N`; there is no `free` state (G-OPS-44).
- Events without a task in that slot (`queueHeld`, `queueReleased`, `configUpdated`, `workerBlacklisted`) are removed with it; they are never rescued (G-OPS-45).
- metric te_retention_removed_total{domain="default", table="te_task_results", how="truncate"} increases.
- No event is published for the removal.

## Notes
- The ring removes a whole creation bucket at once. With `W = 7` and `N = 17`, the slot of creation bucket `b` is recycled during bucket `b + 16`, i.e. between `15 × W` = 105 and `17 × W` = 119 days after its tasks were created (ADR-0009:80), so a task finished an hour after creation is removed 105–119 days later, not at exactly 100. The decided bound (G-OPS-32): data under the common retention is gone by `created_at + N × W`, at most retention + 3 × W. Exchange 2 is placed after that bound.
- The global default level of PRD.md:1099 is the case shown here.
