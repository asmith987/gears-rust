# Retention precedence: tenant policy, then config type pattern, then type trait, then global default

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retention` (PRD.md:1097-1101) · PRD.md:1010 · DESIGN.md:847, :859, :2170-2173 · ADR-0009:72 |
| Phase | p1 |
| Test level | Integration — days of clock + cleanup jobs |
| Gaps | G-OPS-32, G-OPS-34 |

Legal obligations belong to the tenant, so a tenant policy wins over every type rule. Operators can shorten (or lengthen) retention for a type without changing its registration: the most specific config pattern wins over the type's own `retention_days` trait. The global default applies only when none of these exists. The representative case: tenant A must keep its render results for a year; tenant B's are cleaned after the type's 7 days.

## Setup
- Static retention config:
  ```yaml
  retention:
    global_retention_days: 100
    per_type:
      - pattern: "gts.cf.core.tasks.task.v1~acme.reports.*"
        retention_days: 7
  ```
- Tenant A's policy is runtime config, set before the tasks finish (G-OPS-34):
  ```http
  POST /api/task_engine/v1/admin/config HTTP/1.1
  Host: api.example.com
  Authorization: Bearer <admin-token>
  Content-Type: application/json

  { "retention": { "per_tenant": { "{tenant_a}": { "retention_days": 365 } } } }
  ```
  `202`; the version is applied in domain `default` before `T0`.
- `{task_1}` (tenant A) and `{task_2}` (tenant B), both **render**, completed at `T0`.

## Exchange 1 — At `T0+8d` plus one maintenance pass
```http
GET /api/task_engine/v1/tasks/{task_2} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-b-token>
```
- `404 Not Found`.

## Exchange 2 — Same time, tenant A's task
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200 OK`, `state: completed`.

## Cases

| Case | Differs from the representative | Expected | Notes |
|---|---|---|---|
| tenant policy beats type pattern | `{task_1}`, tenant A (representative) | `200` at `T0+8d`; rescued into the `_retained` tables when its slot is recycled (about day 105-119) and removed within one maintenance tick after `T0+365d` | G-OPS-34, G-OPS-32 |
| type pattern applies without tenant policy | `{task_2}`, tenant B (representative) | `404` at `T0+8d` plus one pass; rows removed by the bounded delete for policies shorter than the drop horizon (DESIGN.md:859) | G-OPS-32 |
| no inheritance by the subtree | `{task_4}` (**render**, tenant A1, child of A) completed at `T0` | `404` at `T0+8d` plus one pass: A's policy does not reach A1, the type pattern's 7 days apply | G-OPS-34 |
| policy changed for rows not yet removed | `{task_5}` (**render**, tenant B) completed at `T0`; at `T0+3d` a new config version sets `per_tenant: { "{tenant_b}": { "retention_days": 30 } }` | `200` at `T0+8d` plus one pass; `404` at `T0+30d` plus one pass: the change applies to every row not yet removed | G-OPS-34 |
| config pattern beats type trait | **render** declares the trait `retention_days: 30`; `per_type: [{ pattern: "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~", retention_days: 14 }]`; `per_tenant: {}`; `{task_3}` (**render**, tenant A) completed at `T0` | `GET /tasks/{task_3}` `200` at `T0+13d`; `404` at `T0+15d` plus one pass (14 days, not the trait's 30); metric te_retention_removed_total{domain="default", table="te_task_results", how="delete"} increases | DESIGN.md:2170-2172 |
| per-tenant value over the cap | `POST /admin/config` with `{ "retention": { "per_tenant": { "{tenant_a}": { "retention_days": 400 } } } }` | `400 invalid_argument`, `OUT_OF_RANGE` on `/retention/per_tenant/{tenant_a}/retention_days`; no config version is saved; tenant A keeps 365 days | G-OPS-34: the cap is `trust_limits.global.max_retention_days` (365), checked when the config is saved |
| no tenant policy, no pattern, no trait | shipped config | global default 100 days: [1.01](1.01-positive-finished-task-removed-after-retention.md) | PRD.md:1099 |

## Side effects
- Per row.

## Notes
- Per-tenant retention is runtime config (`retention.per_tenant`, versioned through `POST /admin/config`), capped at `trust_limits.global.max_retention_days` (365), with no subtree inheritance; a larger value is refused `400 OUT_OF_RANGE` when the config is saved (G-OPS-34, case `per-tenant value over the cap`).
- A tenant-owned type's trait above `trust_limits.tenant_owned.max_retention_days` (100) makes the type non-creatable (PRD.md:1010); a config pattern is operator input and is assumed not to be capped by the type trust limits.
