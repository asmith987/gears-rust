# A platform worker reaches a barrier tenant's task only on a claim of platform-operated queues the PDP lets ignore barriers

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-worker-principals` (PRD.md:955-956) · PRD.md:1535 · DESIGN.md:703, :1020, :1024, :2407 · ADR-0016:74, :99 |
| Phase | p1 |
| Test level | Integration — barrier + platform-queue PDP policy |
| Gaps | G-SEC-13, G-SEC-15 |

A claim sends `barrier_mode: ignore` only when **every** named queue is `operated_by: platform`, and only with the PDP's consent to `ignore`. Otherwise the whole claim respects barriers, so tenant C's work stays out of reach of a root-tenant worker. When the claim may cross the barrier, it returns the task's owner tenant, so the worker names tenant C as context tenant downstream.

## Setup
- `{task_9}` (**cleanup**, platform-owned, `authority.mode = worker`), `queued` in **system**, input `{ "tenant_id": "{tenant_c}" }`. A platform gear created it with `"owner_tenant_id": "{tenant_c}"` (tenant C is behind a barrier); the create check carried barrier `Ignore` because **system** is `operated_by: platform`, and the PDP allowed it (G-SEC-13).
- PDP: `{platform_worker}` has task `claim` and `read` with `owner_tenant_id InTenantSubtree({root})`, and may claim on `system` with `barrier_mode: ignore`.

## Request
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~cf.core.tasks.system.v1"], "max_tasks": 1, "timeout_secs": 2 }
```

## Expected response
- `200`; one claim for `{task_9}` with `task.owner_tenant_id = {tenant_c}`, `created_by`, `owner_id`, and `"authority": { "mode": "worker", … }`.
```json
{ "session_id": "{session_1}", "domain": "default", "heartbeat_interval_secs": 10,
  "claims": [ { "task": { "id": "{task_9}", "type": "gts.cf.core.tasks.task.v1~cf.platform._.tenant_cleanup.v1~",
                          "owner_tenant_id": "{tenant_c}", "state": "claimed", "…": "other fields as in CONVENTIONS §5.1" },
                "lease": { "lease_token": "{lt_1}", "lease_epoch": 1, "attempt": 1, "lease_secs": 30, "domain": "default" },
                "authority": { "mode": "worker", "checked": [], "checked_at": "2026-11-03T10:00:00Z" },
                "resumed": null } ] }
```

## Side effects
- `task {task_9} state is claimed`; history of {task_9} gains `taskClaimed` with `actor = {platform_worker}`.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| system queue, PDP allows `ignore` | (representative) | `200`, `{task_9}` with `owner_tenant_id = {tenant_c}` | DESIGN.md:1024 |
| PDP refuses `ignore` | PDP denies `barrier_mode: ignore` on `system` | `204 No Content`; `task {task_9} state is queued` | |
| tenant-operated queue | `{task_3}` (**render**, tenant C) and `{task_1}` (**render**, tenant A) `queued` in **reports**; claim names only **reports**, `max_tasks: 10` | `200`; `claims` holds `{task_1}` only. `{task_3}` is never returned, on this or any later claim. `task {task_1} state is claimed`; `task {task_3} state is queued` | **reports** is not `operated_by: platform`, so the claim respects barriers (PRD.md:1535, ADR-0016:99) |
| mixed claim | no other task queued; claim names **system** and **reports** | `204 No Content`; `task {task_9} state is queued` | one tenant-operated queue switches the whole claim to `respect` (DESIGN.md:2407) |

## Notes
- The SDK should run a separate claim loop for platform queues; the docs do not say so (DESIGN.md:703 describes per-domain loops only).
- A platform gear names the owner tenant with the create field `owner_tenant_id` (default: the caller's tenant). The PDP decides; barrier `Ignore` is sent only when the task's queue is `operated_by: platform` (G-SEC-13). The same rule covers later operations on such tasks: read, search filtered to platform queues only, cancel, re-enqueue and reassign send `Ignore` and let the PDP decide; tenant-operated queues get no bypass (G-SEC-15, [1.11](1.11-guardrail-tenant-scope-of-reads.md)).
