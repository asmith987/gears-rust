# With the PDP unreachable, reads, creates and creator checks fail closed

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-authz` (PRD.md:918) · `cpt-cf-task-engine-fr-worker-principals` (PRD.md:958) · PRD.md:961 · DESIGN.md:245, :1022, :1041, :1215, :2552 |
| Phase | p1 |
| Test level | Integration — PDP outage injection |
| Gaps | G-SEC-01, G-SEC-03 |

Authorization fails closed: with no PDP answer, no task data is returned and nothing is written, so the caller knows to retry and the engine keeps no partial state. Every endpoint answers `503` with `Retry-After` (`unavailable_retry_after_secs`, default 5); leases are kept (G-SEC-01). PRD.md:918 and DESIGN.md:245 still say `403` and change to `503`; PRD.md:961, DESIGN.md:1022 and :1215 already use `503`.

## Setup
- `{task_1}` (**render**, tenant A) exists. The PDP does not answer.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `503 Service Unavailable`, `Retry-After: 5`, category `service_unavailable`, no task fields in the body.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.service_unavailable.v1~",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "Authorization service unavailable",
  "instance": "/api/task_engine/v1/tasks/{task_1}",
  "trace_id": "<trace>",
  "context": { "retry_after_seconds": 5 }
}
```

<!-- No side effects: the request is refused before any write. -->

## Notes
- Decided: `503` on every endpoint, fail closed for p1; a cached-decision path waits for the platform's decision-caching protocol (G-SEC-01). Tests pin the status and the header.
- `Retry-After` and `context.retry_after_seconds` carry `unavailable_retry_after_secs` (default 5) (G-SEC-03).
