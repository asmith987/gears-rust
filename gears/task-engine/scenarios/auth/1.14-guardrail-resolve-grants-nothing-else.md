# A subject granted only resolve can answer an input wait and nothing else

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-authz` (PRD.md:918, :922) · DESIGN.md:1016, :1098, :1199 |
| Phase | p2 |
| Test level | Integration — resolve-only grant |
| Depends on | Proposals › Task mutability › `update` covers only tags; `resolve` gets its own action |
| Gaps | G-SEC-18 |

The point of the separate `resolve` action is that "a service that answers a question gets no other right on the task". The approval service below can resolve the condition, but it cannot read the task, cancel it, or learn anything about it from a refusal.

## Setup
- `{approver_a}` (`<approver-a-token>`, tenant A): PDP grants task `resolve` only.
- `{task_1}` (**export**, tenant A) is `waiting` on input condition `{wc_1}`.

## Exchange 1 — resolve
```http
POST /api/task_engine/v1/wait-conditions/{wc_1}/resolve HTTP/1.1
Host: api.example.com
Authorization: Bearer <approver-a-token>
Content-Type: application/json

{ "value": { "approved": true } }
```
- `200 { "condition": { "id": "{wc_1}", "kind": "input", "state": "satisfied", "resolved_at": "2026-11-03T10:00:00Z", "resolved_by": "{approver_a}" } }`. No task fields in the body.

## Exchange 2 — read the task
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <approver-a-token>
```
- `404` (no `read`, so no existence oracle). `GET /tasks/{task_1}/wait-conditions` is `404` as well.

## Exchange 3 — cancel the task
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <approver-a-token>
Content-Type: application/json

{ "mode": "requested" }
```
- `404`, not `403`: the denial-path `read` check fails (DESIGN.md:1016).

## Side effects
- After Exchange 1: history of {task_1} gains `waitConditionSatisfied` with `actor = {approver_a}`, then `taskResumed`; `task {task_1} state is queued`.
- Exchanges 2 and 3 change nothing.

## Notes
- DESIGN.md:1199 answers `404` for a wait condition the caller may not `read`. Decided: the `404` rule exempts resolve, so a caller with `resolve` finds and resolves the condition by its ID without `read`; `GET` and `cancel` still answer `404` (G-SEC-18).
