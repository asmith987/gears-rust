# A request without valid credentials is refused with 401 on every engine route

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-authn` (PRD.md:909) · `cpt-cf-task-engine-fr-observability` (PRD.md:1112) · DESIGN.md:974-975, :1051-1054, :1056 |
| Phase | p1 |
| Test level | E2E — static-authn: no or bad token → 401 on every route (smoke) |

The platform authenticates every request before the engine sees it. The engine has no anonymous route, so a call without a valid bearer token never reaches a task lookup, a PDP call or a write. A missing, expired or unverifiable token gets the same treatment; the engine never falls back to an anonymous or default security context. Health goes through the platform health endpoints and metrics through the telemetry pipeline, so nothing under the base path answers without authentication and queue names, type IDs and counts cannot be scraped.

## Setup
- `{task_1}` (**render**, tenant A) exists.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
```

## Expected response
- `401 Unauthorized`, `application/problem+json`, category `unauthenticated`.
- The body says nothing about whether `{task_1}` exists.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.unauthenticated.v1~",
  "title": "Unauthenticated",
  "status": 401,
  "detail": "Authentication required",
  "instance": "/api/task_engine/v1/tasks/{task_1}",
  "trace_id": "<trace>",
  "context": { "reason": "MISSING_CREDENTIALS" }
}
```

<!-- No side effects: the request is refused before any write. -->

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| missing token | (representative) | `401`, `context.reason` present (`MISSING_CREDENTIALS`) | |
| expired token | `POST /tasks/{task_1}/cancel` `{ "mode": "requested" }` with `Authorization: Bearer <expired-token>` | `401`, `detail: "Token expired"`, `context.reason = "TOKEN_EXPIRED"`, `instance` `/api/task_engine/v1/tasks/{task_1}/cancel` | platform example code, `docs/arch/errors/categories/16-unauthenticated.md:77`. A worker whose token expires mid-run gets the same answer on its next call and must refresh its credentials; the lease is not touched by a refused call |
| malformed or wrongly signed token | `POST /tasks` with `Authorization: Bearer not-a-real-token`, `Idempotency-Key: 7d1f0c2e-render-r-42`, body `{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "report_id": "r-42", "format": "pdf" } }` | `401`, `detail: "Invalid token"`, `context.reason` present, `instance` `/api/task_engine/v1/tasks` | bad signature, wrong issuer or garbage. Checked before idempotency and validation: the same answer whether or not the key or body are valid. No `te_dedup` row is written for the key; a later valid request with the same key creates the task normally |
| worker and admin routes | `POST /tasks/claim`, `POST /tasks/heartbeat`, admin routes, without `Authorization` | `401` each | a test should sweep the whole route table under `/api/task_engine/v1` |
| metrics route, no token | `GET /api/task_engine/v1/metrics` without `Authorization` | `401` | the engine serves no anonymous health or metrics route (DESIGN.md:1051-1054) |
| metrics route, authenticated | `GET /api/task_engine/v1/metrics` with `<admin-token>` | `404` (unknown path) | |
| health routes | `/api/task_engine/v1/health`, `/healthz`, `/readyz` under the base path, without then with a token | `401`, then `404` | readiness is checked on the gateway's `/readyz` instead |

## Notes
- `context.reason` values come from the AuthN middleware (`docs/arch/errors/categories/16-unauthenticated.md:53`), not from the Task Engine docs; assert `type` and `status`, and only that `reason` is present.
