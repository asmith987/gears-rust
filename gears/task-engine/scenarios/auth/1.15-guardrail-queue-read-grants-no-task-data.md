# Queue read lets a subject inspect queues but see no task data

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-authz` (PRD.md:923) · DESIGN.md:980, :992, :1106-1107 · `schemas/instances/…queue_read.v1.json` |
| Phase | p1 |
| Test level | Integration — queue-read-only grant |
| Gaps | G-SEC-20, G-OPS-02, G-SEC-19 |

Queue actions live on the queue resource type, so a dashboard can be given queue visibility without any task right. It sees each queue's definition, limits and hold state, and nothing about individual tasks. Sampled counts need `configure` on the queue as well (queues have no `admin` action, G-OPS-02).

## Setup
- `{ops_viewer}` (`<ops-viewer-token>`, root tenant): queue `read` only, no task action.
- `{task_1}` (**render**, tenant A) `queued` in **reports**.

## Exchange 1 — inspect the queue
```http
GET /api/task_engine/v1/queues/gts.cf.core.tasks.queue.v1~acme.reports._.render.v1 HTTP/1.1
Host: api.example.com
Authorization: Bearer <ops-viewer-token>
```
- `200`, queue resource (CONVENTIONS §5.9) with `limits`, `settings`, `domains`, `hold`. `counts` and `sampled_at` are omitted: `{ops_viewer}` holds no queue `configure` (G-OPS-02). No task IDs, tenant IDs or per-tenant counts.

## Exchange 2 — search tasks
```http
GET /api/task_engine/v1/tasks?view=tiny HTTP/1.1
Host: api.example.com
Authorization: Bearer <ops-viewer-token>
```
- `403 Forbidden`, category `permission_denied`, `context.reason = "ACTION_DENIED"`: the PDP denies `read` outright.

## Exchange 3 — read one task
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <ops-viewer-token>
```
- `404` (no `read`, no existence oracle).

<!-- No side effects: reads only. -->

## Notes
- A search the PDP denies outright is `403` `ACTION_DENIED`; a granted scope that matches nothing is `200` with an empty page (G-SEC-20).
- A caller with queue `read` and `configure` (for example `{admin}`) gets `counts` and `sampled_at` too (G-OPS-02).
- The reverse also holds: `{creator_a}` without queue `read` gets `403` `ACTION_DENIED` on `GET /queues`.
