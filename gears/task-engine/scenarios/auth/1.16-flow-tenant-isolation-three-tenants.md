# No API path lets one tenant see or change another tenant's tasks (three tenants)

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-nfr-tenant-isolation` (PRD.md:1268-1270) · `cpt-cf-task-engine-fr-tenant-scoping` (PRD.md:934) · PRD.md:363, :1495 · DESIGN.md:204, :2348 |
| Phase | p1 |
| Test level | E2E — three static-authn tenants (smoke) |
| Gaps | G-SEC-05, G-SEC-10, G-SEC-20, G-OPS-14 |

The isolation NFR asks for automated tests with at least three tenants and zero leaks on every endpoint. This flow is the template: one task per tenant, then each tenant probes the others through every read, write and worker path.

## Setup
- `{task_1}` (**render**, tenant A, tags `[{ "key": "project", "value": "q4" }]`, `queued`), `{task_2}` (**render**, tenant B, tags `[{ "key": "project", "value": "b-only" }]`), `{task_3}` (**render**, tenant C, `queued`).
- `{creator_c}` with token `<creator-c-token>`: same grants as `{creator_a}`, in tenant C (behind a barrier).

## Exchange 1 — B reads A's task, history, entries and waits
```http
GET /api/task_engine/v1/tasks/{task_1}/events HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-b-token>
```
- `404`, the body of [foreign task looks missing](1.10-guardrail-no-existence-oracle.md). The same `404` for `GET /tasks/{task_1}`, `GET /tasks/{task_1}/entries`, `GET /tasks/{task_1}/entries/{entry_1}`, `GET /tasks/{task_1}/wait-conditions`.

## Exchange 2 — B tries to change A's task
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-b-token>
Content-Type: application/json

{ "mode": "forced" }
```
- `404` (not `403`). The same for `POST /tasks/{task_1}/entries` (API-consumer entry) and for `{task_1}` inside `POST /tasks/bulk/cancel` (`200`, per-task `outcome: "not_found"`: B holds `cancel`, so the action is not denied outright, G-OPS-14).

## Exchange 3 — B searches and counts with A's tag
```http
GET /api/task_engine/v1/tasks?$filter=has_tag('project', 'q4')&view=long HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-b-token>
```
- `200`, `"items": []`. `GET /tasks/count?$filter=has_tag('project', 'q4')` → `{ "count": 0, "capped": false }`. B's scope is granted but matches no A task, so the answer is an empty page, not `403` (G-SEC-20). A's tag key is not visible to B (PRD.md:363).
- An unfiltered search by B returns `{task_2}` only; by C returns `{task_3}` only; by A returns `{task_1}` only.

## Exchange 4 — B's worker claims from the shared queue
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-b-token>
Content-Type: application/json

{ "worker_id": "reports-b-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 10, "timeout_secs": 1 }
```
- `200` with exactly one claim, `{task_2}`. Never `{task_1}` or `{task_3}`, however many claims follow.

## Side effects
- `task {task_1} state is queued`, `task {task_3} state is queued`; their histories gain nothing.
- `task {task_2} state is claimed`.

## Notes
- Repeat the flow with the roles rotated (A probes B and C, C probes A and B). C sits behind a barrier; the result is the same in both directions.
- Worker calls with a stolen lease token are covered by fencing ([../worker/fencing/](../worker/fencing/)): a valid token from another subject returns `LEASE_LOST` (PRD.md:1522).
- Tag filters use the engine function `has_tag('key', 'value')`; the ToolKit parser has no `any()` lambda (G-SEC-05).
- C's history stays complete, but until #5492 ships C gets no broker events (G-SEC-10); that is not a leak and is covered in [../events/](../events/).
