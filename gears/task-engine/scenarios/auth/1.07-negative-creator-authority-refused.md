# A creator check that is denied or cannot be decided refuses the create, and nothing is stored

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-worker-principals` creator authority (PRD.md:957-958) · PRD.md:1538 · DESIGN.md:1033-1045, :1214, :2540-2556 · ADR-0016:77, :90, :100 |
| Phase | p1 |
| Test level | Integration — denied / undecidable creator check |
| Gaps | G-SEC-19, G-WIRE-15 |

**share** declares one creator check: the creator must hold `share` on the document named by `/document_id`. The check runs with the creator's own context before the create transaction. A denial refuses the create even though the type's workers could share the document. The engine accepts an allow only if it can decide every constraint itself (`Eq`/`In` on `owner_tenant_id`/`id`, or `InTenantSubtree` via the Tenant Resolver); a constraint that needs group membership or properties only the document gear knows fails closed.

## Setup
- PDP: `{creator_a}` is denied `share` on `gts.cf.docs._.document.v1~` `doc-77` (owner tenant A). `{worker_a}` would be allowed.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 91c3-share-doc-77

{
  "type": "gts.cf.core.tasks.task.v1~acme.docs._.share.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1",
  "input": { "document_id": "doc-77" }
}
```

## Expected response
- `403 Forbidden`, category `permission_denied`, `context.reason = "CREATOR_AUTHORITY"`.
- No field violations. The check and reference index appear only in `detail`; nothing echoes `doc-77` or any other resource identifier.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "Creator check 0 (source /document_id, action share), reference 0: denied",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": {
    "resource_type": "gts.cf.core.tasks.task.v1~acme.docs._.share.v1~",
    "reason": "CREATOR_AUTHORITY"
  }
}
```

## Side effects
- No `te_tasks` row, no `te_dedup` row for `91c3-share-doc-77` (the idempotency key is not taken), no history, nothing published.
- `metric te_creator_checks_total{outcome="denied"} increases by 1`.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| denied | (representative) | `403`, `CREATOR_AUTHORITY`; metric `outcome="denied"` | |
| not decidable | PDP returns allow for `share` on `doc-77` with one constraint `InGroup(owner_group, editors)` | `403`, `context.reason = "CREATOR_AUTHORITY_UNVERIFIABLE"`, `detail` naming check 0 and reference 0, no field violations; no task stored, key not taken; `metric te_creator_checks_total{outcome="unverifiable"} increases by 1` | DESIGN.md:1035-1039, ADR-0016:90 |

## Notes
- DESIGN.md:1040 asks for a violation naming the check, but the platform `permission_denied` context has no `field_violations` (`docs/arch/errors/categories/07-permission-denied.md:53-68`). Decided: the `403` carries only its reason; the check and reference index go into `detail` (G-SEC-19, G-WIRE-15).
- The recommended route for work the engine cannot verify is gear-mediated creation with a platform-owned `worker` type (DESIGN.md:1045).
- PDP unreachable during the check is a `503`: see [PDP unreachable](1.09-negative-pdp-unreachable-fails-closed.md).
