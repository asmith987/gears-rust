# References no creator check covers are stored and shown as verified: false

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-resource-refs` (PRD.md:372-374) · PRD.md:1538 · DESIGN.md:875, :1043 · ADR-0016:100 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-SEC-04, G-SEC-05 |

A resource reference is a claim made by the creator, not a proof of access. **render** declares no checks, so its reference is stored with `verified: false`, and every place that shows references shows the flag: the task, the claim, search and published events.

## Setup
- None beyond the fixtures.

## Exchange 1 — create with a reference
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-42

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42", "format": "pdf" },
  "resource_refs": [ { "resource_type": "gts.cf.docs._.document.v1~", "resource_id": "doc-77" } ] }
```
- `201`; body has `"resource_refs": [ { "resource_type": "gts.cf.docs._.document.v1~", "resource_id": "doc-77", "verified": false } ]`. A `verified: true` sent by the caller is ignored.

## Exchange 2 — claim
- `POST /tasks/claim` by `{worker_a}` on **reports** → the claim's `task.resource_refs[0].verified` is `false`; `authority.checked` is `[]`.

## Exchange 3 — search
```http
GET /api/task_engine/v1/tasks?$filter=has_resource_ref('gts.cf.docs._.document.v1~', 'doc-77')&view=long HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200`; the item for `{task_1}` shows the reference with `verified: false`.

## Side effects
- `event taskCreated for {task_1} is published to the task-events topic` with `data.resource_refs[0].verified = false`.

## Notes
- No search view in DESIGN.md:1165-1170 lists `resource_refs`, though PRD.md:374 says search shows the flag; `long` adds `result` and `resource_refs` (G-SEC-04). Reference filters use the engine function `has_resource_ref('type', 'id')`, since the ToolKit parser has no `any()` lambda (G-SEC-05). The search runs inside the default `created_at` window.
- Whether the create request may send `verified` at all is unspecified; assumed ignored.
