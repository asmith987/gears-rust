# A subject allowed to create only type A gets 403 for type B

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-resource-path-access` (PRD.md:943) · PRD.md:1531 · DESIGN.md:1007, :1014, :2534 · ADR-0016:72, :97 |
| Phase | p1 |
| Test level | Integration — type policy |
| Gaps | G-SEC-19 |

The engine sends each task's concrete type and queue to the PDP. A policy can therefore grant `create` on one type only. A type the caller can see but may not create is a `403`, not an unknown type.

## Setup
- PDP: `{creator_a}` task `create` allowed only with `type_id eq gts.cf.core.tasks.task.v1~acme.reports._.render.v1~`.
- **export** (`gts.cf.core.tasks.task.v1~acme.billing._.export.v1~`) is registered and visible to tenant A.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 5a0e-export-2026-10

{
  "type": "gts.cf.core.tasks.task.v1~acme.billing._.export.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "period": "2026-10" }
}
```

## Expected response
- `403 Forbidden`, category `permission_denied`, `context.reason = "ACTION_DENIED"`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "Not allowed to create tasks of this type in this queue",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~acme.billing._.export.v1~", "reason": "ACTION_DENIED" }
}
```

<!-- No side effects: the request is refused before any write. -->

## Notes
- The same request with **render** succeeds (`201`). A policy narrowed by `queue_id` behaves the same way for queues.
- A type that the caller cannot see at all is `400` `UNKNOWN_TASK_TYPE` (PRD.md:1009), not `403`: see [../tasks/create/](../tasks/create/).
- No `te_dedup` row is taken for the key; authorization runs before dedup (DESIGN.md:2376).
