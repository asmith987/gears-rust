Standard filters combine with `and`. Each is served inside the tenant's index range, so a selective filter does not scan the whole window, and each returns only tasks in the caller's tenant scope. Every row runs as `{creator_a}` on tasks in the default window, and items come newest first.

## Setup
- Tenant A, all in the default window: `{task_1}` (**render**, **reports**, `queued`), `{task_2}` (**render**, **bulk**, `queued`), `{task_3a}` (**export**, **reports**, `queued`), `{task_4a}` (**render**, **reports**, `running`).

## Request
```http
GET /api/task_engine/v1/tasks?$filter=state eq 'queued' and queue eq 'gts.cf.core.tasks.queue.v1~acme.reports._.render.v1' and type eq 'gts.cf.core.tasks.task.v1~acme.reports._.render.v1~'&view=tiny HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200`; `items` is exactly `[{ "id": "{task_1}", "state": "queued", "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~" }]`.

## Notes
- A `state` filter that allows only non-terminal states also removes the time window ([window](1.03-positive-explicit-range-and-unfinished-only-window.md)).
- Tag and resource-reference filters are engine filter functions, because the ToolKit OData parser has no `any()` lambda: `has_tag('key')`, `has_tag('key', 'value')`, `has_resource_ref('type', 'id')` (G-SEC-05). Refs appear from `view=long` up (G-SEC-04).
- A task with two matching refs of the same type and ID cannot occur: the `te_resource_refs` key includes both (DESIGN.md:1895).
- Whether `assignee` is the subject (`assignee_subject`) or the process (`worker_id`) is not specified; the subject is assumed, since `assignee_subject` is the PDP property (DESIGN.md:1012).
- `parent_task_id eq …` and `predecessor_id eq …` are plain fields inside the default window (G-SEC-05). `predecessor_id` on a finished successor must read `te_task_results.predecessors` (DESIGN.md:1432), since `te_dependencies` rows are live-only. The older `dependencies` filter (unmet / all-met, DESIGN.md:1138) has no syntax.
- `dead_lettered_from eq …` is a plain field too (G-RTY-11); its home is [DLQ listing](../dead-letter/1.02-positive-list-dead-lettered-by-search.md).
- The 12 filter fields are a documented exception to the REST guideline's cap of 10 (G-SEC-27).
