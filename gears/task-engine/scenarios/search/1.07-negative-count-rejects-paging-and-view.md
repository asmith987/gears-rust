# The count endpoint rejects $orderby, $select, $top, $skiptoken and view

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-search` (PRD.md:1139) · DESIGN.md:1174 |
| Phase | p1 |
| Test level | E2E |

Count takes only `$filter`. Parameters that shape a page make no sense for it and are refused rather than ignored.

## Request
```http
GET /api/task_engine/v1/tasks/count?$filter=state eq 'queued'&$orderby=created_at desc HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `400 Bad Request`, category `invalid_argument`, field violation on `$orderby`.
- Each of `$select=id`, `$top=10`, `$skiptoken={cursor_1}` (or `cursor=`), `view=tiny` gets the same answer with its own field named.

<!-- No side effects: reads only. -->

## Notes
- The count also applies the bounds: a `created_at` range over 31 days → `400` as in [unsupported query](1.06-negative-unsupported-query.md).
- The aliases `limit` and `cursor` are refused the same way: they bind to the same slots as `$top` and `$skiptoken`.
