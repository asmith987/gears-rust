# A search query the engine cannot serve within its bounds is rejected with 400, never silently narrowed

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-search` (PRD.md:1136, :1138-1139, :1143-1144) · PRD.md:1509 · DESIGN.md:1136, :1140-1147, :1161, :1163, :1225, :2821, :2823, :2826 · `docs/toolkit_unified_system/07_odata_pagination_select_filter.md:377-378, :400-423, :435-439, :576` |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-SEC-04, G-SEC-26 |

Only queries an index can serve at the capacity profile are allowed. An unsupported order, a window over 31 days, an unsupported `$` option, a `$select` outside the view, an unknown view or a zero-size page is refused with `400 invalid_argument` and a field violation naming the offending parameter, so a client never gets a page that silently ignored part of its query. Allowed orders are `created_at` and, for finished tasks, `terminal_at`.

## Request
```http
GET /api/task_engine/v1/tasks?$orderby=priority asc HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `400 Bad Request`, category `invalid_argument`; the violation names the allowed keys.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Unsupported $orderby key 'priority'; allowed: created_at, terminal_at",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~",
               "field_violations": [ { "field": "$orderby", "description": "allowed keys: created_at, terminal_at (terminal states only)", "reason": "NOT_ALLOWED" } ] }
}
```

## Notes
- Accepted counterparts: `$orderby=created_at asc` (oldest first; `id` is always appended in the same direction); `$orderby=terminal_at desc&$filter=state in ('completed', 'failed')` (latest-finished first, within the creation window); `view=long&$select=id,state,input` (items with exactly those three members).
- `terminal_at` is not a field of any view (DESIGN.md:1165-1170), so a client cannot see the value it sorted by (G-SEC-04).
- `UNSUPPORTED_QUERY_PARAM` is a field-violation `reason` here, as the ToolKit builds it, not `context.reason`. A total comes from `GET /tasks/count`.
- Reasons (G-SEC-26): an unsupported `$orderby` key, a `$select` field outside the view and an unknown `view` are `NOT_ALLOWED` on that parameter, named as sent; a `created_at` range over the window is `OUT_OF_RANGE` on `$filter`.
- Unknown non-`$` parameters (for example `?status=queued`) are not rejected by the ToolKit extractor (`07_odata_pagination_select_filter.md:435-439`); the docs do not say whether the engine refuses them. A dropped filter would return an unfiltered page.
- A `limit` above the cap is clamped, not refused: [page size clamped](1.08-guardrail-page-size-clamped.md).
