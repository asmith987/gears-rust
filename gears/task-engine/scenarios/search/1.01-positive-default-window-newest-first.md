# Search without a time range covers the last 7 days, newest first

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-search` (PRD.md:1136-1143) · PRD.md:1509 · DESIGN.md:1136, :1144, :1147, :1161, :1168, :1176, :2147 |
| Phase | p1 |
| Test level | Both — E2E newest-first; integration 7-day window (needs aged rows) |
| Gaps | G-SEC-04, G-SEC-25, G-RTY-10, G-RTY-11 |

A search that can return finished tasks and names no `created_at` range gets `created_at ge now − 7d` added. The one exception is a search whose state filter restricts it to `dead_lettered`, whatever its other filters, which has no window ([DLQ listing](../dead-letter/1.02-positive-list-dead-lettered-by-search.md), G-RTY-10). The default order is `created_at desc` with `id desc` as tie-breaker; the default view is `short`.

## Setup
- Now is `T0`. Tenant A has `{task_1}` (`queued`, created `T0-1h`), `{task_2}` (`completed`, created `T0-2d`), `{task_6}` (`completed`, created `T0-8d`), all **render** in **reports**.

## Request
```http
GET /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, a `JsonPage` with `{task_1}` then `{task_2}`; `{task_6}` is outside the window.

## Notes
- The `short` view uses the task resource's names: `assignment` (DESIGN.md:1168 says `assignee`), `null` for unassigned tasks (G-SEC-04), and carries `dead_lettered_from` (G-RTY-11).
- `page_info.limit` echoes the applied page size (DESIGN.md:1161); with no `limit` it is 25 (G-SEC-25).
