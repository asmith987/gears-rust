# Input that fails the type's schema is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-create` (PRD.md:254) · `cpt-cf-task-engine-fr-structured-io` (PRD.md:269) · `cpt-cf-task-engine-nfr-data-protection` (PRD.md:1360, :1364) · DESIGN.md:1210 · DESIGN.md:2538 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-07, G-SEC-21, G-CRT-24 |

The engine validates `input` against the registered input schema before it opens the create transaction (DESIGN.md:2538). **render** requires `report_id`.

## Setup
- As [Minimal create](1.01-positive-minimal-create-queued.md).

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-noid

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "format": "docx" }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, one field violation per failure, each a JSON Pointer into `/input` with reason `SCHEMA_VIOLATION`; each `description` names the failed keyword, never the value (G-SEC-21).
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Input does not match the task type's input schema",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
    "field_violations": [
    { "field": "/input/report_id", "description": "required", "reason": "SCHEMA_VIOLATION" },
    { "field": "/input/format", "description": "enum", "reason": "SCHEMA_VIOLATION" }
  ] }
}
```

## Side effects
- Nothing is stored: no task, no `te_dedup` row, so the same `Idempotency-Key` with a valid input later creates a task.
- **No payload echo** (PRD.md:1360, :1364): the response body does not contain the submitted value `docx` anywhere (not in `detail`, not in any `description`); validator messages are never forwarded (G-SEC-21); and the engine's log line for this request carries the field path but no input value. This is the home of the no-echo rule listed in [ERRORS.md](../../ERRORS.md).

## Notes
- Field paths are RFC 6901 JSON Pointers from the body root and every user-schema failure is `SCHEMA_VIOLATION` (G-SEC-21, G-CRT-07). Assert the category, status, reason and both pointers; the exact `description` wording is free as long as it names the keyword and no value.
- The schema check runs after the type, queue, PDP, `expedite` and `Idempotency-Key` checks (G-CRT-24).
