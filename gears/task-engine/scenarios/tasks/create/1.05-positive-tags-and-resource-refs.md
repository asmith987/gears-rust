# Tags and resource references are set at create; references are unverified without a check

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-tags` (PRD.md:361) · `cpt-cf-task-engine-fr-resource-refs` (PRD.md:370-374) · DESIGN.md:1868-1895 · task-type schema `authority` |
| Phase | p2 |
| Test level | E2E |
| Depends on | Proposals › Task mutability › Set only in the create request |
| Gaps | G-CRT-06, G-CRT-10, G-SEC-05, G-WIRE-04 |

Tags and resource references are the caller's labels for later search. Resource references can be set only at create; tags can be set here and changed later with `PATCH /tasks/{id}/tags` ([1.13](1.13-positive-update-tags-after-create.md)). Limits: at most 16 tags, key 1–128 and value 0–256 characters (G-CRT-06); `resource_id` at most 256 characters (G-CRT-10); refusals in [field limits](1.10-negative-field-limits.md). **render** has no creator checks (`authority` absent = `creator_verified` with no checks), so every reference is stored and published with `verified: false` (PRD.md:374).

## Setup
- As [Minimal create](1.01-positive-minimal-create-queued.md), clock at `T0`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-48

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-48", "format": "pdf" },
  "tags": [{ "key": "project", "value": "q4" }, { "key": "region", "value": "eu-west" }],
  "resource_refs": [ { "resource_type": "gts.cf.docs._.document.v1~", "resource_id": "doc-17" } ]
}
```

## Expected response
- `201 Created`; `tags` as sent, sorted by key (G-WIRE-04); `resource_refs[0].verified` is `false` (a caller-sent `verified` would be ignored; the engine sets it).
```json
{
  "id": "{task_1}",
  "state": "queued",
  "tags": [{ "key": "project", "value": "q4" }, { "key": "region", "value": "eu-west" }],
  "resource_refs": [ { "resource_type": "gts.cf.docs._.document.v1~", "resource_id": "doc-17", "verified": false } ],
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- `te_tags({task_1}, "project")` and `te_tags({task_1}, "region")` are present.
- `te_resource_refs({task_1}, gts.cf.docs._.document.v1~, "doc-17")` is present with `verified = false`.
- history of {task_1} gains `taskCreated` with `initial_state: "queued"`, `resource_refs: [{ resource_type: "gts.cf.docs._.document.v1~", resource_id: "doc-17", verified: false }]`.
- subsequent `GET /tasks?$filter=has_tag('region', 'eu-west')` by `{creator_a}` includes {task_1}; the same search by `{creator_b}` does not.

## Notes
- Tag search uses the engine function `has_tag` (CONVENTIONS §5.9, G-SEC-05); search behaviour is owned by [search](../../search/). The line only shows that tags are tenant-local (PRD.md:363).
- `resource_id` is at most 256 characters, the `te_resource_refs.resource_id` length (DESIGN.md:1891); the event schemas change `maxLength` from 1024 to 256 (G-CRT-10).
