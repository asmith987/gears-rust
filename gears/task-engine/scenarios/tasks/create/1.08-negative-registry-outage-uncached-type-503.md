# Registry unreachable: an uncached type fails closed with 503, a cached type is still served

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-create` (PRD.md:253) · DESIGN.md:1219 |
| Phase | p1 |
| Test level | Integration — registry outage |
| Gaps | G-CRT-23, G-SEC-03, G-CRT-24 |

If the GTS registry cannot be reached and the engine has not resolved the type before, it cannot validate the input or the type's traits. It must fail closed with `503` and `Retry-After` rather than accept the task unchecked. Cached type metadata (schemas, trait and trust-limit verdicts, keyed by reference and revision) stays usable for the whole outage, so a type already cached is still served (G-CRT-23).

## Setup
- The GTS registry is unreachable from every engine node.
- No node has resolved **render** since start (the type cache is empty).

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-49

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-49", "format": "pdf" }
}
```

## Expected response
- `503 Service Unavailable`, `service_unavailable`, header `Retry-After: 5` (`unavailable_retry_after_secs`, G-CRT-23, G-SEC-03).
```http
HTTP/1.1 503 Service Unavailable
Content-Type: application/problem+json
Retry-After: 5
```
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.service_unavailable.v1~",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "Task type registry is unavailable",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "retry_after_seconds": 5 }
}
```

<!-- No side effects: the request is refused before any write. -->

## Cases

| Case | Differs from the representative | Expected | Notes |
|---|---|---|---|
| uncached | (representative) | `503`, `Retry-After: 5`; nothing stored | G-CRT-23 |
| cached | **render** was resolved on this node before the outage, and `{tenant_a}`'s visibility entry for it is within its TTL | `201 Created`, `state: queued`, as in [1.01](1.01-positive-minimal-create-queued.md) | PRD.md:253 "and the type is not known yet"; G-CRT-23 |
| visibility expired | as **cached**, but `{tenant_a}`'s per-tenant visibility entry for **render** has passed its normal TTL during the outage | `503`, `Retry-After: 5` | G-CRT-23: visibility entries keep their TTL |

## Notes
- The type is checked first after JSON parsing (G-CRT-24), so the `503` comes before the queue, PDP and `Idempotency-Key` checks.
