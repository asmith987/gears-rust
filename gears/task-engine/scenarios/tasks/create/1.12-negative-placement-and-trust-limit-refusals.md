# Creates outside the type's trust limits or into a queue that may not hold the task are rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-type-trust` (PRD.md:1010, :1011) · `cpt-cf-task-engine-fr-timeouts` (PRD.md:519) · `cpt-cf-task-engine-fr-worker-principals` (PRD.md:955) · `cpt-cf-task-engine-fr-dead-letter` (PRD.md:801) · `cpt-cf-task-engine-fr-gts-queue` (PRD.md:995-997) · DESIGN.md:590 · DESIGN.md:715 · DESIGN.md:1047 · DESIGN.md:1213 · DESIGN.md:2192 · DESIGN.md:2204 · task-type schema `heartbeat_timeout_secs` · queue schema `accepted_types` |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-02, G-CRT-03, G-CRT-04, G-CRT-05, G-CRT-07, G-CRT-24, G-SEC-21, G-WIRE-15 |

The engine checks the chosen queue and the requested settings before it stores anything. An unregistered queue is `404` and a dead-letter queue `400 DEAD_LETTER_QUEUE`, both right after the type and before the PDP (G-CRT-03, G-CRT-02, G-CRT-24). The other refusals are `400` `invalid_argument` from the trust-limit step after the `Idempotency-Key` check, with a field violation on the field's JSON Pointer; the `description` names the setting (PRD.md:1010). Only a value the request itself sets above a trust limit is refused; an inherited or defaulted one is clamped ([settings resolution](1.03-positive-settings-resolution.md), G-CRT-05). A tenant-owned type's effective execution timeout may not exceed `trust_limits.tenant_owned.max_execution_timeout_secs` (3600), so no task can hold a slot without bound while its worker heartbeats. The lease is the task's `heartbeat_timeout_secs`; its minimum is `trust_limits.min_lease_secs` (10 s), so a worker is never asked to heartbeat faster than every 3 s. Platform workers on `operated_by: platform` queues may cross tenant barriers, so a tenant must not be able to hand its own type to them, even when the caller holds `create`. A queue may list the task types it accepts (each entry also covers types derived from it). A `dead_letter` queue "only holds `dead_lettered` tasks" and is never dispatched (PRD.md:801). "Task creation and claims MUST name registered queues" (PRD.md:995).

## Setup
- **render** is tenant-owned. **system** is `operated_by: platform` (shipped). **dead_letter** is the shipped `kind: dead_letter` queue.
- The PDP would allow `{creator_a}` to `create` **render** in any queue (the checks under test are the engine's, not the PDP's).
- Queue `gts.cf.core.tasks.queue.v1~acme.billing._.exports.v1` (**exports**): dispatch settings as **reports**, `accepted_types: ["gts.cf.core.tasks.task.v1~acme.billing._.export.v1~"]`.
- No queue `gts.cf.core.tasks.queue.v1~acme.reports._.renderr.v1` is registered.

## Request
Representative case: execution timeout above the trust limit.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-long

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-53", "format": "pdf" },
  "timeouts": { "execution_timeout_secs": 7200 }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`; the field violation is on `/timeouts/execution_timeout_secs` with reason `TRUST_LIMIT`, and its `description` names the limit `trust_limits.tenant_owned.max_execution_timeout_secs`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "execution_timeout_secs 7200 exceeds the limit for tenant-owned task types",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/timeouts/execution_timeout_secs", "description": "above trust_limits.tenant_owned.max_execution_timeout_secs (3600)", "reason": "TRUST_LIMIT" } ] }
}
```

## Notes
- The field violation is on the field's JSON Pointer (G-SEC-21); the violated config key appears in `description` (G-CRT-07). The queue refusals use the generic `NOT_ALLOWED`, as [ERRORS.md](../../ERRORS.md) lists for a tenant type on a platform queue and a type outside `accepted_types`.
- **dead-letter queue**: a new task placed there would never run and would sit outside every timeout path. G-CRT-02 decides `400 DEAD_LETTER_QUEUE` on `/queue`, the same code a claim gets (DESIGN.md:2432).
- **unknown queue**: queues are platform-owned and listed by `GET /queues`, so naming a missing one reveals nothing. G-CRT-03 decides `404`, as for a claim; the error table (DESIGN.md:1195-1236) gains the row.
- **partial retry policy**: the same rule applies to a type's `retry_policy` trait; the request-level row is shown because it is testable over HTTP.
