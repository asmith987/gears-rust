The base case every other create scenario varies: a known type, a named queue, valid input and an idempotency key. The engine stores the task, arms its timers and records `taskCreated` in one atomic step (PRD.md:257), and the task enters `queued` because it has no predecessors and no `run_after` (PRD.md:258).

## Setup
- `{creator_a}` holds `create` and `read` on **render** (CONVENTIONS §4).
- Clock at `T0`. No task with key `7d1f0c2e-render-r-42` exists for `{creator_a}`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-42

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "priority": 100,
  "input": { "report_id": "r-42", "format": "pdf" },
  "tags": [{ "key": "project", "value": "q4" }]
}
```

## Expected response
- `201 Created`, `Location: /api/task_engine/v1/tasks/{task_1}`.
- `state` is `queued`; `created_by` is `{creator_a}` (server-set, DESIGN.md:717); `owner_tenant_id` is `{tenant_a}`; `attempt` is `0`; `urgency` defaults to `normal`.
- `timeouts` and `retry_policy` are the resolved values of **reports** (the type declares none, PRD.md:980), stored on the task at create (G-CRT-04).
- The body carries no `Idempotency-Key` field (G-CRT-09).
```json
{
  "id": "{task_1}",
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "owner_tenant_id": "{tenant_a}",
  "created_by": "{creator_a}",
  "state": "queued",
  "urgency": "normal",
  "priority": 100,
  "attempt": 0,
  "result": null,
  "timeouts": { "queue_timeout_secs": 3600, "assignment_timeout_secs": 60, "execution_timeout_secs": 900, "heartbeat_timeout_secs": 30, "lifetime_timeout_secs": 86400 },
  "created_at": "2026-11-03T10:00:00Z",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- task {task_1} state is `queued`.
- timer `queue_timeout` for {task_1} is armed at `T0+3600s`.
- timer `lifetime` for {task_1} is armed at `T0+86400s`.
- No `sla` timer (no `sla_deadline`); no `execution` deadline yet (set by the claim, G-EXE-10).
- history of {task_1} gains `taskCreated` with `initial_state: "queued"`, `queue` = **reports**, `actor` = `{creator_a}`; no `taskQueued` (G-SEC-23, G-SEC-11).
- event `taskCreated` for {task_1} is published to the task-events topic (default `lifecycle` policy, DESIGN.md:2218).
- `te_dedup(owner_tenant_id={tenant_a}, dedup_key=hash("idempotency-key", {creator_a}, "7d1f0c2e-render-r-42"))` is present with `window = caller_key`, the resolved queue **reports** stored for retry matching (G-CRT-11), `expires_at = NULL` while the task is live (G-CRT-13; DESIGN.md:1707-1729).
- subsequent `GET /tasks/{task_1}` returns `200` with `state: queued`.

## Notes
- The `201` body (the full task resource) and `Location` header were agreed in the wire review (G-WIRE-03).
- `priority` is sent here; it is optional and defaults to the queue's `default_priority` (G-CRT-26, [1.02](1.02-positive-run-after-placement-and-lifetime-bound.md)).
