# Settings resolve request → type → queue → engine default, within the trust limits

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-gts-task-type` (PRD.md:980) · `cpt-cf-task-engine-fr-timeouts` (PRD.md:519) · `cpt-cf-task-engine-fr-type-trust` (PRD.md:1010) · DESIGN.md:715 · DESIGN.md:2085-2086 · DESIGN.md:2204 · `schemas/types/gts.cf.core.tasks.task.v1~.schema.json` (`default_queue`, `timeouts`, `retry_policy`) · queue schema `timeouts` |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-04, G-CRT-05 |

The engine resolves every setting as request → type trait → queue effective value, and stores the result on the task (PRD.md:980, DESIGN.md:715). The queue comes from the type's `default_queue` when the request names none. Each timeout field is resolved separately, but a retry policy is never merged: the first level that has one wins whole. Every task has an execution timeout (PRD.md:519): when no level sets one, the engine default applies; and a value inherited from the queue is clamped to the trust limits, while a value the request itself sets above them is refused (G-CRT-05). All effective settings, including the lease `heartbeat_timeout_secs`, are resolved and stored at create and returned by `GET /tasks/{id}` (G-CRT-04).

## Setup
- Task type `gts.cf.core.tasks.task.v1~acme.reports._.thumbnail.v1~` (**thumbnail**), tenant-owned, visible to `{creator_a}`, input `{ "report_id": string (required) }`, traits:
  - `default_queue: "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"` (**reports**)
  - `timeouts: { "execution_timeout_secs": 600 }`
  - `retry_policy: { "max_retries": 1, "strategy": "fixed", "base_interval_secs": 10, "max_interval_secs": 10 }`
- `{creator_a}` holds `create`, `read` on **thumbnail**. Clock at `T0`.
- For the **engine default** case: queue `gts.cf.core.tasks.queue.v1~acme.reports._.adhoc.v1` (**adhoc**): `kind: dispatch`, concurrency 0/0, `default_priority: 100`, `timeouts` all `null`, retry policy as **reports**, no DLQ.
- **render** is tenant-owned and declares no `timeouts` trait.

## Request
Representative case: type defaults.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 3b9a-thumb-r-42

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.thumbnail.v1~",
  "input": { "report_id": "r-42" },
  "timeouts": { "queue_timeout_secs": 120 }
}
```

## Expected response
- `201 Created`; `queue` is **reports** (type `default_queue`, not the `default` queue).
- `timeouts`: `queue_timeout_secs` 120 from the request; `execution_timeout_secs` 600 from the type; the other three from **reports**.
- `retry_policy` is the type's policy whole, with schema defaults for the fields it omits. It does **not** inherit `non_retryable_codes: ["INVALID_REPORT"]` or `jitter_factor: 0.2` from **reports**.
- `priority` is **reports**' `default_priority` (100).
```json
{
  "id": "{task_1}",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "state": "queued",
  "priority": 100,
  "timeouts": { "queue_timeout_secs": 120, "assignment_timeout_secs": 60, "execution_timeout_secs": 600, "heartbeat_timeout_secs": 30, "lifetime_timeout_secs": 86400 },
  "retry_policy": { "max_retries": 1, "max_liveness_requeues": 20, "strategy": "fixed", "base_interval_secs": 10, "max_interval_secs": 10, "jitter_factor": 0, "non_retryable_codes": [] },
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- task {task_1}.queue is **reports**; task {task_1} state is `queued`.
- timer `queue_timeout` for {task_1} is armed at `T0+120s`; timer `lifetime` at `T0+86400s`.
- history of {task_1} gains `taskCreated` with `queue` = **reports**, `initial_state: "queued"`.
- A later change to the **thumbnail** trait or to **reports** does not change {task_1}'s stored `timeouts` or `retry_policy` (DESIGN.md:715).

## Notes
- **type defaults**: the type's retry policy carries the schema's required fields (`max_retries`, `strategy`, `base_interval_secs`, `max_interval_secs`); the omitted optional ones take the schema defaults (`max_liveness_requeues` 20, `jitter_factor` 0, `non_retryable_codes` []), not the queue's values (G-CRT-04). A request `retry_policy` without a required field is refused: [1.12](1.12-negative-placement-and-trust-limit-refusals.md).
- **engine default**: the stored `heartbeat_timeout_secs` is the resolved `30`, never `null`; DESIGN.md:530 reads the lease from the task (G-CRT-04).
- **inherited above the trust cap**: the shipped **default** queue sets `execution_timeout_secs: 86400`, within the platform cap, but tenant-owned types are capped at 3600. An inherited or defaulted value above the cap is clamped; only a value the request itself sets above it is refused (`400`, the **execution timeout above trust limit** case of [placement and trust-limit refusals](1.12-negative-placement-and-trust-limit-refusals.md)) (G-CRT-05).
