# Create fields outside their limits are rejected: priority, tags, resource references

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-priority-dispatch` (PRD.md:398) · `cpt-cf-task-engine-fr-tags` (PRD.md:361, :363) · `cpt-cf-task-engine-fr-resource-refs` (PRD.md:372) · DESIGN.md:1876 (`te_tags.key` VARCHAR(128)) · DESIGN.md:1877 (`te_tags.value` VARCHAR(256)) · DESIGN.md:1895 · DESIGN.md:2078 · `task_created` schema `priority` (0–1000) |
| Phase | p1 (priority) · p2 (tags, resource references) |
| Test level | E2E |
| Depends on | Proposals › Task mutability › Set only in the create request (accepted: "with a new limit on tags per task") |
| Gaps | G-CRT-06, G-CRT-07, G-CRT-10, G-SEC-21, G-WIRE-04 |

Each bounded create field is checked before anything is stored, and a value out of bounds is refused with `400` `invalid_argument` and a field violation, never truncated or clamped. Priority runs from 0 (highest) to 1000 (lowest) (PRD.md:398); it orders only the caller's own tasks, so it needs no permission, but it must be in range. Tags: at most `max_tags_per_task` (16), key 1–128 and value 0–256 Unicode characters (PRD.md:363; G-CRT-06); a truncated key could collide with another tag. The reference list is bounded (PRD.md:372, shipped `max_resource_refs_per_task: 16`, DESIGN.md:2078); excess is `400` (DESIGN.md:1895); a `resource_id` is at most 256 characters (G-CRT-10).

## Setup
- As [Minimal create](1.01-positive-minimal-create-queued.md).
- Engine config `max_tags_per_task: 16` (default, G-CRT-06); shipped `max_resource_refs_per_task: 16`.
- `<129 x "k">` is a key of 129 ASCII characters; `<257 x "v">` a value of 257 ASCII characters; `<257 x "d">` a `resource_id` of 257 characters; `[{ "key": "t01", "value": "x" }, …, { "key": "t17", "value": "x" }]` stands for 17 tags with distinct keys; `{ "resource_type": "gts.cf.docs._.document.v1~", "resource_id": "doc-01" }`, … `"doc-17"` stand for 17 references.

## Request
Representative case: priority above range.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-p1001

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "priority": 1001,
  "input": { "report_id": "r-51", "format": "pdf" }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/priority`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "priority must be between 0 and 1000",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/priority", "description": "must be between 0 (highest) and 1000 (lowest)", "reason": "OUT_OF_RANGE" } ] }
}
```

## Notes
- The tags limits are p2, priority is p1.
- Tag lengths count Unicode characters, not bytes (G-CRT-06); the rows use ASCII so both readings agree.
- Field paths are JSON Pointers (G-SEC-21); `reason` values are the decided set (G-CRT-07). The tag-key repeat uses the generic `DUPLICATE`: G-WIRE-04 decides the `400` but names no code.
- A `description` names the rule and limit, never the value sent.
