# An unknown type, or one the caller cannot see, is rejected before anything is stored

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-create` (PRD.md:253) · `cpt-cf-task-engine-fr-type-trust` (PRD.md:1009) · PRD.md:1499 · DESIGN.md:1047 · DESIGN.md:1212 · DESIGN.md:2532 |
| Phase | p1 |
| Test level | Both — E2E unknown type; integration "cannot see" row |
| Gaps | G-WIRE-14, G-SEC-21, G-CRT-24 |

The type is resolved first (DESIGN.md:2532), with the caller's own security context. A type ID that the registry does not know is refused with `invalid_argument` and a field violation `UNKNOWN_TASK_TYPE` on `/type`; no row, timer or event is written. The type is checked right after JSON parsing, before the queue, the PDP and the `Idempotency-Key` (G-CRT-24). A tenant-owned type registered by another tenant is invisible to the caller and must give the same answer as a type that does not exist, so a caller cannot learn which private types other tenants have.

## Setup
- No task type `gts.cf.core.tasks.task.v1~acme.reports._.render_v2.v1~` is registered.
- For the **other tenant's type** case: tenant B registered the tenant-owned type `gts.cf.core.tasks.task.v1~acme.bprivate._.ledger_close.v1~`, visible only in `{tenant_b}`'s scope. `{creator_b}` can create tasks of it; `{creator_a}` cannot see it.

## Request
Representative case: unregistered type.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render2-r-42

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render_v2.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42" }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, `field_violations[0]` `{ field: "/type", reason: "UNKNOWN_TASK_TYPE" }`; no `context.reason` (G-WIRE-14).
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Unknown task type gts.cf.core.tasks.task.v1~acme.reports._.render_v2.v1~",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": {
    "field_violations": [ { "field": "/type", "description": "task type does not resolve to a registered type visible to the caller", "reason": "UNKNOWN_TASK_TYPE" } ] }
}
```

## Notes
- The idempotency key is not consumed: the same key with a valid type afterwards creates a task (see [refused create holds no key](../idempotency/1.07-guardrail-refused-create-holds-no-key.md)).
- **other tenant's type**: a test should compare the two responses field by field (except the type ID in `detail` and `trace_id`), and also compare latency loosely: a type cache keyed without the caller's tenant would leak through a faster answer.
