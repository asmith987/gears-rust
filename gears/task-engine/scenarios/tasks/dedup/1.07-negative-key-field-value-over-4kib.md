# A key field value over 4 KiB is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-derived-dedup` (PRD.md:300) · DESIGN.md:2187-2189 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-CRT-07, G-CRT-16, G-SEC-21 |

Each key field value may be at most 4 KiB (`dedup.max_key_value_bytes` 4096), measured on its JCS form, which is what is hashed (DESIGN.md:2566). The limit is on the value of one request, so it cannot be checked when the type is loaded; the create is refused with `400 TOO_LONG` on the value's input pointer (G-CRT-16).

## Setup
- **export** as in [1.01](1.01-positive-duplicate-by-derived-identity.md). Its input schema allows any string for `period`.
- `<5000 x "p">` stands for a 5,000-character string.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.billing._.export.v1~", "input": { "period": "<5000 x \"p\">" } }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/input/period`, reason `TOO_LONG`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "A dedup key field value exceeds 4096 bytes",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~acme.billing._.export.v1~",
    "field_violations": [ { "field": "/input/period", "description": "dedup key value longer than dedup.max_key_value_bytes (4096)", "reason": "TOO_LONG" } ] }
}
```

<!-- No side effects: the request is refused before any write. -->

## Notes
- The JCS form of the 5,000-character string is 5,002 bytes (with its quotes), over 4096. A boundary test should size the value on the JCS form, not the raw string (G-CRT-16).
- A type may declare a larger `maxLength` for the field; the per-request limit still applies (G-CRT-16).
