# The dedup scope decides who shares an identity: `tenant` across subjects, `subject` per subject, never across tenants

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-derived-dedup` (PRD.md:301, :304, :312) · PRD.md:1493 · DESIGN.md:1713 · DESIGN.md:2378 · DESIGN.md:2562-2563 · DESIGN.md:2565 · DESIGN.md:2566 · ADR-0012:73 |
| Phase | p2 |
| Test level | E2E |

`scope: tenant` leaves the subject out of the identity, so independent producers in one tenant share one task; the registrant opted in and accepts that callers in the tenant learn an identical task exists (PRD.md:312). `scope: subject` (the default) puts the creating subject into the identity (`scope_c = ctx.subject_id`, DESIGN.md:2563): two subjects with equal input get two tasks, and neither learns that the other's exists. The owner tenant is always part of the identity hash and of the `te_dedup` primary key (DESIGN.md:2566, :1713), so tenant B with input equal to tenant A's gets its own task and no hint of A's, under either scope.

## Setup
- **metric_job** (`gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~`): `dedup { key_fields: ["/graph_id", "/metric"], scope: tenant, window: active }`, `supersede { order_field: "/revision", mode: graceful }`; no `default_queue`. Visible in both tenants (registered by a platform gear).
- **export** as in [1.01](1.01-positive-duplicate-by-derived-identity.md) (`scope: subject`).
- Representative: at `T0`, `{creator_a}` created `{task_1}` with input `{ "graph_id": "g-1", "metric": "pagerank", "revision": 7 }`. It is `queued`. `{creator_a2}` may read `{task_1}` (fixture `read` on the fixture types).

## Request
Representative case: `tenant` scope, second subject.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a2-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 7 } }
```

## Expected response
- `409 Conflict`, `already_exists`, `context.resource_name` = `{task_1}` (equal order value = ordinary dedup, PRD.md:329).
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.already_exists.v1~",
  "title": "Already Exists",
  "status": 409,
  "detail": "A task with the same identity already exists",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}" }
}
```

## Side effects
- Representative: no new task; task {task_1} unchanged (`created_by` still `{creator_a}`).

## Notes
- When the holder under `tenant` scope is a task the caller may not read, the answer is `403` with no ID: [dedup hit on unreadable task](1.05-guardrail-dedup-hit-on-unreadable-task-403.md).
