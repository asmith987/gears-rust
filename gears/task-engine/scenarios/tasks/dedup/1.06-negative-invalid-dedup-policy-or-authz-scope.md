# A type with an invalid `dedup` policy cannot be created; an `authz_scope` type cannot be registered

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-derived-dedup` (PRD.md:300, :301, :310) · DESIGN.md:715-716 · DESIGN.md:1228 · DESIGN.md:2378 (2) · DESIGN.md:2564 · ADR-0012:65 · ADR-0012:67 · task-type schema `dedup.key_fields`, `dedup.scope` |
| Phase | p2 |
| Test level | E2E |
| Depends on | Proposals › Dedup and supersession › Drop `authz_scope` |
| Gaps | G-CRT-07, G-CRT-15, G-SEC-21 |

The engine validates a type's dedup policy the first time it resolves the type, caches the verdict per type revision, and refuses every create of an invalid type (fail closed, DESIGN.md:2378 (2)). The request itself is valid; the type is refused with `400` `INVALID_TYPE_POLICY` on `/type` (G-CRT-15), and the engine never falls back to another scope.

- Each key field must be a required field of the input schema (PRD.md:300); otherwise two tasks that omit it would share an identity built from nothing.
- The `authz_scope` mode is removed from the trait enum: it hashed the caller's right to create the type, not its rights on the data (Proposals › Dedup and supersession). A type that declares it fails registration, so it never reaches the engine; a create naming it gets the unknown-type answer (G-CRT-15).

## Setup
- Task type `gts.cf.core.tasks.task.v1~acme.graph._.loose_job.v1~` (**loose_job**): input `{ "graph_id": string (required), "metric": string (optional) }`, `dedup { key_fields: ["/graph_id", "/metric"], scope: subject }`, registered and visible to `{creator_a}`.
- Task type `gts.cf.core.tasks.task.v1~acme.graph._.scoped_job.v1~` (**scoped_job**): input `{ "graph_id": string (required) }`, `dedup { key_fields: ["/graph_id"], scope: authz_scope }`. Its registration was attempted and refused by the GTS registry (the trait enum has no `authz_scope`), so it is not registered.

## Request
Representative case: key field not required.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.loose_job.v1~", "input": { "graph_id": "g-1", "metric": "pagerank" } }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation `INVALID_TYPE_POLICY` on `/type`; the `description` names the broken rule. Not `500` `internal`, not `201`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Task type gts.cf.core.tasks.task.v1~acme.graph._.loose_job.v1~ cannot be created: invalid dedup policy",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/type", "description": "dedup.key_fields /metric is not a required input field", "reason": "INVALID_TYPE_POLICY" } ] }
}
```

## Notes
- G-CRT-15 settles the `invalid_argument` vs `internal` split on `main` (DESIGN.md:716 vs :1228, :2564): any type the engine finds non-creatable gets `400` `INVALID_TYPE_POLICY` on `/type`. The same answer applies to a `supersede.order_field` that is not a required integer, to `supersede` without `dedup`, to `authority.mode = worker` on a tenant-owned type ([auth/1.08](../../auth/1.08-negative-tenant-owned-worker-authority-type.md)) and to a trait outside the trust limits.
- A new type revision that fixes the policy becomes creatable at once (verdict cached per revision).
- The registration refusal of **scoped_job** happens in the GTS registry, outside the engine; the scenario only checks the engine's answer to a create naming it.
