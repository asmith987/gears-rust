"Cancellation reaches its children" (PRD.md:328): when the replaced task ends `superseded`, its unfinished children with `propagate_cancel` are cancelled through the cascade, inline in the same transaction when there are at most `cascade_inline_limit` (100) of them (DESIGN.md:2972-2980). The cascade applies the supersession's cancel mode to each child; children end `cancelled`, or `forcibly_cancelled` when the mode is forced, never `superseded`, and no actor is recorded (G-CRT-21, G-WAI-23).

## Setup
- **metric_job_excl** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md) (`mode: forced`).
- `{task_1}` (revision 7, **reports**) is `running`, held by `reports-7f9c-1` with `{lt_1}`.
- Its worker created child `{task_3}` (type **render**, **reports**, `parent_task_id = {task_1}`, `parent_lease_token = {lt_1}`, `propagate_cancel: true` by default); `{task_3}` is `queued`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job_excl.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 8 } }
```

## Expected response
- `201 Created` with `{task_2}`.

## Side effects
- task {task_1} state is `cancelled`, result_code `superseded`, superseded_by `{task_2}`.
- task {task_3} state is `cancelled`; task {task_3} result_code is `forcibly_cancelled` (the supersession is forced); task {task_3}.superseded_by is `null`.
- Both transitions commit with the insert of {task_2} (one child, below the inline limit).
- history of {task_3} gains `taskCancelled` with `result_code: "forcibly_cancelled"` and no `actor`.

## Notes
- With a `graceful` supersession type (**metric_job**) an unleased child ends `cancelled` / `cancelled`, and a leased child gets a cancel request with a `cancel_grace` timer (G-WAI-23). The general cascade is homed in [hierarchy](../../hierarchy/children/).
