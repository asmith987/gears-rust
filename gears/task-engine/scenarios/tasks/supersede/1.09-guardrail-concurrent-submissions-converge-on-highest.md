# Concurrent submissions of one group converge on the highest order value

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-supersede` (PRD.md:328-330) · DESIGN.md:2645-2653 · DESIGN.md:2667 · ADR-0012:74 |
| Phase | p2 |
| Test level | Integration — race |
| Gaps | G-CRT-19, G-CRT-25, G-SEC-22 |

Two retries of one producer submit revisions 8 and 9 at the same moment while revision 7 is queued. Whatever the commit order, the group ends with revision 9 live and every other revision either superseded or refused `STALE_ORDER`; the head guard `latest_order <= O` and the lost-race retry make this hold (DESIGN.md:2652, :2667).

## Setup
- **metric_job** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md). `{task_1}` (revision 7, **reports**) is `queued`.

## Exchange 1 and 2 — sent concurrently
`{creator_a}` sends revision 8 and revision 9 on two connections:
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 8 } }
```
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 9 } }
```

## Expected response
- Revision 9: `201 Created` with `{task_9}`.
- Revision 8: either `201 Created` with `{task_8}` (it committed first) or `400` `failed_precondition` with violation `{ type: STATE, subject: STALE_ORDER }` and no task named (9 committed first, G-CRT-25). `409` `aborted` `STATE_CHANGED` only after 3 attempts (G-CRT-19), which two submissions should not cause.

## Side effects
- Exactly one unfinished task in the group: {task_9}.
- `te_supersede_heads(tenant_a, group)` has `latest_order = 9`, `latest_task_id = {task_9}`.
- task {task_1} result_code is `superseded`, with `superseded_by` = {task_8} or {task_9}; if {task_8} was created, its result_code is `superseded` with `superseded_by = {task_9}`.

## Notes
- One subject sends both; cross-subject supersession is [1.10](1.10-positive-cross-subject-supersession-under-tenant-scope.md).
