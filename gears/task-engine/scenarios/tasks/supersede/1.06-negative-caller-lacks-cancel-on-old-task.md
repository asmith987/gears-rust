# Without `cancel` on the task it would replace, the whole create is refused

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-supersede` (PRD.md:335) · PRD.md:1494 · DESIGN.md:720 · DESIGN.md:1231 · DESIGN.md:2601 · ADR-0012:66 |
| Phase | p2 |
| Test level | Integration — cancel grant |
| Depends on | Proposals › Dedup and supersession › No PDP call inside the create transaction |
| Gaps | G-CRT-08, G-SEC-19, G-WIRE-15 |

Supersession cancels someone's task, so the caller needs `create` **and** `cancel` on the replaced task; otherwise the request is rejected `403` and nothing changes (PRD.md:335). The caller may read the old task, so `403` is the right answer, not `404`.

## Setup
- **metric_job** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md).
- PDP policy for this scenario: `{creator_a2}` may `create` and `read` **metric_job**, but may `cancel` only tasks with `created_by = {creator_a2}`.
- `{task_1}` (revision 7, **reports**, `created_by = {creator_a}`) is `queued`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a2-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 8 } }
```

## Expected response
- `403 Forbidden`, `permission_denied`, `context.reason: SUPERSEDE_CANCEL_DENIED` (G-CRT-08, G-SEC-19); no field violation, and the old task's ID is not in the body.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "Not allowed to cancel the task this submission would supersede",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "reason": "SUPERSEDE_CANCEL_DENIED" }
}
```

## Notes
- The case is reachable across subjects under `tenant` scope ([1.10](1.10-positive-cross-subject-supersession-under-tenant-scope.md)); the same refusal applies to a same-subject caller whose `cancel` is denied by policy. `SUPERSEDE_CANCEL_DENIED` tells it apart from a `create` denial (`ACTION_DENIED`) (G-CRT-08).
