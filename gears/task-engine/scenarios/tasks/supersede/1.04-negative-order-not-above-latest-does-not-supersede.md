# An order value not above the group's latest never supersedes: lower is `STALE_ORDER`, equal is a replay

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-supersede` (PRD.md:329, :330) · PRD.md:1494 · DESIGN.md:1230 · DESIGN.md:1735-1747 · DESIGN.md:2569-2570 · DESIGN.md:2599 · DESIGN.md:2603 · ADR-0012:74 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-CRT-25, G-WIRE-14 |

An old revision can never replace a newer outcome. The group's latest order value is kept in `te_supersede_heads` until the retention of its latest task ends, and is not touched by `finalize()` (DESIGN.md:2948), so a late request for a lower revision is stale even after the newer task completed and released its identity. An equal order value is part of the dedup key (DESIGN.md:2570), so the same revision hits the identity row and answers `409` before any supersession logic runs: a slow retry of the current revision never cancels the task it created.

## Setup
- **metric_job** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md).
- Representative: `{task_2}` (revision 8) superseded `{task_1}` (revision 7) and then completed with `success` at `T0+5m`. Its `active` identity is released; `te_supersede_heads` still has `latest_order = 8`, `latest_task_id = {task_2}`. Clock at `T0+1h`.

## Request
Representative case: lower revision after the newer task finished.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 7 } }
```

## Expected response
- `400 Bad Request`, `failed_precondition`, violation `{ type: STATE, subject: STALE_ORDER }`; no `context.reason` (G-WIRE-14) and no `resource_name`: the answer names no task (G-CRT-25).
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 400,
  "detail": "A newer revision of this work has already been submitted",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~",
    "violations": [ { "type": "STATE", "subject": "STALE_ORDER", "description": "the order value is lower than the latest accepted for this work" } ] }
}
```

## Notes
- **lower**: the answer names neither {task_2} nor the latest order value (G-CRT-25). Revision 8 again would create a new task (equal value, identity released).
- **equal**: `resource_type` is the task base type (G-CRT-25).
- **equal**: after the holder ended (window `active`), the same revision creates a new task: [dedup window](../dedup/1.02-positive-window-release-and-reuse.md).
