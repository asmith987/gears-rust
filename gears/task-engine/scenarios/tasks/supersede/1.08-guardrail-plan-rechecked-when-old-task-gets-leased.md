# Supersession is authorized before the transaction and re-planned if the old task changed

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-supersede` (PRD.md:328, :335) · DESIGN.md:2601 · DESIGN.md:2640-2643 · DESIGN.md:2667 |
| Phase | p2 |
| Test level | Integration — race |
| Depends on | Proposals › Dedup and supersession › No PDP call inside the create transaction |
| Gaps | G-CRT-19, G-CRT-17, G-SEC-22 |

The accepted proposal moves the `cancel` check out of the create transaction: authorize before `BEGIN`, re-check the plan inside, and retry from the top if it changed. The plan changed when the old task's state or the group's `latest_task_id` differs from what was planned; `cancel` is re-authorized, outside the transaction, only when the target old task changed; after 3 attempts the create answers `409` `aborted` `STATE_CHANGED` with no `Retry-After` (G-CRT-19). The observable rule: if the old task is claimed between the plan and the write, the result follows the task's **new** state (graceful cancel request), never the stale plan (immediate cancel of a now-leased task), and never a half-applied change.

## Setup
- **metric_job** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md). `{task_1}` (revision 7, **reports**) is `queued`.
- Test hook: the engine pauses the create of revision 8 after its `cancel` authorization and before `BEGIN`; meanwhile `reports-7f9c-1` claims `{task_1}` (lease `{lt_1}`); then the create resumes.
- The PDP test double records every call and whether a database transaction was open on that request at the time.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 8 } }
```

## Expected response
- `201 Created` with `{task_2}`.

## Side effects
- task {task_1} state is `claimed`; task {task_1}.cancel_requested is `true`; task {task_1}.superseded_by is `{task_2}`; timer `cancel_grace` for {task_1} is armed at resume time + 60 s.
- task {task_1} lease_epoch is unchanged and lease {lt_1} stays valid until the worker acknowledges.
- The PDP double recorded no call made while the create's transaction was open, and exactly one `cancel` call: the target did not change, so the retry did not re-authorize (G-CRT-19).
- history of {task_1} gains `taskCancelRequested` with `mode: "graceful"`, `superseded_by: "{task_2}"` (G-CRT-17).
