# Graceful supersession of a running task: cancel request, then `superseded` when the worker stops

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-supersede` (PRD.md:328, :336) · DESIGN.md:535 · DESIGN.md:552 · DESIGN.md:1510 · DESIGN.md:2378 (5) · DESIGN.md:2155 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-CRT-17, G-CRT-18, G-WIRE-06, G-SEC-11 |

In `graceful` mode a leased task is not killed: it gets `cancel_requested`, `superseded_by` and a `cancel_grace` timer (60 s), and the worker learns of it on its next heartbeat (PRD.md:336). When the worker stops and reports `cancelled`, the task still ends `superseded` (PRD.md:328, DESIGN.md:1510). Old and new task may overlap meanwhile.

## Setup
- **metric_job** as in [1.01](1.01-positive-higher-order-supersedes-by-old-task-state.md).
- `{task_1}` (revision 7, **reports**) is `running`, held by `{worker_a}` / `reports-7f9c-1` in session `{session_1}` with lease token `{lt_1}`. Clock at `T0`.

## Exchange 1 — newer revision
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "type": "gts.cf.core.tasks.task.v1~acme.graph._.metric_job.v1~", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "input": { "graph_id": "g-1", "metric": "pagerank", "revision": 8 } }
```
- `201 Created` with `{task_2}`, `state: queued`.
- task {task_1} state is still `running`; task {task_1}.cancel_requested is `true`; task {task_1}.superseded_by is `{task_2}`; task {task_1}.cancel_request has `mode: graceful`, `superseded_by: {task_2}`.
- timer `cancel_grace` for {task_1} is armed at `T0+60s`.
- history of {task_1} gains `taskCancelRequested` with `mode: "graceful"`, `superseded_by: "{task_2}"`, `actor: "{creator_a}"` (G-CRT-17, G-SEC-11).

## Exchange 2 — the worker's heartbeat sees the request
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```
- `200 OK`; `results[0]` is `{ "task_id": "{task_1}", "outcome": "ok", "state": "running", "cancel_requested": true, "cancel_request": { "mode": "graceful", "requested_by": "{creator_a}", "requested_at": "2026-11-03T10:00:00Z", "reason": null, "grace_until": "2026-11-03T10:01:00Z", "superseded_by": "{task_2}" } }`. The worker learns from `superseded_by` that the cancel is a supersession (G-CRT-17, G-WIRE-06).

## Exchange 3 — the worker stops and reports `cancelled`
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "cancelled" }
```
- `200 OK`, task resource with `state: cancelled`, `result.result_code: superseded`, `superseded_by: {task_2}`.

## Side effects
- After Exchange 3: task {task_1} result_code is `superseded`; timer `cancel_grace` for {task_1} is removed.
- `queue_global(reports) used changes by -1`; `queue_tenant(reports, tenant_a) used changes by -1` (slots held until the worker stopped, DESIGN.md:2667).
- history of {task_1} gains `taskCancelled` with `result_code: "superseded"`, `superseded_by: "{task_2}"`.

## Notes
- G-CRT-17: a graceful supersession of a leased task records `taskCancelRequested { mode: graceful, superseded_by }` at once and `taskCancelled { superseded_by }` when it ends; the `task_cancel_requested` schema gains the optional `superseded_by`.
- Other worker reports in the grace window (`success`, `error`) and grace expiry: [1.02](1.02-positive-graceful-supersession-endings.md) (G-CRT-18).
