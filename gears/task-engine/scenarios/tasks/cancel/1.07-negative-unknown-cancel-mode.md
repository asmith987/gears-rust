# A cancel with an unknown mode is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:346-350) · `cpt-cf-task-engine-fr-state-result-enums` (PRD.md:1044) |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-RTY-18, G-SEC-21 |

Only `requested`, `graceful` and `forced` exist (PRD.md:346-350). Another value is a bad request; the task is untouched.

## Setup
- `{task_1}`: **render** on **reports**, `running` under `{lt_1}`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "mode": "immediate" }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/mode` with reason `INVALID_ENUM_VALUE` (CONVENTIONS §6).

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "mode must be requested, graceful or forced",
  "instance": "/api/task_engine/v1/tasks/{task_1}/cancel",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/mode", "description": "one of requested, graceful, forced", "reason": "INVALID_ENUM_VALUE" } ] }
}
```

## Side effects
<!-- No side effects: the request is refused before any write. -->

## Notes
- An omitted `mode` (or no body at all) is not an error: it means `requested` (G-RTY-18, decided in the wire review). On this running task that is `202` with `cancel_request.mode = requested`, as in [1.02](1.02-positive-cancel-of-leased-task-by-mode.md).
