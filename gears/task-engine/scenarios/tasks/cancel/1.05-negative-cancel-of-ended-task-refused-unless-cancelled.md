# A cancel of an ended task is refused, unless the task already ended cancelled

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:344) · `cpt-cf-task-engine-fr-state-result-enums` (PRD.md:1028) · DESIGN.md:515, :1234 · ADR-0002:74 |
| Phase | p1 (dependency-failed case p2) |
| Test level | E2E |
| Gaps | G-RTY-13, G-WIRE-14 |

A terminal task never changes state again except by re-enqueue (PRD.md:1028). A cancel of a task that already ended in the cancelled family (state `cancelled`, with result `cancelled`, `forcibly_cancelled`, `superseded` or `dependency_failed`) is answered `200` with the unchanged task and no event, so a client that retries a cancel whose response was lost gets a success. A cancel of a task that ended any other way (`completed`, `failed`, `dead_lettered`) is `400` `failed_precondition` `TASK_FINISHED` (G-RTY-13). Cancelling a `dead_lettered` task does not remove it from the dead-letter queue.

## Setup
- `{task_1}`: **render** on **reports**, `completed` / `success` at `T0+60s`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "mode": "forced" }
```

## Expected response
- `400 Bad Request`, `failed_precondition`, violation `{ type: STATE, subject: TASK_FINISHED }`, `resource_name` = the task (CONVENTIONS §6).

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 400,
  "detail": "task {task_1} is completed and cannot be cancelled",
  "instance": "/api/task_engine/v1/tasks/{task_1}/cancel",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}",
    "violations": [ { "type": "STATE", "subject": "TASK_FINISHED", "description": "the task has already ended" } ] }
}
```

## Cases

| Case | Starting state (differs from the representative) | Expected | Notes |
|---|---|---|---|
| completed | (representative) `completed` / `success` | `400`, `TASK_FINISHED` | G-RTY-13 |
| failed | `failed` / `error` | `400`, `TASK_FINISHED` | G-RTY-13 |
| dead-lettered | `dead_lettered` / `error` | `400`, `TASK_FINISHED`; the task stays in the dead-letter queue | G-RTY-13 |
| already-cancelled | `cancelled` / `cancelled` (cancelled at `T0+60s` as in [1.01](1.01-positive-cancel-of-unleased-task-ends-at-once.md)) | `200`, the unchanged task (`state: cancelled`, `result.result_code: cancelled`, same `terminal_at`); no event | G-RTY-13 |
| already-forced | `cancelled` / `forcibly_cancelled` | `200`, unchanged; no event | G-RTY-13 |
| superseded | `cancelled` / `superseded` | `200`, unchanged; no event | G-RTY-13 |
| dependency-failed | `cancelled` / `dependency_failed` (p2: predecessors) | `200`, unchanged; no event | G-RTY-13 |

Response for **already-cancelled**:
```json
{ "id": "{task_1}", "state": "cancelled",
  "result": { "result_code": "cancelled", "output": null, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:01:00Z", "…": "other fields as in CONVENTIONS §5.1" }
```

## Notes
- The request's `mode` does not matter: a `forced` cancel of a task that ended `cancelled` is still `200` with the task unchanged (its result stays `cancelled`).
