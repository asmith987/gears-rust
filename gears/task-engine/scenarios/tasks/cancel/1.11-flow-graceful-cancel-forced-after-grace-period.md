# A graceful cancel the worker does not finish in time becomes forcibly_cancelled

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:349) · DESIGN.md:551, :2155, :2739 · ADR-0003:32 |
| Phase | p1 |
| Test level | Both — grace expiry |
| Gaps | G-RTY-19 |

`graceful` is `requested` with a deadline. It sets `cancel_requested` and arms a `cancel_grace` timer at `now + cancel_grace_period_secs` (60 s, DESIGN.md:2155). If the worker has not ended the task when the timer fires, the engine applies the forced-cancel row: `cancelled` / `forcibly_cancelled` (DESIGN.md:551, :2739).

## Setup
- `{task_1}`: **render** on **reports**, `running` under `{lt_1}` in `{session_1}`; the handler ignores cancel requests; the process keeps heartbeating.

## Exchange 1 — graceful cancel
At `T0+100s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "mode": "graceful", "reason": "maintenance window" }
```
- `202 Accepted`, `state: running`, `cancel_requested: true`, `cancel_request.grace_until: T0+160s`; timer `cancel_grace` for `{task_1}` is armed at `T0+160s`.

## Exchange 2 — the grace timer fires (no request)
At `T0+160s` the timer wheel runs `finalize(forcibly_cancelled)` (DESIGN.md:2739), unless the worker acknowledged first (G-OPS-38).

## Exchange 3 — the worker's next heartbeat
At `T0+165s`:
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```

## Expected response
- `200 OK`, `results: [ { "task_id": "{task_1}", "outcome": "lease_lost" } ]`.
- `GET /tasks/{task_1}` shows `state: cancelled`, `result.result_code: forcibly_cancelled`, `terminal_at` in `[T0+160s, T0+161s]`.

## Side effects
- lease `{lt_1}` is invalid (later calls get LEASE_LOST); the token is cleared (DESIGN.md:577).
- `queue_global(reports)` and `queue_tenant(reports, tenant_a)` concurrency used change by `-1` at `T0+160s`.
- history of `{task_1}` gains `taskCancelRequested` (`mode: graceful`, `actor: {admin}`) at `T0+100s` and `taskCancelled` (`result_code: forcibly_cancelled`, no `actor`) at `T0+160s`.
- If the worker had completed `cancelled` before `T0+160s`, finalize would delete the `cancel_grace` timer and the result would be `cancelled` ([1.10](1.10-flow-worker-acknowledges-cancel-request.md)).

## Notes
- The grace period is the engine-wide `cancel_grace_period_secs` in p1; no per-queue, per-type or per-request value (G-RTY-19). PRD.md:349 "configurable" means this setting.
