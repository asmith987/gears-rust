# A worker may not report cancelled when no cancel was requested

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-state-result-enums` (PRD.md:1039) · DESIGN.md:737, :1211 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-SEC-21, G-EXE-17 |

A worker may send `cancelled` only after a cancel request (PRD.md:1039); otherwise a worker could end tasks as cancelled on its own. The result is rejected `400`; the task stays `running` and the lease stays valid (DESIGN.md:737).

## Setup
- `{task_1}`: **render** on **reports**, `running` under `{lt_1}`, `cancel_requested: false`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "cancelled" }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/result_code` (the `complete` body is flat, G-EXE-15) with reason `NOT_ALLOWED`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "result_code cancelled is allowed only after a cancel request",
  "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/result_code", "description": "no cancel was requested for this task", "reason": "NOT_ALLOWED" } ] }
}
```

## Side effects
<!-- No side effects: the task stays running; lease {lt_1} stays valid and the worker can send another result. -->

## Notes
- `NOT_ALLOWED` is in the decided reason list (CONVENTIONS §6, G-CRT-07). A zombie worker whose lease is gone gets `409` `LEASE_LOST` instead of this `400` (G-EXE-17).
