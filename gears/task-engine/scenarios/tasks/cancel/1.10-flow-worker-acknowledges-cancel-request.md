# The worker sees the cancel request on its heartbeat and ends the task cancelled

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:348) · `cpt-cf-task-engine-fr-state-result-enums` (PRD.md:1039) · DESIGN.md:535, :737, :1306-1307 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-OPS-38, G-RTY-21, G-WIRE-06 |

The cooperative path: the heartbeat carries `cancel_requested: true`; the worker stops, cleans up, and completes with `result_code: cancelled`, which a worker may send only after a cancel request (PRD.md:1039).

## Setup
- Run [1.02](1.02-positive-cancel-of-leased-task-by-mode.md): `{task_1}` is `running` with `cancel_requested: true`, lease `{lt_1}`.

## Exchange 1 — heartbeat
At `T0+105s`:
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```
- `200 OK`:
```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "results": [ { "task_id": "{task_1}", "outcome": "ok", "state": "running", "cancel_requested": true,
                 "cancel_request": { "mode": "requested", "requested_by": "{creator_a}", "requested_at": "2026-11-03T10:01:40Z",
                                     "reason": null, "grace_until": null, "superseded_by": null } } ] }
```

## Exchange 2 — the worker completes cancelled
At `T0+107s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "cancelled" }
```

## Expected response
- `200 OK`, `state: cancelled`, `result.result_code: cancelled`.

```json
{ "id": "{task_1}", "state": "cancelled", "cancel_requested": true,
  "result": { "result_code": "cancelled", "output": null, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:01:47Z", "…": "other fields as in CONVENTIONS §5.1" }
```

## Side effects
- task `{task_1}` state is `cancelled`; result_code is `cancelled`.
- `queue_global(reports)` and `queue_tenant(reports, tenant_a)` concurrency used change by `-1`.
- `lease_token` is kept on the result row, so repeating exchange 2 returns `200` with the stored outcome (DESIGN.md:576, :736).
- history of `{task_1}` gains `taskCancelled` (`result_code: cancelled`, `actor: {worker_a}`); it is published.
- After a `graceful` cancel the same acknowledgement also deletes the `cancel_grace` timer (G-OPS-38).

## Notes
- The acknowledgement is `complete` with `result_code: cancelled` (G-OPS-38); it is allowed from `claimed` too, without `start` (G-RTY-21, G-EXE-11). Other result codes after a cancel request: [1.04](1.04-positive-worker-finishes-normally-after-cancel-request.md).
