# A graceful cancel after a requested one arms the grace timer once

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-cancel` (PRD.md:348-349) · DESIGN.md:551 |
| Phase | p1 |
| Test level | Both — grace timer |
| Gaps | G-RTY-16 |

An operator who asked politely and got no reaction may escalate. Cancel modes on a flagged task only move forward (G-RTY-16): `requested` → `graceful` arms the `cancel_grace` timer and records `taskCancelRequested`; a repeat of `graceful`, or `requested` after `graceful`, is a no-op `202` that keeps the first deadline and records nothing.

## Setup
- `{task_1}`: **render** on **reports**, `running` under `{lt_1}`. At `T0+100s` a `requested` cancel was accepted ([1.02](1.02-positive-cancel-of-leased-task-by-mode.md)); the worker ignores it.

## Exchange 1 — escalate to graceful
At `T0+120s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "mode": "graceful" }
```
- `202 Accepted`, `state: running`, `cancel_requested: true`, `cancel_request.mode: graceful`, `cancel_request.grace_until: T0+180s`; timer `cancel_grace` for `{task_1}` is armed at `T0+180s`; history gains `taskCancelRequested` (`mode: graceful`, `actor: {admin}`).

## Exchange 2 — graceful again
At `T0+150s`, the same request.

## Expected response
- `202 Accepted`, unchanged task; timer `cancel_grace` stays at `T0+180s`; no event.
- The same holds for `{ "mode": "requested" }` at this point: `202`, no change, no event.

## Side effects
- At `T0+180s` the task ends `cancelled` / `forcibly_cancelled` as in [1.11](1.11-flow-graceful-cancel-forced-after-grace-period.md).
- history of `{task_1}` holds two `taskCancelRequested` events (`requested` at `T0+100s`, `graceful` at `T0+120s`); the no-op repeat adds none.
- A `forced` cancel at any point ends the task at once ([1.02, forced](1.02-positive-cancel-of-leased-task-by-mode.md)).

## Notes
- Modes only move forward and a no-op repeat records no event (G-RTY-16), so repeated calls cannot postpone the forced stop.
