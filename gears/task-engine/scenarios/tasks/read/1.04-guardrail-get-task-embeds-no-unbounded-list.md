# GET /tasks/{id} embeds no list that can grow without limit

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-rest-api` (PRD.md:1068) · DESIGN.md:1063, :2078, :2128 |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › API reads and responses › Bounded responses |
| Gaps | G-CRT-06 |

The task resource carries only lists with a configured bound: `predecessors` (at most `max_predecessors_per_task`, 64), `resource_refs` (at most `max_resource_refs_per_task`, 16) and `tags` (at most `max_tags_per_task`, 16, G-CRT-06). History, entries, children and wait conditions are read from their own endpoints.

## Setup
- `{task_1}` (**render**, tenant A) has 1,200 history events, 300 entries and 500 children.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200`; the body has the fields of CONVENTIONS §5.1 only. No `events`, `entries`, `children` or `wait_conditions` member; `predecessors`, `resource_refs` and `tags` are within their limits.
- Response size does not grow with history, entries or children.
