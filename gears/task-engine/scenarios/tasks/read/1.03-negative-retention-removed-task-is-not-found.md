# A task removed by retention answers 404, like one that never existed

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retention` (PRD.md:1089-1099) · DESIGN.md:1199 |
| Phase | p1 |
| Test level | Integration — retention |

Retention removes a finished task with its entries and history once its retention has passed, counted from `terminal_at`. Afterwards nothing about the task can be read.

## Setup
- `{task_7}` (**render**, tenant A) completed at `T0-101d`; global retention 100 days; the retention pass for its slot has run.

## Request
```http
GET /api/task_engine/v1/tasks/{task_7} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `404 Not Found`, the `not_found` body of [ERRORS.md](../../ERRORS.md) (as in [no existence oracle](../../auth/1.10-guardrail-no-existence-oracle.md)) with `resource_name = {task_7}`.
- `GET /tasks/{task_7}/events` and `/entries` → `404`.

<!-- No side effects: reads only. -->

## Notes
- The response is the same as for a never-used ID; there is no `410 Gone`. A task kept by a longer per-tenant or per-type policy, or rescued into `_retained` tables, stays readable (DESIGN.md:1441).
- Retention runs in slot passes (DESIGN.md:852-859), so a task can stay readable for a while after its retention passes; a test asserts `404` only after the pass.
