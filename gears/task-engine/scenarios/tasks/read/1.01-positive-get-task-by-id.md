# Get a task by ID returns the full task resource and never a lease token

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-rest-api` (PRD.md:1068) · `cpt-cf-task-engine-fr-authz` (PRD.md:918) · DESIGN.md:1015, :1063, :1081, :2354 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-WIRE-19, G-CRT-09, G-EXE-10 |

`GET /tasks/{id}` needs only `read`. It returns the task resource of CONVENTIONS §5.1. A running task shows who holds it (`assignment`) but not the lease token: tokens appear only in claim and accept responses.

## Setup
- `{task_1}` (**render**, tenant A) is `running`, claimed by `{worker_a}` (`reports-7f9c-1`) at `T0+5s` with `{lt_1}`, epoch 1.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <readonly-a-token>
```

## Expected response
- `200 OK`, the task resource.
- No member anywhere in the body is named `lease_token` or contains `{lt_1}`; the body carries no `Idempotency-Key` either (G-CRT-09).
- `assignment.execution_deadline` is the claim time plus the execution timeout of **reports** (900 s), set by the claim (G-EXE-10, G-WIRE-19).
```json
{
  "id": "{task_1}",
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "owner_tenant_id": "{tenant_a}",
  "created_by": "{creator_a}",
  "state": "running",
  "attempt": 1,
  "input": { "report_id": "r-42", "format": "pdf" },
  "assignment": { "assignee_subject": "{worker_a}", "worker_id": "reports-7f9c-1", "claimed_at": "2026-11-03T10:00:05Z", "attempt": 1, "lease_epoch": 1, "execution_deadline": "2026-11-03T10:15:05Z" },
  "terminal_at": null,
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Notes
- A worker reading the task it holds gets the same body; the token is never echoed back.
