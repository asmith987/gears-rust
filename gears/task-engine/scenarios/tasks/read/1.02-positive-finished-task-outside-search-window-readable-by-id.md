# A finished task outside the search window is still readable by ID

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-search` (PRD.md:1143) · DESIGN.md:1161 |
| Phase | p1 |
| Test level | Integration — needs a task older than the window |
| Depends on | Proposals › API reads and responses › Search window stays as designed |

Search for finished tasks covers at most 31 days of creation time (7 by default). Reads by ID are not windowed: every stored task, and its history, stays readable until retention removes it.

## Setup
- Now is `T0`. `{task_6}` (**render**, tenant A) was created at `T0-40d` (2026-09-24T10:00:00Z) and completed (`success`) at `T0-40d+1m`. The task's retention is the 100-day global default.

## Exchange 1 — read by ID
```http
GET /api/task_engine/v1/tasks/{task_6} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200`; `state: "completed"`, `result.result_code: "success"`, `created_at: "2026-09-24T10:00:00Z"`, `terminal_at: "2026-09-24T10:01:00Z"`.
- `GET /tasks/{task_6}/events` → `200`, the complete history.

## Exchange 2 — default search does not find it
```http
GET /api/task_engine/v1/tasks?$filter=state eq 'completed'&view=tiny HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200`; `{task_6}` is not among the items (the engine added `created_at ge T0-7d`).
- `$filter=created_at ge 2026-09-20T00:00:00Z and created_at lt 2026-10-20T00:00:00Z and state eq 'completed'` (30 days) finds it.
