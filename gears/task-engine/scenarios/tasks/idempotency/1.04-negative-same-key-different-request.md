# The same key with a different request is rejected on `Idempotency-Key`

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-idempotent-create` (PRD.md:282) · DESIGN.md:718 · DESIGN.md:1204 · DESIGN.md:1716 · DESIGN.md:2575 · DESIGN.md:2592-2593 · ADR-0012:55 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-07, G-CRT-09, G-CRT-11, G-SEC-21 |

If type, input or context differ from the request the key was first accepted with, the key is being reused for other work. The engine refuses with `400` `invalid_argument`, `KEY_REUSED` on `Idempotency-Key`. The answer names no task: the key is the caller's own, so nothing is disclosed (DESIGN.md:2593). The queue is not in the fingerprint hash: the key row stores the queue resolved at create, and a retry that names no queue or that queue matches; a retry that names another queue is a different request (G-CRT-11).

## Setup
- Representative: [Minimal create](../create/1.01-positive-minimal-create-queued.md) at `T0` created `{task_1}` with key `7d1f0c2e-render-r-42` and input `{ "report_id": "r-42", "format": "pdf" }`.
- For the **queue** cases: at `T0`, `{creator_a}` created `{task_1}` of **render** with key `7d1f0c2e-render-r-64`, input `{ "report_id": "r-64", "format": "pdf" }` and **no** `queue`; the resolved queue, stored on the key row, is **default**.

## Request
Representative case: different input.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-r-42

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "priority": 100,
  "input": { "report_id": "r-42", "format": "csv" },
  "tags": [{ "key": "project", "value": "q4" }]
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation `KEY_REUSED` on `Idempotency-Key` (the header, named as sent, G-SEC-21); no `resource_name`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Idempotency-Key was already used with a different request",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "Idempotency-Key", "description": "key was first used with a different type, queue, input or context", "reason": "KEY_REUSED" } ] }
}
```

## Side effects
- No new task; task {task_1} is unchanged.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| different input | `input.format: "csv"` (the representative) | `400` `KEY_REUSED` on `Idempotency-Key` | DESIGN.md:1204, :2592-2593 |
| retry names another queue | **queue** setup; key `7d1f0c2e-render-r-64`, `queue: "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"` (**reports**), input `{ "report_id": "r-64", "format": "pdf" }`, no `priority`, no `tags` | `400` `KEY_REUSED` on `Idempotency-Key`, same body | G-CRT-11 |
| retry names the resolved queue | **queue** setup; the retry names `queue: "gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1"` | `409` `already_exists` naming {task_1} (a replay, [replay returns 409](1.01-positive-replay-returns-409-with-existing-id.md)) | control row; G-CRT-11 |
| retry omits a queue the first request named | representative setup (first request named **reports**); the retry is the original request without `queue` | `409` `already_exists` naming {task_1} | control row; G-CRT-11 |
| retry as first sent | **queue** setup; the retry again omits `queue` | `409` `already_exists` naming {task_1} | control row |

## Notes
- `KEY_REUSED` is in the decided reason set (G-CRT-07). Key-order and whitespace differences in the JSON are not differences: the fingerprint is over JCS (DESIGN.md:2575).
- PRD.md:282 "differs in … queue" is read against the resolved queue: absent or equal matches (G-CRT-11). DESIGN.md:1716 and :2575 drop `queue` from the hash.
