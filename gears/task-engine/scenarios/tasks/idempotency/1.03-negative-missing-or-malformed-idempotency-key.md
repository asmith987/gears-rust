# A create without a valid `Idempotency-Key` is rejected: 428 when missing, 400 when empty or malformed

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-idempotent-create` (PRD.md:278) · DESIGN.md:718 · DESIGN.md:1205 · DESIGN.md:2573 · ADR-0012:55 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-07, G-CRT-09, G-CRT-24, G-SEC-21 |

For a type without a derived dedup identity the key is required, because a forgotten key is the usual cause of duplicate work (PRD.md:287). A missing key is refused with `invalid_argument` and the transport override `428 Precondition Required`. A key that is present must be 1–255 printable ASCII characters without spaces (`!`–`~`), case-sensitive; an empty or malformed key is `400` `INVALID_FORMAT` (G-CRT-09). The header is named as sent, `Idempotency-Key` (G-SEC-21). The key is never returned on the task resource.

## Setup
- **render** declares no `dedup` trait.

## Request
Representative case: no header.
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42", "format": "pdf" }
}
```

## Expected response
- `428 Precondition Required`, `invalid_argument`, field violation `REQUIRED` on `Idempotency-Key`.
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 428,
  "detail": "Idempotency-Key header is required for this task type",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
    "field_violations": [ { "field": "Idempotency-Key", "description": "header is required", "reason": "REQUIRED" } ] }
}
```

<!-- No side effects in any case: the request is refused before any write. -->

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| missing | no header (the representative) | `428`, `REQUIRED` on `Idempotency-Key` | PRD.md:278, DESIGN.md:1205 |
| empty | `Idempotency-Key:` with an empty value | `400 Bad Request`, `invalid_argument`, `{ "field": "Idempotency-Key", "description": "1-255 printable ASCII characters without spaces", "reason": "INVALID_FORMAT" }` | G-CRT-09 |
| contains a space | `Idempotency-Key: render r-42` | `400`, `INVALID_FORMAT` on `Idempotency-Key` | G-CRT-09 |
| non-ASCII | `Idempotency-Key: render-ü-42` | `400`, `INVALID_FORMAT` on `Idempotency-Key` | G-CRT-09 |
| too long | a key of 256 characters | `400`, `INVALID_FORMAT` on `Idempotency-Key` | G-CRT-09; 255 characters is accepted |
| malformed, dedup type | p2. **export** (a type with a derived identity, CONVENTIONS fixtures), `Idempotency-Key: k 1` | `400`, `INVALID_FORMAT` on `Idempotency-Key`; no task created | G-CRT-24: a sent key is always validated, also for a type with a derived identity |
| missing, unknown type | no header, `type: "gts.cf.core.tasks.task.v1~acme.reports._.nosuch.v1~"` | `400`, `UNKNOWN_TASK_TYPE` on `/type`, not `428` | G-CRT-24: the type is checked first |
| missing, invalid input | no header, `input: { "format": "pdf" }` | `428`, not `400` `SCHEMA_VIOLATION` | G-CRT-24: the key check comes before schema validation |

## Notes
- Check order (G-CRT-24): the `428` comes after the type, queue, PDP and `expedite` checks, so a caller without `create` gets `403` `ACTION_DENIED` and learns nothing about the type's key rule; it comes before the trust-limit, schema and payload checks.
- Keys differing only in case are different keys (G-CRT-09).
- For a `dedup` type a sent key is ignored ([dedup/1.03](../dedup/1.03-guardrail-sent-key-is-ignored.md)); a sent key is still validated, so a malformed one is refused (G-CRT-24, case `malformed, dedup type`).
