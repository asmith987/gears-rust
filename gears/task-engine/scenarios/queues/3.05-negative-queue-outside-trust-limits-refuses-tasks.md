# A queue registered outside the trust limits refuses new tasks, naming the setting

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-type-trust` (PRD.md:1010) · PRD.md:1533 · DESIGN.md:1047, :1213, :2191-2192 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-05, G-CRT-07, G-SEC-21, G-OPS-11 |

Queues are registered by other gears and are untrusted input. A queue whose lease is below `trust_limits.min_lease_secs` (10 s) stays registered, but every create into it is rejected and the error names the setting.

## Setup
- Queue `gts.cf.core.tasks.queue.v1~acme.reports._.fast.v1` (**fast**) is registered like **reports** but with `timeouts.heartbeat_timeout_secs: 5`.
- `trust_limits.min_lease_secs: 10` (DESIGN.md:2192).

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 7d1f0c2e-render-fast-1

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.fast.v1",
  "input": { "report_id": "r-50", "format": "pdf" }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`; one field violation on `/queue` (JSON Pointer, G-SEC-21) with reason `TRUST_LIMIT` (G-CRT-07); its `description` names the queue setting and the limit, not the value.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "Queue gts.cf.core.tasks.queue.v1~acme.reports._.fast.v1 is outside the engine trust limits",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/queue", "description": "queue setting timeouts.heartbeat_timeout_secs is below trust_limits.min_lease_secs", "reason": "TRUST_LIMIT" } ] }
}
```

## Notes
- `GET /queues` is assumed to still list **fast**; whether it shows that the queue refuses tasks is not said.
- DESIGN.md:1213 says only "field violation names the setting"; `TRUST_LIMIT` is the decided reason (G-CRT-07) and the setting goes into `description`.
- G-CRT-05 clamps an inherited value above a trust cap; it does not cover a queue below the minimum lease. PRD.md:1010 ("a queue outside them refuses new tasks") is followed here.
- A runtime config change that would move a queue outside the trust limits is not covered: G-OPS-11's decision settles only the body semantics. Not asserted here.
