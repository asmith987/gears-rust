# A config override beats the queue registration, which beats the config default

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-queue-depth` (PRD.md:445) · `cpt-cf-task-engine-fr-concurrency-overrides` (PRD.md:473-476) · DESIGN.md:756, :2175-2185, :2212-2215 |
| Phase | p2 (row **runtime beats static** p3) |
| Test level | Integration — config precedence |
| Gaps | G-OPS-12, G-CLM-21, G-OPS-43 |

Effective queue limits come from three levels: a config override, then the queue's registration, then the config default. Among overrides an exact ID beats any pattern, a longer literal prefix (before the first wildcard) beats a shorter one, and for the same pattern a runtime (`/admin/config`) override beats the static one (G-CLM-21, G-OPS-12). `GET /queues` shows the result. One row per queue and setting below.

## Setup
- Static config:
  ```yaml
  queue_depth:
    queue_max_queue_depth: 1000000
    overrides:
      - pattern: "gts.cf.core.tasks.queue.v1~acme.reports.*"
        queue_max_queue_depth: 50000
      - pattern: "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"
        queue_max_queue_depth: 20000
      - pattern: "gts.cf.core.tasks.queue.v1~acme.reports._.b*"
        queue_max_queue_depth: 30000
  concurrency_overrides:
    - pattern: "gts.cf.core.tasks.queue.v1~acme.reports.*"
      global_concurrency_limit: 80
  ```
- **reports** registration: `global_concurrency_limit: 50`, no `queue_max_queue_depth`. **default** registration: no `queue_max_queue_depth`.
- Queue registration for a new queue `gts.cf.core.tasks.queue.v1~acme.media._.thumbs.v1` (**thumbs**): `queue_max_queue_depth: 2000`, `global_concurrency_limit: 20`; no override matches it.

## Request
```http
GET /api/task_engine/v1/queues HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```

## Expected response
- `200 OK`. Effective `limits` per queue as in the Cases table.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| exact ID beats pattern | **reports** item | `queue_max_queue_depth: 20000` (exact-ID override beats the `acme.reports.*` pattern) | G-OPS-12 |
| override beats registration | **reports** item | `global_concurrency_limit: 80` (override beats registration 50) | PRD.md:473-476; G-CLM-21 |
| longest literal prefix wins | **bulk** item | `queue_max_queue_depth: 30000` (`acme.reports._.b*` has a longer literal prefix than `acme.reports.*`), `global_concurrency_limit: 80` | G-CLM-21 |
| registration beats default | **thumbs** item | `queue_max_queue_depth: 2000`, `global_concurrency_limit: 20` (registration; no override matches) | PRD.md:445 |
| runtime beats static (p3) | runtime config version 7 `{ "queues": { "gts.cf.core.tasks.queue.v1~acme.reports.*": { "global_concurrency_limit": 60 } } }` applied in `default` | **bulk** and **reports** items show `global_concurrency_limit: 60`, `config_version: 7` | G-OPS-12 |
| config default | **default** item | `queue_max_queue_depth: 1000000` (config default); `global_concurrency_limit: 0` (registration) | DESIGN.md:756 |

## Notes
- Specificity (G-CLM-21): exact ID, then the longest literal prefix before the first wildcard. Two patterns of equal specificity that match the same queue are rejected when the config is loaded, so such a config never reaches `GET /queues` (no scenario covers the load failure yet).
- Queue and type overrides are different dimensions; both apply (G-CLM-21). This file shows queue overrides only.
- The runtime row needs runtime config (p3); the other rows are p2.
