# An unregistered queue ID returns `404` on every queue endpoint

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-gts-queue` (PRD.md:995) · DESIGN.md:1107, :1199 · Proposals › Queue operations › Admin queue hold |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › Queue operations › Admin queue hold — hold and release cases only |
| Gaps | G-CLM-15, G-OPS-09 |

Every queue is a registered GTS instance (PRD.md:995). An ID that resolves to no queue is not found, whether it is read or held. A mistyped ID on hold must not create a hold record that silently does nothing.

## Setup
- No queue `gts.cf.core.tasks.queue.v1~acme.reports._.nope.v1` is registered.
- `{ops_viewer}` (queue `read` only) as defined in [Queue introspection](1.01-positive-queue-introspection.md); `{admin}` has queue `configure` (fixture).

## Request
```http
GET /api/task_engine/v1/queues/gts.cf.core.tasks.queue.v1~acme.reports._.nope.v1 HTTP/1.1
Host: api.example.com
Authorization: Bearer <ops-viewer-token>
```

## Expected response
- `404 Not Found`, `not_found`, `resource_type` = the queue base type, `resource_name` = the ID sent.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "Queue gts.cf.core.tasks.queue.v1~acme.reports._.nope.v1 not found",
  "instance": "/api/task_engine/v1/queues/gts.cf.core.tasks.queue.v1~acme.reports._.nope.v1",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.queue.v1~", "resource_name": "gts.cf.core.tasks.queue.v1~acme.reports._.nope.v1" }
}
```

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| detail | (representative) `GET /queues/…acme.reports._.nope.v1` as `{ops_viewer}` | `404 not_found` as above | DESIGN.md:1199 |
| hold | `POST /admin/queues/gts.cf.core.tasks.queue.v1~acme.reports._.rendr.v1/hold` as `{admin}`, body `{ "reason": "INC-4711" }` | `404 not_found`, `resource_name` = `gts.cf.core.tasks.queue.v1~acme.reports._.rendr.v1`, `instance` = the hold path; no hold record is created | PRD.md:995 |
| release | `POST /admin/queues/gts.cf.core.tasks.queue.v1~acme.reports._.rendr.v1/release` as `{admin}` | `404 not_found`, same shape; an unknown queue is not "a queue that is not held" (that is `200`, G-OPS-09) | |

## Notes
- DESIGN's error table lists not-found only for tasks, entries and wait conditions (DESIGN.md:1199). A missing queue uses the same category and shape the claim uses for an unregistered queue (G-CLM-15): `resource_type` and `resource_name` only, no field violation (CONVENTIONS §6).
- Hold has no wildcard form; one call holds one queue (Proposals › Queue operations). Holding every queue of a domain takes one call per queue.
