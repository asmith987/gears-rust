# Hold and release edge cases: repeat hold, `until` in the past, release when not held, dead-letter queue

| | |
|---|---|
| Requirement | Proposals › Queue operations › Admin queue hold · `cpt-cf-task-engine-fr-dead-letter` (PRD.md:801) · `cpt-cf-task-engine-fr-gts-queue` (PRD.md:997) · DESIGN.md:2432 |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › Queue operations › Admin queue hold |
| Gaps | G-OPS-04, G-OPS-08, G-OPS-09, G-OPS-10, G-SEC-21 |

The proposal does not say what happens when hold or release is called in an unusual starting state; the gap review decided each (G-OPS-08, G-OPS-09, G-OPS-10). The representative case: an operator extends a maintenance window by holding the queue again with a later `until`. The hold stays in force without a gap: `since` is kept, `reason` and `until` are replaced, `by` names the latest caller, and another `queueHeld` is recorded. Unknown queue IDs are in [Unknown queue](1.02-negative-unknown-queue-not-found.md).

## Setup
- **reports** is held since `T0` by `{admin}` with `until = T0+15m`.
- Clock `T0+10m`.

## Request
```http
POST /api/task_engine/v1/admin/queues/gts.cf.core.tasks.queue.v1~acme.reports._.render.v1/hold HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "reason": "DB maintenance window (extended)", "until": "2026-11-03T10:45:00Z" }
```

## Expected response
- `200 OK`, the queue resource with `hold: { "since": "2026-11-03T10:00:00Z", "by": "{admin}", "reason": "DB maintenance window (extended)", "until": "2026-11-03T10:45:00Z" }`.

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| hold an already held queue | (representative) | `200`, `since` kept, `reason`/`until` replaced, `by` = the caller. Side effects: the hold does not end at `T0+15m`, the queue stays held until `T0+45m`; history of queue **reports** gains another queueHeld `{ queue, actor: "{admin}", reason: "DB maintenance window (extended)", until: "2026-11-03T10:45:00Z" }`, published | G-OPS-09, G-OPS-04 |
| `until` in the past | **reports** not held; `POST …/hold` `{ "reason": "maintenance", "until": "2026-11-03T09:59:00Z" }` at `T0` | `400 invalid_argument`, `field_violations[0] = { field: "/until", reason: "OUT_OF_RANGE", description: "until must be in the future" }`; no hold stored, no event | G-OPS-08; field path G-SEC-21 |
| `until` equal to now | as above with `until: "2026-11-03T10:00:00Z"` at `T0` | same `400`; "not in the future" includes now | G-OPS-08 |
| release a queue that is not held | **reports** not held; `POST /admin/queues/…acme.reports._.render.v1/release` | `200`, the queue resource with `hold: null`; no `queueReleased` recorded | G-OPS-09 |
| hold a dead-letter queue | `POST /admin/queues/gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1/hold` `{ "reason": "stop re-enqueues" }` | `400 failed_precondition`, `violations[0] = { type: "STATE", subject: "DEAD_LETTER_QUEUE" }`, `resource_name` = the dead-letter queue; nothing stored, no event; re-enqueue from the DLQ is unaffected | PRD.md:801, :997; G-OPS-10 |

Full error body for the dead-letter case:

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 400,
  "detail": "A dead_letter queue cannot be held",
  "instance": "/api/task_engine/v1/admin/queues/gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1/hold",
  "trace_id": "<trace>",
  "context": {
    "resource_type": "gts.cf.core.tasks.queue.v1~",
    "resource_name": "gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1",
    "violations": [ { "type": "STATE", "subject": "DEAD_LETTER_QUEUE", "description": "only dispatch queues can be held" } ]
  }
}
```

## Side effects
- Per row. The refused rows write nothing.

## Notes
- A dead-letter queue is never dispatched (PRD.md:801), so there is nothing to hold, and a hold never affects re-enqueue from a DLQ (G-OPS-10).
- The `OUT_OF_RANGE` reason for a past `until` is the generic code of CONVENTIONS §6; G-OPS-08 decides only the `400`.
