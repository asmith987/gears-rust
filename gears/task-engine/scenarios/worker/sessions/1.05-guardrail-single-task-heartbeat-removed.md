# The single-task heartbeat endpoint is gone

| | |
|---|---|
| Requirement | DESIGN.md:1066 (removed), :1067 · `cpt-cf-task-engine-fr-heartbeat` (PRD.md:674) |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › API reads and responses › Bounded responses (accepted: "the single-task heartbeat … only the batch heartbeat stays") |

`main` lists `POST /tasks/{id}/heartbeat` next to the batch heartbeat (DESIGN.md:1066). The accepted proposal removes it: a worker always renews its session with `POST /tasks/heartbeat`, even for one lease.

## Setup
- `{task_1}` (`running`) is held by `{worker_a}` in session `{session_1}` with lease `{lt_1}`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```

## Expected response
- `404 Not Found` (no such route). A `405 Method Not Allowed` is also acceptable if the router matches the path for another method; nothing else is.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "no route for POST /api/task_engine/v1/tasks/{task_1}/heartbeat",
  "instance": "/api/task_engine/v1/tasks/{task_1}/heartbeat",
  "trace_id": "<trace>"
}
```

## Side effects
<!-- No side effects: the request is refused before any write. -->
- session `{session_1}` lease_until is not extended.

## Notes
- A route that does not exist must not be confused with the `/tasks/{id}` read; the body above is the platform router's, not the task `not_found` with `resource_name`.
