# A running task past its execution deadline ends timed_out even when the session scan finds it first

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-timeouts` (PRD.md:519-520) · replaces DESIGN.md:2755-2759, :2777-2804 · DESIGN.md:2770-2775 |
| Phase | p1 |
| Test level | Integration — clock race |
| Depends on | Proposals › Heartbeats and leases › Same timeout precedence in both scans |
| Gaps | G-EXE-10 |

On `main` the deadline scan ends an overdue running task `timed_out`, but the session scan requeues it as a lost worker; the two run in different shards, so a lagging shard decides. With the accepted change both scans call one shared expiry step with the same order of causes: an execution timeout is task-attributed and terminal, so it wins.

## Setup
- `{task_1}`: **render** task on **reports** (`execution_timeout_secs: 900`, DLQ **dead_letter**), claimed (and started) at `T0`, so `execution_deadline = T0+900s` (set by the claim, G-EXE-10). It is the only task of session `{session_1}`.
- The worker process hangs at `T0+880s` and heartbeats no more; `lease_until = T0+900s` (last renewal at `T0+870s`).
- At `T0+901s` the session-scan shard runs before the deadline-scan shard that owns `{task_1}`.

## Request
At `T0+905s`:
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, `state: dead_lettered`, `result.result_code: timed_out`, `liveness_requeues: 0`.

```json
{
  "id": "{task_1}",
  "state": "dead_lettered",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1",
  "dead_lettered_from": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "liveness_requeues": 0,
  "result": { "result_code": "timed_out", "output": null, "error": null, "warnings": [] },
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- session `{session_1}` is expired.
- task `{task_1}` state is `dead_lettered`; task `{task_1}` result_code is `timed_out`.
- history of `{task_1}` gains `taskTimedOut` and `taskDeadLettered`.
- No liveness failure is recorded toward the blacklist (an execution timeout is not counted, PRD.md:702).
- metric `te_lease_expired_total{cause="execution"}` increases by 1 (not `cause="session"`).

## Notes
- The other pairs (assignment deadline with session expiry, lifetime deadline with session expiry), where the accepted precedence does not apply and the guarded update makes the first detector win, are in [Concurrent deadline detectors act once](../../timeouts/1.06-guardrail-concurrent-deadline-detectors-act-once.md).
