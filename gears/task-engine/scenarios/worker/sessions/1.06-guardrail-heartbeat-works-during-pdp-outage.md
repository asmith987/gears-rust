# Heartbeats keep sessions alive while the PDP is unreachable

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-heartbeat` (PRD.md:674) · replaces PRD.md:925, :961; DESIGN.md:989, :1009, :1022; ADR-0016:72, :81 for heartbeats |
| Phase | p1 |
| Test level | Integration — PDP outage |
| Depends on | Proposals › Heartbeats and leases › No PDP call on heartbeat |
| Gaps | G-EXE-06, G-SEC-01, G-SEC-03 |

On `main` every lease-fenced call checks `claim`, so a PDP outage of one lease length expires every session on the platform. With the accepted change a heartbeat checks only authentication, the session's subject guard, and token, holder and state per lease. It changes no task data and extends only leases the subject already holds.

## Setup
- `{task_1}` (`running`) is held by `{worker_a}` in session `{session_1}` with lease `{lt_1}`; `lease_until = T0+30s`.
- From `T0+1s` the AuthZ Resolver (PDP) is unreachable from every engine node. Authentication (local token validation) still works.

## Request
At `T0+10s`, and again every 10 s:
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```

## Expected response
- `200 OK`, `{task_1}` `ok`, for as long as the outage lasts.

```json
{
  "session_id": "{session_1}",
  "heartbeat_interval_secs": 10,
  "results": [ { "task_id": "{task_1}", "outcome": "ok", "state": "running", "cancel_requested": false } ]
}
```

## Side effects
- session `{session_1}` lease_until is extended to `T0+40s` (and further on each heartbeat).
- No PDP call is attempted.
- The session scan expires nothing; metric `te_worker_sessions_expired_total` does not increase.
- subsequent `POST /tasks/{task_1}/progress` (or any other worker write) during the outage returns `503` `service_unavailable` with `Retry-After: 5` and changes nothing — see [PDP unreachable on a worker write](../fencing/1.08-guardrail-worker-write-authorization-outcomes.md).

## Notes
- Every other call that needs the PDP fails closed with `503` and `Retry-After` (`unavailable_retry_after_secs`, 5) during an outage; nothing is written and leases are kept (G-SEC-01, G-EXE-06). A cached-decision path is not in p1.
- PRD.md:925 and DESIGN.md:989 still list heartbeat among calls that need `claim`; those lines are to be edited under the accepted proposal.
