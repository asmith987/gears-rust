# A batch heartbeat with more leases than heartbeat_batch_max is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-heartbeat` (PRD.md:674) · DESIGN.md:1067 (`heartbeat_batch_max`, default 500) |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-04 |

The batch heartbeat lists at most `heartbeat_batch_max` leases (default 500, DESIGN.md:1067). A longer list is refused as a bad request; the session is not renewed, so the worker must split the list and send again before its lease runs out.

## Setup
- Session `{session_1}` of `reports-7f9c-1` holds 501 leases (`{task_1}` … `{task_501}`). `heartbeat_batch_max: 500`.

## Request
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "session_id": "{session_1}",
  "leases": [
    { "task_id": "{task_1}", "lease_token": "{lt_1}" },
    "… 499 more …",
    { "task_id": "{task_501}", "lease_token": "{lt_501}" }
  ]
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, a field violation on `/leases` (`TOO_MANY`) naming the limit.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "too many leases in one heartbeat",
  "instance": "/api/task_engine/v1/tasks/heartbeat",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/leases", "description": "at most heartbeat_batch_max (500) leases per request", "reason": "TOO_MANY" } ] }
}
```

## Side effects
<!-- No side effects: the request is refused before any write. -->

## Notes
- Above `heartbeat_batch_max` (default 500, range 1–1000) the request is refused `400 TOO_MANY` on `/leases` and the session is not renewed (G-EXE-04); the setting is added to the configuration block (DESIGN.md:2061-2247).
- A session can hold more than 500 leases only if the SDK claims that many; `claim_max_batch` (32, DESIGN.md:2135) caps one claim, not a session.
