# Neither priority nor age is compared across queues

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-assignment` (PRD.md:657) · `cpt-cf-task-engine-fr-priority-dispatch` (PRD.md:398) |
| Phase | p1 |
| Test level | Integration — needs deterministic queue contents; shared e2e queues interfere |
| Depends on | Proposals › Claiming and ordering › Claims across queues — gives up oldest-first across queues |
| Gaps | G-CLM-01, G-CLM-04 |

"Priority is not compared across queues" (PRD.md:657) stays true; with the accepted rotation, age is no longer compared either (Proposals › Claiming and ordering, Gives up). Two consecutive claims over two queues return one task of each, even when one queue holds only priority-0 tasks and the other only old priority-1000 tasks.

## Setup
- All tasks `{tenant_a}`, `normal`, `queued`:
  - **reports**: `{r1}`, `{r2}`, priority 1000, created `T0`, `T0+1s`;
  - **bulk**: `{b1}`, `{b2}`, priority 0, created `T0+60s`, `T0+61s`.
- One engine node; one worker process claims sequentially. Clock `T0+70s`.

## Request (sent twice)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": "{session_1}",
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
             "gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1"],
  "max_tasks": 1, "timeout_secs": 0 }
```

## Expected response
- Two `200 OK` responses with one claim each; together they are `{r1, b1}`.
- Not `{b1, b2}` (which a cross-queue priority order would give) and not `{r1, r2}` (which the replaced oldest-first merge would give).

## Side effects
- tasks `{r1}` and `{b1}` state is `claimed`; `{r2}`, `{b2}` stay `queued`.
