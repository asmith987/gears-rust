# A `critical` task is claimed before `normal` tasks of its queue, whatever their tenant or age

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-priority-dispatch` (PRD.md:392-401, :1530) · DESIGN.md:2441, :2446 · ADR-0008:46 |
| Phase | p1 |
| Test level | Both — E2E smoke on a dedicated queue; integration full matrix |

Urgency is the first key of the order inside a queue and the only one that ranks tenants: `critical` goes before `normal` even when the `normal` task is older and belongs to the tenant whose turn it is (PRD.md:396, :401). Only callers with `expedite` can create `critical` tasks.

## Setup
- PDP grants `{creator_b}` `expedite` for this scenario.
- **reports** (`round_robin`) holds, all `queued`:
  - `{task_1}` of `{tenant_a}`, `normal`, priority 0, created `T0`;
  - `{task_2}` of `{tenant_b}`, `critical`, priority 1000, created `T0+5s`.
- `{platform_worker}` may claim from **reports** for both tenants. Clock `T0+10s`.

## Request
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-ops-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 1, "timeout_secs": 0 }
```

## Expected response
- `200 OK`, one claim for `{task_2}` (`urgency: critical`), not the older, higher-priority `{task_1}`.

```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "claims": [ { "task": { "id": "{task_2}", "owner_tenant_id": "{tenant_b}", "urgency": "critical", "priority": 1000,
                          "state": "claimed", "…": "other fields as in CONVENTIONS §5.1" },
                "lease": { "lease_token": "{lt_1}", "lease_epoch": 1, "attempt": 1, "lease_secs": 30 },
                "authority": { "…": "…" }, "resumed": null } ] }
```

## Side effects
- task `{task_2}` state is `claimed`; task `{task_1}` state is `queued`.
- subsequent claim by the same worker returns `{task_1}`.

## Notes
- `platform-ops-1` is a scenario-local `worker_id`.
- Creating `{task_2}` without `expedite` is `403` (PRD.md:396); that refusal belongs to `tasks/create/`.
