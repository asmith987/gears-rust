# Priority orders one tenant's own tasks, never one tenant against another

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-priority-dispatch` (PRD.md:398-401) · `cpt-cf-task-engine-fr-tenant-fairness` (PRD.md:410) · DESIGN.md:2455-2458, :2514 |
| Phase | p1 |
| Test level | Integration — needs deterministic queue contents; shared e2e queues interfere |
| Gaps | G-CLM-27 |

Inside one tenant of a `round_robin` queue, a higher priority (lower number) goes first even when it is newer. Across tenants priority does nothing: a tenant cannot jump the rotation by sending priority 0.

## Setup
- **default** (`round_robin`) holds, all `queued`, `normal`:
  - `{task_1}` of `{tenant_a}`, priority 500, created `T0`;
  - `{task_2}` of `{tenant_a}`, priority 10, created `T0+1s`;
  - `{task_3}` of `{tenant_b}`, priority 1000, created `T0+2s`.
- Clock `T0+5s`.

## Exchange 1 — tenant worker of A
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1"], "max_tasks": 1, "timeout_secs": 0 }
```
- `200 OK`, one claim for `{task_2}` (priority 10 beats the older priority-500 task of the same tenant).
- `{task_3}` is invisible to `{worker_a}` (scoped read, DESIGN.md:2451).

## Exchange 2 — platform worker, both tenants
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-ops-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1"], "max_tasks": 2, "timeout_secs": 0 }
```

## Expected response
- Exchange 2: `200 OK` with two claims, `{task_1}` and `{task_3}`: B's priority-1000 task is not held back behind A's priority-500 task.

## Side effects
- tasks `{task_1}`, `{task_2}`, `{task_3}` state is `claimed`.

## Notes
- Priority aging is dropped (G-CLM-27), so priorities do not change during the test.
