# `round_robin` serves a small tenant's tasks between a big tenant's, whatever their priority

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-tenant-fairness` (PRD.md:404-413, :1529) · `cpt-cf-task-engine-fr-priority-dispatch` (PRD.md:398, :401) · DESIGN.md:2445-2459, :2513 |
| Phase | p1 |
| Test level | Integration — needs deterministic queue contents; shared e2e queues interfere |

The PRD acceptance case: with tenant A holding 1,000 queued tasks and tenant B holding 10, B's tasks are claimed between A's, not after all of them, even if A uses priority `0` and B `1000` (PRD.md:1529). In `round_robin` the queue picks the next tenant first, and priority only orders the chosen tenant's own tasks.

## Setup
- **default** queue (`round_robin`, unlimited concurrency) holds, all `queued`, `normal`:
  - 1,000 tasks of `{tenant_a}`, priority 0, created `T0` … `T0+999ms`;
  - 10 tasks of `{tenant_b}`, priority 1000, created after all of A's (`T0+1s` … `T0+1.009s`).
- One engine node. `{platform_worker}` may claim from **default** for both tenants. Clock `T0+5s`.

## Request
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-ops-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1"], "max_tasks": 20, "timeout_secs": 0 }
```

## Expected response
- `200 OK` with 20 claims: exactly **10** of `{tenant_b}` (all of B's tasks) and 10 of `{tenant_a}`.
- The 10 tasks of A are A's 10 oldest (A's own order: priority, then age, then ID).

## Side effects
- All 10 of B's tasks and A's 10 oldest are `claimed`; A's other 990 stay `queued`.

## Notes
- One batch claim is used because tenant turns inside one claim do not depend on where the node's cursor stood before (DESIGN.md:2446: one candidate per tenant in turn). The sequential variant (20 claims with `max_tasks: 1`, one node) must alternate tenants: no two consecutive claims return a task of the same tenant while both have work.
- With several nodes the rotation is approximate (PRD.md:410); see [1.08](1.08-guardrail-round-robin-across-nodes-is-approximate.md).
- `claim_candidate_budget` (256) is far above the 20 probes this claim needs.
