# Tenant rotation across nodes is approximate but never skips a tenant for more than a cycle per node

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-tenant-fairness` (PRD.md:410) · DESIGN.md:2513 |
| Phase | p1 |
| Test level | Integration — needs deterministic queue contents; shared e2e queues interfere |
| Gaps | G-CLM-05 |

The tenant cursor of a `round_robin` queue is node memory. With several engine nodes each node rotates on its own, so the global sequence is not a perfect A, B, A, B; but no active tenant is skipped for more than one cycle **per node** (PRD.md:410). Tests check that bound, not exact alternation.

## Setup
- Two engine nodes, N1 and N2. **default** (`round_robin`) holds 100 `queued` tasks of `{tenant_a}` (priority 0) and 10 of `{tenant_b}` (priority 1000).
- `{platform_worker}` sends claims with `max_tasks: 1`, alternating N1, N2, N1, N2 (two worker processes, one per node, each with its own session).

## Request (×4: N1, N2, N1, N2)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-ops-1", "session_id": "{session_1}",
  "queues": ["gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1"], "max_tasks": 1, "timeout_secs": 0 }
```

## Expected response
- Four `200 OK` answers. The two claims served by N1 are one of A and one of B; the same for the two served by N2. So at least two of the four claims return a `{tenant_b}` task.
- Not asserted: the global interleaving (A, A, B, B is allowed).

## Side effects
- Two `{tenant_b}` tasks and two `{tenant_a}` tasks are `claimed`.

## Notes
- The worker on N2 uses `platform-ops-2` and its own session; both are scenario-local.
- The same per-node reasoning checks the queue rotation, which also keeps its cursor in node memory: per node and waiter group, each of n named queues is the start queue of one claim round in every n consecutive rounds; across nodes and restarts only eventual service is promised (G-CLM-05).
