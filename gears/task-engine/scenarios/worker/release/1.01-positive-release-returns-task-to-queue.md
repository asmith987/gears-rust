# Releasing a task gives it back without spending any budget, with an optional delay or checkpoint

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-release` (PRD.md:687: "a `claimed` or `running` task", "MAY carry a checkpoint"; :689) · `cpt-cf-task-engine-fr-task-checkpoint` (PRD.md:383) · `cpt-cf-task-engine-fr-wait-conditions` (PRD.md:548) · DESIGN.md:491-493, :546, :556-561, :574, :703, :724, :732, :1071, :1095 · ADR-0011:61 |
| Phase | p1 (release) · p2 (event waits) |
| Test level | E2E |
| Gaps | G-CLM-30, G-EXE-10, G-EXE-11, G-EXE-12, G-EXE-13, G-EXE-16, G-EXE-23, G-EXE-24, G-EXE-25, G-WAI-15, G-WIRE-09 |

A worker that shuts down, is over capacity, or knows the task cannot progress now gives the task back. In one fenced transaction the engine ends the lease, frees the slots, cancels any armed wait group, moves the task to `queued` (or `scheduled` with a delay) and records `taskQueued` with `reason: released`. No retry budget, no liveness budget, no blacklist strike, and no new attempt: the next claim continues the same attempt (PRD.md:661; attempt counting lives in [Attempt counting across claims](../claim/1.05-positive-attempt-counting-across-claims.md)).

## Setup
- `{task_1}` (`running`) on **reports**, held by `reports-7f9c-1` in session `{session_1}` with `{lt_1}`; `attempt: 1`, `retry_count: 0`, `liveness_requeues: 0`.

## Request
Representative case (**running, no delay**), at `T0+20s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/release HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```

## Expected response
- `200 OK`, the task `queued`, `assignment: null`, counters unchanged.

```json
{
  "id": "{task_1}",
  "state": "queued",
  "attempt": 1,
  "retry_count": 0,
  "liveness_requeues": 0,
  "assignment": null,
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
Shared by every row:
- lease `{lt_1}` is invalid (later calls get LEASE_LOST); task `{task_1}` lease_epoch is `1` (kept, DESIGN.md:574).
- `queue_global(reports)` used changes by `-1`; `queue_tenant(reports, tenant_a)` used changes by `-1`.
- history of `{task_1}` gains `taskQueued` with `reason: released`, `actor: {worker_a}`, `attempt: 1`.
- No liveness failure and no blacklist strike is recorded; `attempt`, `retry_count`, `liveness_requeues` unchanged.
- subsequent claim of `{task_1}` returns `attempt: 1` and `lease_epoch: 2`.

Representative only:
- task `{task_1}` state is `queued`; `resume_pending` is set (DESIGN.md:732).
- The task re-enters the queued set as a re-entry, never refused by depth limits (DESIGN.md:559; [Engine moves never refused](../../limits/depth/1.04-guardrail-engine-moves-never-refused.md), row "release without delay").
- timer `execution` for `{task_1}` is removed; timer `queue_timeout` for `{task_1}` is armed at `T0+20s+3600s`; timer `lifetime` is kept.
- event taskQueued for `{task_1}` is not published under the default `lifecycle` preset (PRD.md:898).

## Notes
- A release with a stale token gets `409` `LEASE_LOST` ([Failed fence returns LEASE_LOST](../fencing/1.04-negative-failed-fence-returns-lease-lost.md)). A repeated release after a lost response also gets `LEASE_LOST`; the SDK treats it as applied (G-EXE-16).
