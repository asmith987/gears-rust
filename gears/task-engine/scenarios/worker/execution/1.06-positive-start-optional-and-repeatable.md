# `start` is optional and safe to repeat: a second `start` is a no-op and a worker may finish from `claimed`

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-design-state-machine` · `cpt-cf-task-engine-fr-timeouts` (PRD.md:519) · DESIGN.md:481, :486, :531, :534-538, :734, :1317 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-10, G-EXE-11, G-EXE-25, G-WAI-20 |

The worker fence accepts `state_code IN (claimed, running)` (DESIGN.md:734), and the state machine now matches it: `start` is optional (G-EXE-11). `complete` (success, warning, a reported failure, a cancel acknowledgement), `release` and set-wait are allowed from `claimed` as well as `running`; the `claimed → terminal` and `claimed → scheduled` edges are added. A repeated `start` by the holder on a `running` task is an idempotent `200` that changes nothing (G-EXE-10), so a network retry of `start` is safe. The execution deadline is set by the claim and never moved by `start`, so repeating `start` cannot push it out. A call with a stale token still gets `409 LEASE_LOST` ([Failed fence returns LEASE_LOST](../fencing/1.04-negative-failed-fence-returns-lease-lost.md)).

## Setup
- Representative case (**start while running**): `{task_1}` was claimed at `T0` (`execution_deadline = T0+900s`) and started at `T0+2s` ([Start a claimed task](1.01-positive-start-claimed-task.md)): `running`, lease `{lt_1}`.

## Request
At `T0+800s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/start HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```

## Expected response
- `200 OK`, the task resource unchanged: `state: running`, `assignment.execution_deadline` still `T0+900s`, `updated_at` still `T0+2s`.

```json
{
  "id": "{task_1}",
  "state": "running",
  "attempt": 1,
  "assignment": { "assignee_subject": "{worker_a}", "worker_id": "reports-7f9c-1", "claimed_at": "2026-11-03T10:00:00Z", "attempt": 1, "lease_epoch": 1,
                  "execution_deadline": "2026-11-03T10:15:00Z" },
  "updated_at": "2026-11-03T10:00:02Z",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- Representative: nothing changes. Timer `execution` for `{task_1}` stays at `T0+900s`; history gains no second `taskStarted`; lease `{lt_1}` stays valid.

## Cases

Rows other than the representative start from `{task_1}` claimed at `T0` by `reports-7f9c-1` with `{lt_1}`, never started (`claimed`, `assignment_deadline = T0+60s`, `execution_deadline = T0+900s`); each request is sent at `T0+20s`.

## Notes
- DESIGN.md:486, :534-538 and :1317 (`state = running` in the completion update) change under G-EXE-11; DESIGN.md:531 ("set again on every start") changes under G-EXE-10.
- No worker call with a valid lease is refused with a `STATE` violation any more: the lease exists only in `claimed` and `running`, both valid sources, and every other state has already invalidated it (`409 LEASE_LOST`).
