# Progress with a percent outside 0–100 is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-progress` (PRD.md:753: "percent (0–100)") · DESIGN.md:1210 · `schemas/types/…task_progressed.v1~` (`percent` 0–100) |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-SEC-21 |

Percent is bounded to 0–100. A value outside it is a bad request and is not buffered.

## Setup
- `{task_1}` (`running`), held by `reports-7f9c-1` with `{lt_1}`; `progress` is `{ "percent": 45 }`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/progress HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "percent": 140 }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation on `/percent`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "invalid progress",
  "instance": "/api/task_engine/v1/tasks/{task_1}/progress",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/percent", "description": "must be between 0 and 100", "reason": "OUT_OF_RANGE" } ] }
}
```

## Side effects
<!-- No side effects: the request is refused before anything is buffered. -->
- task `{task_1}`.progress stays `{ "percent": 45 }`.

## Notes
- The same applies to negative `completed_units` / `total_units` (schema `minimum: 0`). Whether `completed_units > total_units` is refused is not stated; not asserted.
