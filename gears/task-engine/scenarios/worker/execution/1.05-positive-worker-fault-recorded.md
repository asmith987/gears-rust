# A reported failure records its fault, and the published event carries only its classification

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-structured-io` (PRD.md:269: `fault` is `task`, `dependency` or `worker`) · `cpt-cf-task-engine-fr-worker-blacklist` (PRD.md:700, :702) · DESIGN.md:538, :737, :875 |
| Phase | p1 (fault recorded) · p3 (blacklist effect) |
| Test level | E2E |
| Gaps | G-WIRE-04, G-EXE-05, G-RTY-03 |

An error carries a `fault` that says who is to blame. It is stored in full (in the task's history while the task is retried, in its result once it ends), is readable through the API, and affects only the worker blacklist: `worker` counts as a strike, `task` and `dependency` do not. Published events carry the error's `domain`, `code`, `fault` and `retryable`, never its `message` or `context` (DESIGN.md:875).

## Setup
- `{task_1}` (`running`) on **reports** (`max_retries: 3`, `base_interval_secs: 5`), held by `reports-7f9c-1` with `{lt_1}`; `retry_count: 0`.

## Request
At `T0+40s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "SCRATCH_DISK_FULL",
    "message": "no space left on /tmp (report r-42)",
    "context": {
      "free_bytes": 0
    },
    "retryable": true,
    "fault": "worker"
  }
}
```

## Expected response
- `200 OK`, the task in `scheduled` for a retry (retryable, `retry_count < max_retries`, DESIGN.md:538), with `result: null` (it stays `null` until the task ends, G-RTY-03); `run_after` is `now + 5 s` shortened by jitter to 4–5 s (`n = retry_count + 1 = 1`, DESIGN.md:2866).

```json
{
  "id": "{task_1}",
  "state": "scheduled",
  "retry_count": 1,
  "run_after": "2026-11-03T10:00:44Z",
  "result": null,
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- task `{task_1}` state is `scheduled`; `retry_count` advances from `0` to `1`; `liveness_requeues` unchanged.
- lease `{lt_1}` is invalid (later calls get LEASE_LOST).
- history of `{task_1}` gains `taskRetrying` with `cause: reported` and the full `error` (with `message` and `context`), as `GET /tasks/{task_1}/events` returns it (G-EXE-05, G-RTY-03).
- event taskRetrying for `{task_1}` is published to the task-events topic with only the error summary `{ "domain": "acme.reports", "code": "SCRATCH_DISK_FULL", "fault": "worker", "retryable": true }` (no `message`, no `context`, DESIGN.md:875).
- Blacklist (p3): one failure is counted for (`{worker_a}`, `reports-7f9c-1`) on **reports**; with `fault: "task"` or `"dependency"` nothing would be counted or reset (PRD.md:702).

## Notes
- A `scheduled` task's `result` stays `null` until it ends; the last error is read from the `taskRetrying` history row (G-RTY-03).
