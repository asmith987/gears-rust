# Two concurrent payload writes on one task: one wins, the other gets CONCURRENT_MODIFICATION

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-nfr-payload-size` (PRD.md:1276) · DESIGN.md:724, :1207, :2669-2699 |
| Phase | p1 |
| Test level | Integration — race |

Payload writes (checkpoint, complete with output, set-wait with checkpoint, release with checkpoint) read the stored `revision`, check the size, and write with `WHERE revision = r`. Two writes from the holder that race on the same task cannot both commit: the loser gets `409` `aborted` / `CONCURRENT_MODIFICATION`, which — unlike `LEASE_LOST` — is retryable.

## Setup
- `{task_1}` (`running`), held by `reports-7f9c-1` with `{lt_1}`; `context` `{ "page": 3 }`, `revision` 5.
- The worker's handler runs two sub-steps in parallel; both read `revision` 5.

## Exchange 1 — checkpoint A (commits first)
```http
POST /api/task_engine/v1/tasks/{task_1}/checkpoint HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "checkpoint": { "page": 4 } }
```

- `200 OK`, `{ "context": { "page": 4 } }`; `revision` becomes 6.

## Exchange 2 — checkpoint B (loses the guard)
```http
POST /api/task_engine/v1/tasks/{task_1}/checkpoint HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "checkpoint": { "thumbs": 12 } }
```

- `409 Conflict`, `aborted`, `context.reason = "CONCURRENT_MODIFICATION"`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.aborted.v1~",
  "title": "Aborted",
  "status": 409,
  "detail": "the task payload was changed by a concurrent write; retry",
  "instance": "/api/task_engine/v1/tasks/{task_1}/checkpoint",
  "trace_id": "<trace>",
  "context": { "reason": "CONCURRENT_MODIFICATION" }
}
```

## Side effects
- task `{task_1}`.context is `{ "page": 4 }`; `revision` is 6; one `taskCheckpointed`.
- lease `{lt_1}` stays valid.
- subsequent retry of exchange 2 returns `200` with `{ "page": 4, "thumbs": 12 }`.

## Notes
- Heartbeat and progress never read or bump `revision`, so they never cause this conflict (DESIGN.md:2699).
- A zombie whose write races a payload change gets `LEASE_LOST`, never `CONCURRENT_MODIFICATION`: see the "checkpoint racing a payload write" row of [Failed fence returns LEASE_LOST](../fencing/1.04-negative-failed-fence-returns-lease-lost.md).
