# A checkpoint that pushes the task over 64 KB is rejected and changes nothing

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-checkpoint` (PRD.md:383) · `cpt-cf-task-engine-nfr-payload-size` (PRD.md:1276, :1278) · DESIGN.md:724, :1209, :2680-2681 |
| Phase | p1 (checkpoint is p1, G-EXE-12) |
| Test level | E2E |
| Gaps | G-EXE-12, G-EXE-13, G-SEC-21 |

The limit is on the task's **combined** payload — input + context + output, uncompressed canonical JSON — after the merge, not on the checkpoint body alone (DESIGN.md:724; the limit applies to the merge result, G-EXE-13). Over 65,536 bytes the write is rejected `413` and the stored context stays as it was.

## Setup
- `{task_1}` (`running`), held by `reports-7f9c-1` with `{lt_1}`; `max_payload_size_bytes: 65536` (DESIGN.md:2142).
- Stored payload: `input` 40 B, `context` `{ "page": 3, "notes": "<40,000 characters>" }` ≈ 40,030 B; `output` none.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/checkpoint HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "checkpoint": { "page": 4, "index": "<30,000 characters>" } }
```

The body (≈ 30 KB) is under the 1 MB request limit; the merged payload (≈ 70 KB) is over 64 KB.

## Expected response
- `413 Payload Too Large`, `invalid_argument` with the transport override (DESIGN.md:1209).

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 413,
  "detail": "the task payload would exceed 65536 bytes",
  "instance": "/api/task_engine/v1/tasks/{task_1}/checkpoint",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/checkpoint", "description": "input + context + output must not exceed max_payload_size_bytes (65536)", "reason": "PAYLOAD_TOO_LARGE" } ] }
}
```

## Side effects
<!-- No side effects: the payload write rolls back. -->
- task `{task_1}`.context is unchanged (`page` is still 3); `revision` unchanged; no `taskCheckpointed`; lease `{lt_1}` stays valid.
