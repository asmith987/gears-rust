# Starting a claimed task makes it running; the execution deadline set by the claim stays

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-timeouts` (PRD.md:518-519) · `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:726) · DESIGN.md:481, :531, :572, :794-795, :1299-1301 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-WIRE-06, G-EXE-10, G-EXE-11 |

`start` moves `claimed → running` and clears the assignment deadline. It is optional: a worker may complete, fail, release or set a wait straight from `claimed` (G-EXE-11). The execution deadline is not set here: the claim already set `execution_deadline = claim time + effective execution_timeout`, and `start` never moves it (G-EXE-10; DESIGN.md:531 changes under that decision). The lease token and epoch are kept (DESIGN.md:572).

## Setup
- `{task_1}`: **render** task of `{tenant_a}` on **reports** (`assignment_timeout_secs: 60`, `execution_timeout_secs: 900`).
- At `T0` `{worker_a}` claimed it as `reports-7f9c-1`: session `{session_1}`, lease `{lt_1}`, `lease_epoch: 1`, `attempt: 1`, so `assignment_deadline = T0+60s` and `execution_deadline = T0+900s`.

## Request
At `T0+2s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/start HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}" }
```

## Expected response
- `200 OK`, the task with `state: running`, `attempt: 1`, `assignment.lease_epoch: 1`, `assignment.execution_deadline` `T0+900s` (unchanged), no `lease_token`.

```json
{
  "id": "{task_1}",
  "state": "running",
  "attempt": 1,
  "assignment": { "assignee_subject": "{worker_a}", "worker_id": "reports-7f9c-1", "claimed_at": "2026-11-03T10:00:00Z", "attempt": 1, "lease_epoch": 1,
                  "execution_deadline": "2026-11-03T10:15:00Z" },
  "updated_at": "2026-11-03T10:00:02Z",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- task `{task_1}` state is `running`.
- timer `assignment` for `{task_1}` is removed; timer `execution` for `{task_1}` stays armed at `T0+900s`, as the claim set it (both are `te_task_state` deadline columns, DESIGN.md:794-795; G-EXE-10).
- lease `{lt_1}` stays valid; task `{task_1}` lease_epoch is `1`.
- history of `{task_1}` gains `taskStarted` with `assignee: reports-7f9c-1`, `assignee_subject: {worker_a}`, `attempt: 1`, `actor: {worker_a}`.
- event taskStarted for `{task_1}` is not published under the default `lifecycle` preset (PRD.md:898); it is published under `all`.
- No counter changes (slots were taken at claim).

## Notes
- The response is the full task resource (G-WIRE-06).
- A repeated `start` by the holder is a no-op `200`, and completing without `start` is allowed: [1.06](1.06-positive-start-optional-and-repeatable.md).
