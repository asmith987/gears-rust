# Long-poll claim wakes for a task created on another node within the poll interval

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-assignment` (PRD.md:659, :1481) · DESIGN.md:758, :958, :2411-2418, :2138 · ADR-0013:55-57, :64, :70 |
| Phase | p1 |
| Test level | Integration — two nodes |

Engine nodes share only the database. A worker parked on node N1 must get a task that is created through node N2 within one `claim_poll_interval_ms` (default 1,000 ms, jittered ±20%), without the Cluster gear (PRD.md:659). The wake-up comes from N1's queue watcher, not from a signal crossing nodes (DESIGN.md:956-958).

## Setup
- Two engine nodes, N1 and N2, on one domain database; no Cluster gear. Default `claim_poll_interval_ms: 1000`.
- **reports** has no `queued` task. `{worker_a}` has no session.

## Exchange 1 — worker parks on N1 (`T0`)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"],
  "max_tasks": 1, "timeout_secs": 30 }
```
Sent to N1. No response yet: the request is parked, holding no database connection (DESIGN.md:2415).

## Exchange 2 — creator creates a task on N2 (`T0+10s`)
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 3a7c-longpoll-r-77

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-77", "format": "pdf" } }
```
Sent to N2 → `201 Created`, task `{task_1}`, `queued`.

## Expected response (Exchange 1 completes)
- `200 OK` to the parked claim on N1, no later than `T0+10s + 1.2 s` (one jittered poll interval) plus the claim's own latency.
- One claim for `{task_1}`, `state: claimed`, `attempt: 1`.

```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "claims": [ { "task": { "id": "{task_1}", "state": "claimed", "…": "other fields as in CONVENTIONS §5.1" },
                "lease": { "lease_token": "{lt_1}", "lease_epoch": 1, "attempt": 1, "lease_secs": 30 },
                "authority": { "mode": "creator_verified", "checked": [], "checked_at": "2026-11-03T10:00:10Z" },
                "resumed": null } ] }
```

## Side effects
- task `{task_1}` state is `claimed`; history of `{task_1}` gains `taskCreated` then `taskClaimed`.
- The claim on N1 is not answered before `{task_1}` commits (no early `204`).

## Notes
- The test asserts an upper bound only. A same-node create wakes the waiter at once through the local `newTask` signal (DESIGN.md:951); the cross-node bound is the watcher tick (ADR-0013:64).
- The bound is "within the poll interval" (PRD.md:659); with ±20% jitter (DESIGN.md:2138) a single tick may be up to 1.2 s apart, so tests use `1.2 × claim_poll_interval_ms` plus a small margin for the claim itself.
