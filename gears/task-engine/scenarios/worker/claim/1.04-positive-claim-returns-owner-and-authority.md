# The claim returns the task's owner tenant, creator, owner and creator authority

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-worker-principals` (PRD.md:956-960) · DESIGN.md:1024, :1043 · ADR-0016:75 |
| Phase | p1 |
| Test level | E2E |

Workers act as themselves, but in the task's tenant. So the claim tells the worker whose work it is: the owner tenant (the context tenant for its downstream calls), the creator, and the owner, all set by the engine. For a `creator_verified` type it also carries what was checked at creation and which references are verified, so the worker acts only on verified resources (DESIGN.md:1043).

## Setup
- `{creator_a}` created `{task_1}` of type **share** in **reports** at `T0` with `input: { "document_id": "d-9" }` and `owner_id: "{creator_a2}"`. The creator check `share` on `gts.cf.docs._.document.v1~` `d-9` was allowed at creation.
- `{platform_worker}` (root tenant) may claim from **reports**; `{tenant_a}` is not behind a barrier.

## Request (`T0+5s`)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json

{ "worker_id": "platform-ops-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 1, "timeout_secs": 0 }
```

## Expected response
- `200 OK`, one claim for `{task_1}`.
- `task.owner_tenant_id` is `{tenant_a}` (not the worker's root tenant); `task.created_by` is `{creator_a}`; `task.owner_id` is `{creator_a2}`.
- `authority.mode` is `creator_verified`, `authority.checked` names the `/document_id` check as verified, `authority.checked_at` is `T0`.
- No creator token or credential appears anywhere in the body.

```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "claims": [ {
    "task": { "id": "{task_1}", "type": "gts.cf.core.tasks.task.v1~acme.docs._.share.v1~", "state": "claimed",
              "owner_tenant_id": "{tenant_a}", "created_by": "{creator_a}", "owner_id": "{creator_a2}",
              "input": { "document_id": "d-9" }, "resource_refs": [],
              "…": "other fields as in CONVENTIONS §5.1" },
    "lease": { "lease_token": "{lt_1}", "lease_epoch": 1, "attempt": 1, "lease_secs": 30 },
    "authority": { "mode": "creator_verified",
                   "checked": [ { "source": "/document_id", "resource_type": "gts.cf.docs._.document.v1~", "action": "share", "verdict": "verified" } ],
                   "checked_at": "2026-11-03T10:00:00Z" },
    "resumed": null } ] }
```

## Side effects
- task `{task_1}` state is `claimed`; `task {task_1}.assignment` names `{platform_worker}` / `platform-ops-1`.
- history of `{task_1}` gains `taskClaimed` with `assignee_subject = {platform_worker}`.

## Notes
- The item shape of `authority.checked` is not specified (DESIGN.md:1043 says "mode, checked sources, `checked_at`"); `{source, resource_type, action, verdict}` mirrors `te_tasks.authority_json` (DESIGN.md:1043). Tests assert `mode`, `checked_at` and that the check is present and verified.
- `platform-ops-1` is a scenario-local `worker_id`.
