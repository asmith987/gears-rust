# A claim that finds nothing waits for its timeout, capped at `claim_max_wait_secs`, then answers `204`

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-assignment` (PRD.md:659, :1518) · `cpt-cf-task-engine-fr-queue-concurrency` (PRD.md:429) · DESIGN.md:758, :2137, :2414, :2420 · ADR-0013:55, :71 |

When no task is ready and no eligible task was skipped for capacity, a long-poll claim parks until its timeout and then returns `204 No Content`. The worker sends its next claim at once (PRD.md:659). The wait is capped by `claim_max_wait_secs` (default 50 s, below common 60 s proxy timeouts): a larger requested timeout is clamped to the cap, and the request is accepted, not refused with `400`.

## Setup
- Default config: `claim_max_wait_secs: 50`.
- **reports** has no `queued` task and none arrives during the request. `{worker_a}` has no session.

## Request (`T0`) — representative case `timeout_secs: 5`
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"],
  "max_tasks": 1, "timeout_secs": 5 }
```

## Expected response
- `204 No Content`, no body, sent at `T0+5s` (not earlier than the requested timeout, and not much later).

```http
HTTP/1.1 204 No Content
```

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| within cap | `timeout_secs: 5` | `204` at `T0+5s` | PRD.md:659 |
| above cap | `timeout_secs: 120` | not `400`: accepted and parked; `204` at `T0+50s` (± scheduling slack), not at `T0+120s` | `claim_max_wait_secs` 50, DESIGN.md:2137, ADR-0013:71 |
| no wait | `timeout_secs: 0` | `204` at once, after one claim attempt | DESIGN.md:2414 |

## Notes
- `timeout_secs` defaults to `0` (one attempt, no wait) and is clamped to `claim_max_wait_secs`; a negative value is `400` (G-CLM-19, row in [1.07](1.07-negative-claim-request-validation.md)).
- A `204` carries no body and touches no session: a session is opened or renewed only by a claim that takes a task (G-CLM-16). DESIGN.md:2408 (session opened before the claim loop) changes under that decision. An integration test may assert that no `te_worker_sessions` row was created.
- The response does not tell the worker that its timeout was shortened; the docs define no header or field for it.
