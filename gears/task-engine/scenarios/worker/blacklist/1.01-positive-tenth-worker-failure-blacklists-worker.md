# The tenth consecutive worker failure blacklists the worker on that queue

| | |
|---|---|

A worker process whose environment is broken keeps failing every task it takes. After 10 consecutive worker-attributed failures on **reports** it is skipped there for 60 minutes, and a `workerBlacklisted` event records it. The task itself is retried as usual. Lease expiries and assignment timeouts count like reported `fault=worker` failures, as long as each lands in its own outage window, so a worker that keeps claiming tasks and then never finishing or starting them within the assignment timeout is blacklisted the same way. What does and does not count is in [Counting rules](1.03-guardrail-blacklist-counting-rules.md).

## Setup
- **reports** declares no blacklist settings, so the defaults apply: threshold 10, duration 60 min.
- `te_worker_blacklist({worker_a}, reports-7f9c-1, reports)`: `consecutive_failures = 9`, `blacklisted_until = null`.
- `{task_1}` on **reports** is `running`, held by `reports-7f9c-1` with `{lt_1}`, `retry_count: 0`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "FONT_CACHE_CORRUPT",
    "message": "local font cache unreadable",
    "fault": "worker",
    "retryable": true
  }
}
```

## Expected response
- `200 OK`, the task resource: `state: scheduled` (retry with backoff), `retry_count: 1`.

## Side effects
- Representative: task {task_1} state is scheduled; task {task_1}.retry_count advances from 0 to 1.
- Both cases: `te_worker_blacklist({worker_a}, reports-7f9c-1, reports)`: `blacklisted_until = T0+60m`, and `consecutive_failures` reset to 0 as the blacklisting starts (G-OPS-31).
- event `workerBlacklisted` for queue **reports** is published, `subject` = the queue ID, data `{ "worker": "reports-7f9c-1", "worker_subject": "{worker_a}", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1", "failure_count": 10, "until": "2026-11-03T11:00:00Z" }`; it is enqueued in the queue's domain (DESIGN.md:877).
- metric te_blacklisted_workers{queue="…acme.reports._.render.v1"} increases by 1.
- Every engine node skips the worker on **reports** within `runtime_config_poll_secs` (5 s, DESIGN.md:2259).
- `reports-7f9c-1` keeps any other leases it holds; blacklisting only stops new claims.
