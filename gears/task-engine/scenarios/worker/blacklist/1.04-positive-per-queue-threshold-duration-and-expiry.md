# A queue's own blacklist threshold and duration apply, and claims resume after it

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-worker-blacklist` (PRD.md:704) · `schemas/types/gts.cf.core.tasks.queue.v1~` (`blacklist_failure_threshold`, `blacklist_duration_minutes`) · DESIGN.md:2158-2159, :2259 |
| Phase | p3 |
| Test level | Integration — p3; counters, durations |
| Gaps | G-OPS-31 |

A queue may set a stricter threshold and a shorter cool-down than the defaults. After the cool-down the worker is offered tasks again, and its counter starts from zero: it needs `threshold` new failures to be blacklisted again (G-OPS-31).

## Setup
- **bulk** registration adds `blacklist_failure_threshold: 3`, `blacklist_duration_minutes: 10`.
- (`{worker_a}`, `reports-7f9c-1`) fails three **bulk** tasks in a row with `fault: worker`; the third at `T0`.

## Exchange 1 — At `T0+5m`, claim **bulk**
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": "{session_1}",
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1"], "max_tasks": 1, "timeout_secs": 0 }
```
- `204 No Content` (blacklisted until `T0+10m`).

## Exchange 2 — At `T0+10m+5s`, the same claim
- `200 OK` with a **bulk** task.

## Exchange 3 — The worker fails that task with `fault: worker`, then claims **bulk** again
- The `complete` (`result_code: error`, `fault: worker`, retryable) → `200`, task `scheduled`.
- The next claim → `200 OK` with a **bulk** task: one failure after the cool-down does not blacklist again.

## Side effects
- At `T0`: `te_worker_blacklist({worker_a}, reports-7f9c-1, bulk)`: `blacklisted_until = T0+10m`, `consecutive_failures` reset to 0 as the blacklisting starts; `workerBlacklisted` with `failure_count: 3`, `until: "2026-11-03T10:10:00Z"`.
- After `T0+10m` the entry no longer blocks claims (within `runtime_config_poll_secs`).
- After Exchange 3: `consecutive_failures = 1`, no new `workerBlacklisted`.

## Notes
- The counter resets to 0 when the blacklisting starts (G-OPS-31). DESIGN.md:2814 (reset only on success) changes under that decision.
