# The lease token never appears in task reads, history, events or search

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:724: "returned only to the new holder") · DESIGN.md:1081, :2344 · ADR-0011:59, :83 |
| Phase | p1 |
| Test level | E2E |

The token is a holder-bound secret. It appears only in claim and accept responses and in the holder's own requests (DESIGN.md:1081), never in logs or events (DESIGN.md:2344). Readers of the task — even the worker itself through `GET` — see only `lease_epoch`.

## Setup
- `{task_1}` (`running`) is held by `{worker_a}` (`reports-7f9c-1`) with lease `{lt_1}`, `lease_epoch: 1`.

## Exchange 1 — the task
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
```

- `200 OK`; `assignment` has no `lease_token`:

```json
{
  "id": "{task_1}",
  "state": "running",
  "assignment": { "assignee_subject": "{worker_a}", "worker_id": "reports-7f9c-1", "claimed_at": "2026-11-03T10:00:00Z", "attempt": 1, "lease_epoch": 1 },
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Exchange 2 — the history
```http
GET /api/task_engine/v1/tasks/{task_1}/events?limit=50 HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

- `200 OK`; no item payload (`taskClaimed`, `taskStarted`, …) contains `{lt_1}` or a `lease_token` key. `taskClaimed` carries `assignee`, `assignee_subject`, `attempt`, `lease_until` only (`schemas/types/…task_claimed.v1~`).

## Exchange 3 — search at the widest view
```http
GET /api/task_engine/v1/tasks?$filter=state eq 'running'&view=full HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

- `200 OK`; the item for `{task_1}` and its embedded history contain no `lease_token`.

## Side effects
<!-- No side effects: reads only. -->
- The broker events for `{task_1}` on the task-events topic contain no `lease_token`.
- No log line written while serving these calls or the claim contains `{lt_1}` (only `lease_epoch` is logged, DESIGN.md:2344).
