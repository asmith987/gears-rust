# LEASE_LOST is final: the worker does not retry, and a retry would fail the same way

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:726: "`LEASE_LOST` is final … MUST NOT retry") · DESIGN.md:703 · ADR-0011:62-63, :72 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-16 |

The canonical `aborted` category is normally retryable, so retry middleware would resend the call. For `context.reason = "LEASE_LOST"` the SDK HTTP client and any retry middleware **must not** retry (DESIGN.md:703); the right reaction is to abandon the task. A lost token never becomes valid again, so a retry would only fail again.

## Setup
- `{task_1}` was held by `reports-7f9c-1` with `{lt_1}`; the session expired and `{task_1}` was reclaimed by `reports-7f9c-2` with `{lt_2}` ([Zombie complete after reclaim](1.09-flow-zombie-complete-after-reclaim.md)).
- `reports-7f9c-1` runs the SDK worker runtime with default HTTP retry middleware.

## Exchange 1 — the zombie's checkpoint
```http
POST /api/task_engine/v1/tasks/{task_1}/checkpoint HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "checkpoint": { "page": 9 } }
```

- `409 Conflict`, `aborted`, `context.reason = "LEASE_LOST"`.

## Exchange 2 — what the engine sees next
- No second `checkpoint` (or any other call) with `{lt_1}` arrives from `reports-7f9c-1`: the SDK fires `lease.lost`, the handler stops, and the task's lease is dropped from the next batch heartbeat.
- If a non-SDK client does resend the same request, it gets the same `409` `LEASE_LOST`, at any later time.

## Side effects
<!-- No side effects: every attempt is refused by the fence. -->
- metric `te_lease_fencing_rejections_total{op="checkpoint"}` increases by 1 (by 2 if a non-SDK client resent it).
- `{task_1}` under `{lt_2}` is unaffected.

## Notes
- One case reads `LEASE_LOST` differently: after the SDK's own retryable failure report or release whose response was lost, a resend gets `LEASE_LOST` and the SDK treats the report as applied (debug log, no `lease.lost`, G-EXE-16). It is still not retried.
