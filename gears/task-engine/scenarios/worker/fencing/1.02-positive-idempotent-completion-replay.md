# Repeating a completion with the same token and result returns the stored outcome

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:728) · DESIGN.md:576, :736, :2692 · ADR-0011:65 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-16, G-RTY-05 |

A worker whose completion response was lost on the network sends it again. The fenced update now matches nothing (the task is terminal), but the task is terminal with the same `lease_token` and `assignee_subject` (a worker completion keeps the token, DESIGN.md:576) and a canonical-JSON-equal result. The engine returns the stored outcome instead of `LEASE_LOST`, so the retry is not mistaken for lease loss.

## Setup
- `{task_1}` was `running` under `reports-7f9c-1` with `{lt_1}`. At `T0+20s` it sent the completion below; the engine committed it (`completed` / `success`), but the response was lost.

## Request
At `T0+21s`, the same body again:
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-42.pdf"} }
```

## Expected response
- `200 OK` with the platform header `Idempotency-Replayed: true` and the stored task (DESIGN.md:736).

```http
HTTP/1.1 200 OK
Idempotency-Replayed: true
Content-Type: application/json
```
```json
{
  "id": "{task_1}",
  "state": "completed",
  "result": { "result_code": "success", "output": { "url": "https://files.example.com/r-42.pdf" }, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:00:20Z",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
<!-- No side effects: a replay writes nothing. -->
- history of `{task_1}` holds exactly one `taskCompleted`.

## Notes
- Equality is canonical JSON (key order and whitespace do not matter, DESIGN.md:736).
- The replay rule covers terminal outcomes only. A repeated non-terminal report (a **retryable** `error`, which moves the task to `scheduled` and clears the token, DESIGN.md:574; or a release) gets `409 LEASE_LOST`; the engine keeps no replay state for it, and the SDK treats `LEASE_LOST` after its own retryable failure or release as already applied (G-EXE-16, G-RTY-05).
