# A second completion with a different result is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:728: "A different result is rejected (`400`, task already ended)") · DESIGN.md:736, :1234 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-WIRE-14 |

At most one completion is accepted per task. The holder that already completed and now sends a different result is not a network retry; it gets `failed_precondition` `400` (violation type `STATE`) and the stored result stays.

## Setup
- As in [Idempotent completion replay](1.02-positive-idempotent-completion-replay.md): `{task_1}` is `completed` / `success` with `output.url = https://files.example.com/r-42.pdf`, completed with `{lt_1}`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "warning",
  "output": {
    "url": "https://files.example.com/r-42.pdf"
  },
  "warnings": [
    {
      "domain": "acme.reports",
      "code": "FONT_FALLBACK",
      "message": "fallback font used",
      "retryable": false,
      "fault": "task"
    }
  ]
}
```

## Expected response
- `400 Bad Request`, `failed_precondition`, violation `{ type: STATE, subject: STATE }`, `resource_name` = the task (G-WIRE-14).

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
  "status": 400,
  "detail": "the task has already ended with a different result",
  "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~", "resource_name": "{task_1}",
               "violations": [ { "type": "STATE", "subject": "STATE", "description": "task is completed" } ] }
}
```

## Side effects
<!-- No side effects: the stored result is unchanged. -->
- task `{task_1}` result_code is `success` (unchanged).
