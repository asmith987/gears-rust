# Progress buffered under a lease that is lost before the flush is never saved

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:726: "A progress update accepted under a lease that is lost before it is saved MUST be dropped") · `cpt-cf-task-engine-fr-progress` (PRD.md:753) · DESIGN.md:936-940, :2322 · ADR-0011:73, :84 |
| Phase | p1 |
| Test level | Integration — flush vs lease loss |
| Gaps | G-WIRE-06 |

Progress is accepted with a fence check, then written later by the flush. If the lease is lost in between, the flush write is guarded by `lease_token = <entry token>` and matches no row, so the snapshot (and any event it would have produced) is dropped.

## Setup
- `{task_1}` (`running`) on **reports**, held by `reports-7f9c-1` in session `{session_1}` with `{lt_1}`; progress flush interval 5 s (`progress_flush_interval_secs`, DESIGN.md:2067); `progress` is `{ "percent": 40 }` (saved).
- Last heartbeat at `T0`; `lease_until = T0+30s`.

## Exchange 1 — progress accepted
At `T0+28s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/progress HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "percent": 80, "milestone": "rendered" }
```

- `200 OK`, empty body; the update is buffered with `due_at = T0+33s`.

## Exchange 2 — the lease is lost before the flush (no request)
At `T0+30.5s` the session scan expires `{session_1}` and requeues `{task_1}` to `scheduled`, clearing `{lt_1}`. At `T0+33s` the flush runs.

## Exchange 3 — read the task
At `T0+40s`:
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

- `200 OK`, `state: scheduled`, `progress: { "percent": 40 }` (the buffered 80 % was dropped).

## Side effects
- metric `te_progress_stale_dropped_total` increases by 1.
- history of `{task_1}` gains no `taskProgressed`; event taskProgressed for `{task_1}` is not published.

## Notes
- The progress answer is `200` with an empty body (DESIGN.md:1314; G-WIRE-06).
- A *terminal* transition flushes a pending entry under the task's lease inside its own transaction (DESIGN.md:2940-2941), so this drop applies to non-terminal lease loss (session expiry, release, park).
