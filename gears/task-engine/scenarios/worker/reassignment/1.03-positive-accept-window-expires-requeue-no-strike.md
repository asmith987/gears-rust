# If nobody accepts within one lease, the task is requeued with no blacklist strike

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-reassignment` (PRD.md:715) · DESIGN.md:539, :548, :2775-2798 |
| Phase | p3 |
| Test level | Integration — accept-window expiry |
| Gaps | G-OPS-26, G-EXE-05, G-RTY-02 |

A hand-off that is never accepted must not leave the task stuck. After one lease duration the deadline scan requeues it like a lost lease: it uses the liveness budget (`liveness_requeues` +1, backoff). The named worker never held it, so nobody gets a blacklist strike (G-OPS-26).

## Setup
- `{task_1}` on **reports** was reassigned at `T0` to (`{worker_a}`, `reports-7f9c-2`); `handoff_until = T0+30s`; `liveness_requeues: 0`.
- `reports-7f9c-2` never calls accept.
- Clock advances to `T0+31s`.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, `state: scheduled`, `liveness_requeues: 1`, `retry_count` unchanged, `assignment: null`, `run_after` ∈ [`T0+35s`, `T0+36s`] (first liveness backoff waits `base` = 5 s, shortened by up to 20 % jitter).

```json
{ "id": "{task_1}", "state": "scheduled", "attempt": 1, "retry_count": 0, "liveness_requeues": 1,
  "run_after": "2026-11-03T10:00:36Z", "assignment": null, "…": "other fields as in CONVENTIONS §5.1" }
```

## Side effects
- queue_global(reports) used changes by -1; queue_tenant(reports, {tenant_a}) used changes by -1.
- timer scheduled for {task_1} is armed at `run_after`.
- `te_worker_blacklist` is unchanged for both `reports-7f9c-1` and `reports-7f9c-2` on **reports**.
- metric te_lease_expired_total{cause="handoff"} increases by 1.
- history of {task_1} gains taskRetrying with `cause: liveness`, `timeout_type: assignment` (G-EXE-05).
- The next claim gives `{task_1}` to any eligible worker, with `attempt: 2`.

## Cases

| Case | Differs from the Setup | Expected | Notes |
|---|---|---|---|
| liveness budget left | (representative) | `scheduled`, as above | G-OPS-26 |
| liveness budget exhausted | `liveness_requeues: 20` (= `max_liveness_requeues`) before the hand-off expires | `200`, `result.result_code: timed_out` (the task is `dead_lettered`, as **reports** has a DLQ, like the execution-timeout row of [blacklist/1.03](../blacklist/1.03-guardrail-blacklist-counting-rules.md)); history gains `taskTimedOut` with `timeout_type: assignment`; no blacklist strike | G-RTY-02 |

## Notes
- No strike for an expired hand-off (G-OPS-26); DESIGN.md:539 and :806 change under that decision.
- A liveness requeue records `taskRetrying` with `cause: liveness` and `timeout_type` (G-EXE-05); an expired hand-off is `assignment` (G-RTY-02).
