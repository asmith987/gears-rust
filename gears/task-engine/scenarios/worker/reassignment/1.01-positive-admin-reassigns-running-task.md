# An admin reassigns a running task to another worker identity

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-reassignment` (PRD.md:711-715) · PRD.md:1521 · DESIGN.md:547, :570, :1073 · ADR-0011 · ADR-0017:62 |
| Phase | p3 |
| Test level | E2E |
| Gaps | G-OPS-27, G-OPS-41 |

An operator moves a running task from a degraded worker process to a healthy one without losing its history. In one atomic step the old lease ends, the new assignee is recorded, the epoch goes up and `taskReassigned` is recorded. The admin gets no lease token: the new holder must accept with its own credentials.

## Setup
- `{task_1}` on **reports** is `running`, held by `{worker_a}` / `reports-7f9c-1` in `{session_1}`, `{lt_1}`, `lease_epoch: 1`, `attempt: 1`, `execution_deadline = T0+600s`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/reassign HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "subject_id": "{worker_a}", "worker_id": "reports-7f9c-2", "reason": "host reports-7f9c-1 degraded" }
```

## Expected response
- `200 OK`, the task resource. `state` and `attempt` are unchanged; `assignment` names the new identity and `lease_epoch: 2`. No `lease_token` anywhere in the body.

```json
{ "id": "{task_1}", "state": "running", "attempt": 1,
  "assignment": { "assignee_subject": "{worker_a}", "worker_id": "reports-7f9c-2", "claimed_at": "2026-11-03T09:55:00Z", "attempt": 1, "lease_epoch": 2 },
  "…": "other fields as in CONVENTIONS §5.1" }
```

## Side effects
- lease {lt_1} is invalid (later calls get LEASE_LOST).
- task {task_1} lease_epoch is 2; task {task_1} state is running.
- `{task_1}` is detached from `{session_1}`; `handoff_until = T0+30s` (one lease).
- timer execution for {task_1} is unchanged (`T0+600s`) until the accept resets it (G-OPS-27); queue_global(reports) and queue_tenant(reports, {tenant_a}) used are unchanged.
- history of {task_1} gains taskReassigned with `actor: "{admin}"`, `previous_assignee: "reports-7f9c-1"`, `new_assignee: "reports-7f9c-2"`, `lease_epoch: 2`, `reason: "host reports-7f9c-1 degraded"`.

## Notes
- `reason` is optional free text (at most 1024 characters, G-OPS-47) and is recorded in `taskReassigned`; without it the event has no `reason` (the schema field becomes optional, G-OPS-41).
- The target's rights are not checked here: its accept is authorized with its own scope ([1.02](1.02-positive-only-named-identity-accepts.md), G-OPS-27). Refusals are in [1.06](1.06-negative-reassign-refused.md).
- `claimed_at` keeps the original claim time until the accept; the accept works like a claim for the new holder and sets `claimed_at`, a new assignment deadline and the full execution deadline, while `attempt` does not change (G-OPS-27, [1.02](1.02-positive-only-named-identity-accepts.md)).
