# Reassignment is refused without task `admin` or when the task has no holder

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-reassignment` (PRD.md:713) · PRD.md:918, :925 · DESIGN.md:547, :991, :995, :1073, :1234 |
| Phase | p3 |
| Test level | Both — admin grant row integration |
| Gaps | G-OPS-27, G-SEC-19, G-WIRE-14, G-WIRE-15 |

Reassignment needs `admin`: a worker cannot hand its task to another identity, and the creator cannot move it to a worker of its choice. And only a `claimed` or `running` task has a holder to replace: a `queued` task cannot be pre-assigned to a worker. A target blacklisted on the task's queue is refused too, because it could never take the task (G-OPS-27).

## Setup
- `{task_1}` is `running`, created by `{creator_a}`, held by `reports-7f9c-1`. `{creator_a}` can read it but has no `admin`.

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/reassign HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "subject_id": "{worker_a}", "worker_id": "reports-7f9c-2" }
```

## Expected response
- `403 Forbidden`, `permission_denied`, `context.reason = "ACTION_DENIED"` (the caller may read the task).

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.permission_denied.v1~",
  "title": "Permission Denied",
  "status": 403,
  "detail": "Not allowed to reassign this task",
  "instance": "/api/task_engine/v1/tasks/{task_1}/reassign",
  "trace_id": "<trace>",
  "context": { "reason": "ACTION_DENIED", "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}" }
}
```

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| readable, no `admin` | (representative) | `403 permission_denied` `ACTION_DENIED` | PRD.md:925; DESIGN.md:991; G-SEC-19 |
| not readable | caller cannot read `{task_1}` | `404 not_found`, same as a missing task | PRD.md:918 |
| task not leased | `{task_1}` is `queued` on **reports**; caller `<admin-token>` | `400 failed_precondition`, `detail` "Only a claimed or running task can be reassigned", `context`: `resource_type` the task type, `resource_name` `{task_1}`, `violations: [ { "type": "STATE", "subject": "STATE", "description": "task is queued" } ]` | DESIGN.md:547, :1234; G-OPS-27, G-WIRE-14 |
| target blacklisted | caller `<admin-token>`; (`{worker_a}`, `reports-7f9c-2`) is blacklisted on **reports** | `400 failed_precondition`, `violations: [ { "type": "STATE", "subject": "TARGET_BLACKLISTED", "description": "the target worker is blacklisted on this queue" } ]`, `resource_name` `{task_1}`; the current holder keeps its lease | G-OPS-27; p3 with the blacklist |

## Notes
- Preconditions (G-OPS-27): only `claimed`/`running` (else `STATE`); a task whose hand-off is still pending can be reassigned again (not a refusal: a new target, epoch +1 again, new accept window); a target blacklisted on the queue → `TARGET_BLACKLISTED`; the target's rights are not checked here, only at its accept.
- `403` carries a reason from the closed list and no field violations; `404` carries only `resource_type` and `resource_name` (G-SEC-19, G-WIRE-15).
