# After reassignment the old holder's calls get `LEASE_LOST`

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-reassignment` (PRD.md:713) · `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:722) · PRD.md:1521 · DESIGN.md:547, :1208 |
| Phase | p3 |
| Test level | E2E |

The old holder may still be working. Its heartbeat reports the lease as lost, and its completion is fenced, so it cannot overwrite the work of the new holder.

## Setup
- `{task_1}` was reassigned from `reports-7f9c-1` to `reports-7f9c-2` ([1.01](1.01-positive-admin-reassigns-running-task.md)); `{lt_1}` is the old token.

## Exchange 1 — Old holder heartbeats
```http
POST /api/task_engine/v1/tasks/heartbeat HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "session_id": "{session_1}", "leases": [ { "task_id": "{task_1}", "lease_token": "{lt_1}" } ] }
```
- `200 OK`, `results[0].outcome = "lease_lost"`; the session itself is renewed.

```json
{ "session_id": "{session_1}", "heartbeat_interval_secs": 10,
  "results": [ { "task_id": "{task_1}", "outcome": "lease_lost" } ] }
```

## Exchange 2 — Old holder tries to complete
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "lease_token": "{lt_1}", "result_code": "success", "output": {"url": "https://files.example.com/r-42.pdf"} }
```
- `409 Conflict`, `aborted`, `context.reason = "LEASE_LOST"`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.aborted.v1~",
  "title": "Aborted",
  "status": 409,
  "detail": "Lease is no longer held",
  "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>",
  "context": { "reason": "LEASE_LOST" }
}
```

## Side effects
- task {task_1} state is running (unchanged); no result is stored.
- metric te_lease_fencing_rejections_total{op="complete"} increases by 1.
