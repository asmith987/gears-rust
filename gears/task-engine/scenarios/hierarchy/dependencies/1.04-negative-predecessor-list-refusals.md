# A predecessor list over 64 entries, or naming a task twice, is rejected

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-dependencies` (PRD.md:841) · DESIGN.md:1217, :2128 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-WAI-42 |

The number of predecessors per task is bounded (`dependencies.max_predecessors_per_task`, default 64). A create with 65 is rejected as a whole. The same task listed twice is rejected too, on the second occurrence (G-WAI-42), instead of surfacing as a primary-key conflict.

## Setup
- 65 `queued` **render** tasks `{task_p01}` … `{task_p65}` in tenant A, all readable by `{creator_a}`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: join-65

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42-join", "format": "pdf" },
  "predecessors": [ { "task_id": "{task_p01}" }, { "task_id": "{task_p02}" }, "… 62 more …", { "task_id": "{task_p65}" } ]
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, field violation `DEPENDENCY_GRAPH_TOO_LARGE` on `/predecessors` (DESIGN.md:1217); no `context.reason`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "At most 64 predecessors per task",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": {
    "field_violations": [ { "field": "/predecessors", "description": "at most dependencies.max_predecessors_per_task (64) entries", "reason": "DEPENDENCY_GRAPH_TOO_LARGE" } ]
  }
}
```

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| `too_many` | (the representative request) | `400`, `DEPENDENCY_GRAPH_TOO_LARGE` on `/predecessors` | DESIGN.md:1217 |
| `exactly_64` | `{task_p01}` … `{task_p64}` | `201`, `blocked` | |
| `duplicate` | `"predecessors": [ { "task_id": "{task_p01}" }, { "task_id": "{task_p02}", "on_predecessor_failure": "ignore" }, { "task_id": "{task_p01}", "on_predecessor_failure": "ignore" } ]` | `400`, `DUPLICATE` on `/predecessors/2` | G-WAI-42; refused whatever the `on_predecessor_failure` values |

## Side effects
- `too_many`, `duplicate`: nothing changes; the request is refused before any write.
- `exactly_64`: `{task_66}` is created `blocked` with 64 `te_dependencies` rows (`outcome = pending`).

## Notes
- The graph-walk bound (`max_graph_nodes`) applies only to the cycle check of dependency additions, which no longer exist; at create it is unreachable (DESIGN.md:2638).
- The literal `"… 62 more …"` stands for 62 more entries of the same shape.
