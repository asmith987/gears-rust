# A task created with predecessors starts `blocked`, `queued` or is refused, by what its predecessors already did

Predecessors, their failure rule and the `all`/`any` mode are all given in `POST /tasks` and never change. Each live predecessor makes its link unmet; a successor with any unmet link is created `blocked`, which takes precedence over `run_after` (DESIGN.md:525), cannot be claimed, and counts as deferred. Linking a terminal predecessor is allowed: it is read from `te_task_results` and its outcome is applied at once. A `completed` predecessor counts as satisfied; a failed, cancelled or dead-lettered one counts as satisfied on an `ignore` link (G-WAI-37); and a create that could never be unblocked (for example `all` on an already failed `cancel` predecessor) is refused with `DEPENDENCY_UNSATISFIABLE` instead of producing a task that is cancelled at birth (PRD.md:839, G-WAI-36). Each link's state is shown in `predecessors[].outcome` (`pending`, `succeeded`, `failed_ignored`, `failed`). Link authorization runs first, so the caller already may read every predecessor ([1.03](1.03-guardrail-unreadable-predecessor-404.md)).

## Setup
- `{task_1}` and `{task_2}` (**render**, queue **reports**, tenant A) are `queued`; `{creator_a}` may `read` both.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: merge-r-42

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-42-merged", "format": "pdf" },
  "predecessors": [
    { "task_id": "{task_1}" },
    { "task_id": "{task_2}", "on_predecessor_failure": "cancel" }
  ],
  "dependency_mode": "all"
}
```

## Expected response
- `201 Created`, `Location: /api/task_engine/v1/tasks/{task_3}`, `state: blocked`.
- `on_predecessor_failure` defaults to `cancel` (Proposals › Task mutability); each link starts `outcome: pending` (G-WAI-37).

## Side effects
- `live`: task `{task_3}` state is `blocked`; `te_dependencies({task_3}, {task_1})` and `te_dependencies({task_3}, {task_2})` are present with `outcome = pending`, `on_predecessor_failure = cancel`, `mode = all`; `{task_3}` joins the deferred set (DESIGN.md:2609); timer `lifetime` for `{task_3}` is armed at `T0+86400s`, no `queue_timeout` timer; history of `{task_3}` gains `taskCreated` with `initial_state: blocked`; subsequent `POST /tasks/claim` on **reports** never returns `{task_3}` while it is `blocked`.
- `completed`: `te_dependencies({task_2}, {task_1})` is present with `outcome = succeeded`; history of `{task_2}` gains `taskCreated` with `initial_state: queued`; `{task_2}` joins the queued set, not the deferred set.
- `failed_cancel_all`: none — the transaction rolls back (no task, dedup row, counter change).
- `failed_ignore_all`: `te_dependencies({task_3}, {task_1})` is present with `outcome = failed_ignored`, `on_predecessor_failure = ignore`; `({task_3}, {task_2})` with `outcome = pending`; `{task_3}` joins the deferred set.

## Notes
- Storage follows G-WAI-37: `te_dependencies.on_predecessor_failure_code` and `outcome_code` per link (replacing DESIGN's `satisfied`, DESIGN.md:1858-1866).
- An omitted `dependency_mode` is `all` (G-WAI-40).
- `completed`: DESIGN.md:2655 inserts `queued | scheduled | blocked` from the plan; that a fully satisfied set yields `queued` follows from PRD.md:258 ("blocked if it has unmet predecessors"). A terminal predecessor lives in the history ring; once retention removes it, naming it gets `404` like a missing task.
- `failed_cancel_all`: `DEPENDENCY_UNSATISFIABLE` is the decided subject (G-WAI-36); the violation names no field, so the failing link is only in `description`. With `any` mode the same create is accepted while `{task_2}` is live; it is rejected only when every `cancel` predecessor has already failed.
- `failed_ignore_all`: if `{task_1}` were the only predecessor, `{task_3}` would be created `queued`; an `ignore` link counts the failure as satisfied at create as in the cascade (G-WAI-37).
