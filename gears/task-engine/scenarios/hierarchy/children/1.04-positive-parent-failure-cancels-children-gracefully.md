# A parent that fails cancels its unfinished children gracefully

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-parent-child` (PRD.md:826) · DESIGN.md:551, :2951-2956 |
| Phase | p2 |
| Test level | Both — E2E for the response and the immediate child outcomes; integration for the grace expiry (clock) |
| Gaps | G-WAI-38, G-WAI-23 |

A parent with `propagate_cancel: true` that ends in any non-success terminal state (failed, dead-lettered, timed out) cancels its unfinished children through the children cascade in `graceful` mode (G-WAI-38). Nothing will consume their results, so they are stopped; a leased child gets a graceful request and the grace period to finish. A parent that ends successfully cascades nothing, and `propagate_cancel: false` opts out. DESIGN.md:2955 still runs the cascade only for `cancelled`; G-WAI-38 extends it.

## Setup
- `{task_1}` (**render**, queue **reports**, tenant A, `propagate_cancel: true`, `wait_for_children: false`) is `running` under `{worker_a}` with `{lt_1}`, `retry_count` 3 (budget used up). Clock T0+5m.
- Its children `{task_2}` (`running` under `reports-7f9c-2` with `{lt_2}`) and `{task_3}` (`queued`).

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "RENDER_TIMEOUT",
    "message": "renderer timed out",
    "fault": "dependency",
    "retryable": true
  }
}
```

## Expected response
- `200 OK`, task resource: `state: dead_lettered` (retries exhausted, **reports** has DLQ **dead_letter**), `result.result_code: error`.

```json
{
  "id": "{task_1}",
  "state": "dead_lettered",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1",
  "dead_lettered_from": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Cases

| Case | Setup differs | Request differs | Expected for the parent | Expected for the children |
|---|---|---|---|---|
| `dead_lettered_cascades` | (the representative Setup) | (the representative request) | `200 dead_lettered` | `{task_3}` `cancelled` / `cancelled` at once; `{task_2}` stays `running` with `cancel_requested: true` and a `cancel_grace` timer; side effects below |
| `opt_out` | parent created with `propagate_cancel: false` | (the representative request) | `200 dead_lettered` | `{task_2}` unchanged (`running`, `cancel_requested: false`, `{lt_2}` valid); `{task_3}` unchanged (`queued`); no `cascade` timer |
| `success_no_cascade` | `retry_count` 0 | `{ "lease_token": "{lt_1}", "result_code": "success", "output": { "url": "https://files.example.com/r-42.pdf" } }` | `200 completed` | `{task_2}` and `{task_3}` unchanged; a successful parent cascades nothing (G-WAI-38) |

## Side effects (case `dead_lettered_cascades`)
- task `{task_1}` state is `dead_lettered`.
- task `{task_3}` state is `cancelled`, result_code `cancelled`, in the same transaction; history of `{task_3}` gains `taskCancelled` with `mode: graceful` and no `actor`; `{task_3}` leaves the queued set.
- task `{task_2}` state is `running`, `cancel_requested` is true, `cancel_request.mode` is `graceful`; lease `{lt_2}` is still valid; history of `{task_2}` gains `taskCancelRequested` with `mode: graceful` and no `actor`.
- timer `cancel_grace` for `{task_2}` is armed at T0+5m+60s (`cancel_grace_period_secs` 60, DESIGN.md:551).
- If `{task_2}` has not ended by then: task `{task_2}` state is `cancelled`, result_code `forcibly_cancelled`; lease `{lt_2}` is invalid (later calls get LEASE_LOST).
- If `{task_2}`'s worker acknowledges first with `complete` `result_code: cancelled`, it ends `cancelled` and the `cancel_grace` timer is removed (CONVENTIONS §5.5).

## Notes
- The same holds for a parent that ends `failed` (no DLQ) or `timed_out` (G-WAI-38). A forced cancel of the parent stays forced for the children ([1.03](1.03-positive-parent-cancel-cascade-to-children.md)).
- An admin re-enqueue of `{task_1}` later finds its children in whatever state they reached; re-enqueueing one of the cancelled children is refused while `{task_1}` is terminal (`400` `PARENT_FINISHED`, G-WAI-24, home in `dead-letter/`).
