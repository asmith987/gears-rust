# A child whose queue is in another task domain does not find its parent (`404`)

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-parent-child` (PRD.md:826) · PRD.md:1182, :1506 · DESIGN.md:730, :1223, :2637 |
| Phase | p3 |
| Test level | Integration — p3 domains |
| Gaps | G-WAI-41, G-WIRE-15 |

A parent and its children must live in one task domain, because the child insert, the parent lock and the children cascade are one database transaction (PRD.md:1182). A create looks up linked tasks only in the new task's domain, which its queue decides. A child routed to a queue of another domain therefore does not find its parent there and gets the same `404` as a missing parent; there is no cross-domain probe and no separate code (G-WAI-41).

## Setup
- Task domains configured: **reports** is in domain `default`; a queue `gts.cf.core.tasks.queue.v1~acme.reports._.archive.v1` (**archive**, defined here) is routed to domain `archive-db`. `{worker_a}` has `create` on **render** in both queues.
- `{task_1}` (**render**, queue **reports**, tenant A) is `running` under `{worker_a}` with `{lt_1}`.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json
Idempotency-Key: child-cross-domain-1

{
  "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.archive.v1",
  "input": { "report_id": "r-42-archive", "format": "pdf" },
  "parent_task_id": "{task_1}",
  "parent_lease_token": "{lt_1}"
}
```

## Expected response
- `404 Not Found`, `not_found`, the same body as [1.05](1.05-guardrail-child-link-refusals.md) (`resource_type` and `resource_name` only, no field violation, G-WIRE-15), even though the caller holds the parent's current lease.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.not_found.v1~",
  "title": "Not Found",
  "status": 404,
  "detail": "Parent task not found",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}" }
}
```
