# A search not narrowed to one domain merges all domains with a stable cursor

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-task-domains` (PRD.md:1186) · `cpt-cf-task-engine-fr-search` · PRD.md:1508 · ADR-0010:64, :73 · DESIGN.md:2817-2844 |
| Phase | p3 |
| Test level | Integration — p3 multi-domain deployment / moves |
| Gaps | G-RTY-10, G-SEC-26 |

A read that is filtered neither by queue nor by a type with a type rule covers every domain. The engine merges the domains' results in sort order, and the cursor carries per-domain positions, so the next page continues each domain where it stopped even while tasks are being created.

## Setup
- Domains `heavy` (queue **heavy**) and `default`.
- Tenant A tasks, all `queued`, by `created_at`: `{task_1}` T0-5m (**reports**), `{task_2}` T0-4m (**heavy**), `{task_3}` T0-3m (**reports**), `{task_4}` T0-2m (**heavy**).

## Exchange 1 — First page
```http
GET /api/task_engine/v1/tasks?$filter=state eq 'queued'&$orderby=created_at asc&limit=2&view=short HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200 OK`: `{task_1}`, `{task_2}` (one from each domain), `next_cursor = {cursor_1}`.

```json
{ "items": [ { "id": "{task_1}", "created_at": "2026-11-03T09:55:00Z" }, { "id": "{task_2}", "created_at": "2026-11-03T09:56:00Z" } ],
  "page_info": { "next_cursor": "{cursor_1}", "prev_cursor": null, "limit": 2 } }
```

## Exchange 2 — Meanwhile `{task_5}` is created on **heavy** at `T0` (newer than all four)

## Exchange 3 — Next page
```http
GET /api/task_engine/v1/tasks?$filter=state eq 'queued'&limit=2&view=short&cursor={cursor_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```
- `200 OK`: `{task_3}`, `{task_4}`; no item repeats from page 1 and none is skipped. `{task_5}` comes on the page after.

## Notes
- Search bounds (`$orderby` keys, window, page-size caps) are in `search/`. The default `created_at` window applies to this search, since its state filter does not restrict it to unfinished states (DESIGN.md:2824) or to `dead_lettered` (G-RTY-10); all four tasks fall inside it.
- The cursor also binds `view` and `$select`: sending `view=full` with `{cursor_1}` → `400`, `FIELD_SELECTION_MISMATCH` on `cursor` (G-SEC-26).
