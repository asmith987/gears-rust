# Config overrides set concurrency limits by GTS pattern; the most specific pattern wins

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-concurrency-overrides` (PRD.md:471-478) · DESIGN.md:2212-2215 · `schemas/types/gts.cf.core.tasks.queue.v1~.schema.json` (description) |
| Phase | p2 |
| Test level | Integration — GTS-pattern override config matrix |
| Gaps | G-CLM-09, G-CLM-10, G-CLM-21, G-OPS-12 |

Operators override the concurrency limits of queues and types in the engine config with GTS patterns and wildcards; the most specific matching pattern wins, and an override wins over the queue registration.

## Setup
- Engine config at startup:
  ```yaml
  concurrency_overrides:
    - pattern: "gts.cf.core.tasks.queue.v1~acme.reports.*"
      per_tenant_concurrency_limit: 2
    - pattern: "gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1"
      per_tenant_concurrency_limit: 1
  ```
  Effective per-tenant limits: **reports** 2 (wildcard; registration says 5), **bulk** 1 (exact ID).
- `{tenant_a}`: **bulk** 1 task `claimed` + 1 `queued`; **reports** 1 task `claimed` + 2 `queued`.

## Exchange 1 — claim from **bulk**
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-2", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1"], "max_tasks": 1, "timeout_secs": 0 }
```
- `429` (quota subject `concurrency`, `Retry-After: 1`): limit 1 from the exact ID, not 2 from the wildcard.

## Exchange 2 — claim from **reports**, `max_tasks: 2`
- `200 OK` with **one** claim (limit 2 from the wildcard: 1 held + 1), not two (registration 5).

## Exchange 3 — claim from **reports** again
- `429` (quota subject `concurrency`).

## Side effects
- `queue_tenant(reports, {tenant_a}) used` is 2; `queue_tenant(bulk, {tenant_a}) used` is 1.

## Notes
- Specificity (G-CLM-21): an exact ID beats any pattern; among patterns the longest literal prefix before the first wildcard wins; two patterns of equal specificity that match the same queue are rejected when the config is loaded. For the same pattern a runtime (`/admin/config`) override beats the static one (G-OPS-12). Queue and type overrides are different dimensions and both apply.
- Overrides are loaded at startup. Changing a limit at runtime is [queues/3.01](../../queues/3.01-positive-runtime-config-save-is-complete-version.md).
