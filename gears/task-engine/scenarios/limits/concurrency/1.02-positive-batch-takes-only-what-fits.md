# A batch claim takes only as many tasks as the limits allow, and that is a success

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-queue-concurrency` (PRD.md:427-429) · `cpt-cf-task-engine-fr-assignment` (PRD.md:655) · DESIGN.md:2473-2475, :2495 · ADR-0008:72-73 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CLM-09, G-CLM-10 |

A batch claim reserves `+k` per counter row and lowers `k` to what is free when the full reservation does not fit (DESIGN.md:2475). If anything was assigned, the answer is `200` with fewer tasks than asked for; `429` is only for "nothing assigned".

## Setup
- **reports** (`per_tenant_concurrency_limit: 5`): `{tenant_a}` has 3 tasks `claimed` and 10 `queued`. No other tenant has work.

## Request
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-2", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.render.v1"], "max_tasks": 5, "timeout_secs": 0 }
```

## Expected response
- `200 OK` with exactly **2** claims (A's two oldest queued tasks); not `429`.

## Side effects
- `queue_tenant(reports, {tenant_a}) used changes by +2` (now 5, the limit); `queue_global(reports) used changes by +2`.
- subsequent claim by the same worker returns `429` (quota subject `concurrency`, `Retry-After: 1`), as in [1.05](1.05-negative-nothing-assignable-returns-429.md).

## Notes
- A dimension whose limit is `0` is unlimited and has no counter row (DESIGN.md:1667); on **default** the same request would return 5 claims.
