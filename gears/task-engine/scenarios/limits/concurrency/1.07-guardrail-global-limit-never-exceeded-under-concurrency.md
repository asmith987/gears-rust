# The global concurrency limit is never exceeded by concurrent claims

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-queue-concurrency` (PRD.md:427, :1491) · DESIGN.md:1593, :1615-1619, :2473-2477 · ADR-0005:79-84 · ADR-0008:73, :138 |
| Phase | p1 |
| Test level | Integration — concurrent claims |
| Gaps | G-CLM-09, G-CLM-10 |

Limits are hard upper bounds: the guarded `used + k <= limit_value` is checked inside one `UPDATE` under the row lock, so concurrent claims on any number of nodes can never together push a dimension past its limit (DESIGN.md:1617).

## Setup
- Scenario queue `gts.cf.core.tasks.queue.v1~acme.reports._.narrow.v1` (**narrow**): like **reports** but `global_concurrency_limit: 3`, `per_tenant_concurrency_limit: 0` (unlimited).
- **narrow** holds 10 `queued` tasks: 5 of `{tenant_a}`, 5 of `{tenant_b}`.
- Two engine nodes. Six worker processes send one claim each at the same moment: three of `{worker_a}` and three of `{worker_b}`, `max_tasks: 2`, `timeout_secs: 0`.

## Request (×6)
```http
POST /api/task_engine/v1/tasks/claim HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{ "worker_id": "reports-7f9c-1", "session_id": null,
  "queues": ["gts.cf.core.tasks.queue.v1~acme.reports._.narrow.v1"], "max_tasks": 2, "timeout_secs": 0 }
```

## Expected response
- The total number of claims across all six responses is at most **3** (expected exactly 3).
- Every response without a claim is `429` with quota subject `concurrency` and `Retry-After: 1` (eligible tasks remain; they were skipped for capacity).

## Side effects
- Exactly 3 tasks of **narrow** are `claimed`; 7 stay `queued`.
- `queue_global(narrow) used` is 3 (never more at any instant; sample `GET /tasks/count?$filter=queue eq '…narrow.v1' and state eq 'claimed'` during the run).
- No `40P01` / `1213` deadlock surfaces as an error (ADR-0008:142).

## Notes
- Repeat with claims, completions and releases mixed, and with counter reconciliation running (PRD.md:1545, ADR-0005:86), on every backend.
- `reports-7f9c-1` … `-3` and `reports-b-1` … `-3` are the six `worker_id`s; the `-3`/`b-2`/`b-3` ones are scenario-local.
