# Engine moves and re-entries are never refused by depth or deferred limits

Engine-driven moves never strand admitted work (PRD.md:453). Two kinds are never refused, whatever the counts:

- **Re-entries** into `scheduled` or `queued` of work that was already admitted (DESIGN.md:559): a retry after a reported retryable failure, a liveness requeue after a session expires (DESIGN.md:2788), and a release without delay ("A release without a delay is never refused by queue depth limits", PRD.md:689). A running task holds no queue-depth capacity, so a full queue must not trap a worker that wants to hand a task back.
- **Hand-overs** out of a deferred state into `queued` (DESIGN.md:560): `scheduled` → `queued` when `run_after` is reached, `waiting` → `queued` when the wait is satisfied (DESIGN.md:533: "hand-over, never refused"), `blocked` → `queued` when the predecessors succeed. The task was admitted when it was deferred.

The limit may be passed for a short time; for retries by at most the work claimed within one maximum retry backoff.

## Setup (representative case: retry with the deferred limit full)
- Engine config: `tenant_max_deferred_tasks: 2`. `{tenant_a}` has 2 `scheduled` tasks, sampled.
- `reports-7f9c-1` holds `{task_1}` (**reports**, `running`, `{lt_1}`, `retry_count: 0`).

## Request
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "RENDER_TIMEOUT",
    "message": "renderer timed out",
    "fault": "dependency",
    "retryable": true
  }
}
```

## Expected response
- `200 OK`, task `state: scheduled`, `retry_count: 1`; not `429`.

## Cases

Rows "retry" and "liveness requeue" fill the **deferred** limit (`tenant_max_deferred_tasks: 2`, 2 `scheduled` tasks, sampled). The other rows fill the **queue depth** (`tenant_max_queue_depth: 3` for **reports**, `{tenant_a}` has 3 `queued` tasks there). In every row the setup waits until the queue's `sampled_at` is later than its creates (G-CLM-13).
