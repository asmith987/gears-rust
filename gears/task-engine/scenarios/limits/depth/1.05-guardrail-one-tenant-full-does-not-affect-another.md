# One tenant at its depth limit never affects another tenant

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-queue-depth` (PRD.md:455) · DESIGN.md:2376 |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › Limits and counters › Per-tenant depth from periodic counts |
| Gaps | G-CLM-10, G-CLM-13 |

Per-tenant counts are per tenant, so one tenant cannot use another's capacity (PRD.md:455). With sampled counts this still holds: each tenant is compared with its own sample.

## Setup
- Engine config: `tenant_max_queue_depth: 3` for **reports**; queue-wide and domain-wide limits far away.
- `{tenant_a}` has 3 `queued` tasks in **reports**; the queue's `sampled_at` is later than these creates (G-CLM-13), so A's creates now get `429` `queue_depth.tenant`. `{tenant_b}` has none.

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-b-token>
Content-Type: application/json
Idempotency-Key: 2f90-depth-b-1

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "b-1", "format": "pdf" } }
```

## Expected response
- `201 Created`, task `queued`, `owner_tenant_id: {tenant_b}`.

## Side effects
- `{tenant_b}` has 1 `queued` task in **reports**; `{tenant_a}`'s tasks are unchanged.
- history of the new task gains `taskCreated`.
