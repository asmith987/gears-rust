# A depth limit of `0` means unlimited

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-queue-depth` (PRD.md:447) · DESIGN.md:1667, :2175 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CLM-13 |

`0` means unlimited for every depth limit (PRD.md:447), never "no tasks allowed". An operator cannot use `0` to stop a queue; that is what the accepted queue hold is for (Proposals › Queue operations, Why).

## Setup
- Engine config override for **reports**: `tenant_max_queue_depth: 0`, `queue_max_queue_depth: 0`.
- `{tenant_a}` has 200,000 `queued` tasks in **reports** (twice the default `tenant_max_queue_depth` of 100,000), sampled: `GET /queues/{reports}` (as `{admin}`) shows a `sampled_at` later than the last setup create (G-CLM-13).

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 8d4a-unlimited-1

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-unl", "format": "pdf" } }
```

## Expected response
- `201 Created`, task `queued`.

## Side effects
- `{tenant_a}` has 200,001 `queued` tasks in **reports**.

## Notes
- `global_max_queue_depth` (default 5,000,000) still applies; the setup stays below it.
- Seeding 200,000 rows is heavy; a test may instead set the **default** values low (e.g. `tenant_max_queue_depth: 2` as the config default) and the override to `0`, and create 3 tasks.
