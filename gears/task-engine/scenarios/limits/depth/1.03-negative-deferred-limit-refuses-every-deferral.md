# Every admission into a deferred state is refused when the tenant's deferred limit is full: dimension `deferred`

`tenant_max_deferred_tasks` caps one tenant's `scheduled`, `blocked` and `waiting` tasks in a task domain (PRD.md:445). Every move into one of those states that the client or worker chooses is an admission into the deferred set and is refused with `429` (`deferred`) when that set is full; nothing changes. This covers a create that starts `scheduled` (`run_after` in the future), `blocked` (an unmet predecessor, DESIGN.md:2609) or `waiting` (an initial wait group, a deferred admission, G-CLM-26, G-CRT-01), and the worker's own deferrals: a release with `delay_secs` and parking in `waiting` (PRD.md:452). Without the limit a tenant could park or defer tasks to free queue space, create more, and later flood the queue. A refused worker keeps its lease and slot, so it can keep the task, retry later, or release it without a delay. Engine moves into `scheduled` are never refused ([1.04](1.04-guardrail-engine-moves-never-refused.md)). This folder is the home of every deferred-limit refusal.

## Setup
- Engine config: `queue_depth.tenant_max_deferred_tasks: 2`.
- `{tenant_a}` has 2 deferred tasks (in the representative case 2 `scheduled` tasks in **reports** and **bulk**, `run_after` = `T0+3600s`, created at `T0`). The test waits until `GET /queues/{reports}` (as `{admin}`) shows a `sampled_at` later than these creates, so the count is sampled (G-CLM-13).
- Worker rows: `reports-7f9c-1` holds `{task_1}` of `{tenant_a}` in **reports**, `running`, token `{lt_1}`, session `{session_1}`.

## Request (representative case: create with `run_after`)
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json
Idempotency-Key: 5d1e-deferred-r-300

{ "type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "input": { "report_id": "r-300", "format": "pdf" },
  "run_after": "2026-11-03T12:00:00Z" }
```

## Expected response
- `429 Too Many Requests`, `resource_exhausted`; one violation with `subject: "queue_depth.deferred"`; no `context.reason`; no usage figures (PRD.md:455).
- `resource_type` = the task base type, no `resource_name` (G-CLM-10).
- `Retry-After` is an integer in [15, 30], equal to the violation's `retry_after_seconds` (G-CLM-09).

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/problem+json
Retry-After: 27
```
```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.resource_exhausted.v1~",
  "title": "Resource Exhausted",
  "status": 429,
  "detail": "deferred task limit reached for this tenant",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": {
    "resource_type": "gts.cf.core.tasks.task.v1~",
    "violations": [ { "subject": "queue_depth.deferred", "description": "tenant_max_deferred_tasks reached", "retry_after_seconds": 27 } ]
  }
}
```

## Cases

Every row answers `429` with the body above (`Retry-After` in [15, 30]); only `instance` changes with the endpoint.

## Side effects
- No row changes any task, counter, timer or event; metric `te_queue_depth_rejections_total{queue="…render.v1", dimension="deferred"}` increases by 1 per refusal.

## Notes
- The deferred limit is checked against the sampled count like the queued limit (Proposals › Limits and counters › Per-tenant depth from periodic counts), so the setup waits until `sampled_at` passes its creates. A refused delayed release keeps its lease and the task stays `running` (G-EXE-23). `Retry-After: 27` is one draw from [15, 30]; tests assert the range (G-CLM-09, G-SEC-03).
- `resource_type` is the task base type and `resource_name` is omitted: the deferred limit is per tenant and domain, not per queue (G-CLM-10, G-WIRE-14).
- Arming a wait group (`park: false`) does not count against the deferred limit (DESIGN.md:813); the same refusal happens later at `park`.
- DESIGN.md:558 and :2609 do not yet list a create into `waiting` among the admissions; the decision adds it (G-CLM-26).
