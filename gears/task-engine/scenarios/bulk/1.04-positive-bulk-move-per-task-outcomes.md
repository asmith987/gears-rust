# Bulk move takes unleased tasks to another queue of the same domain and refuses the rest per task

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-bulk-ops` (PRD.md:1162) · `cpt-cf-task-engine-fr-task-domains` (PRD.md:1180) · DESIGN.md:715, :756, :1117, :1121, :1224, :1234 · Proposals › Domains › Fixed domain |
| Phase | p2 (p3 for the cross-domain case) |
| Test level | E2E |
| Depends on | Proposals › Domains › Queue-move model (a task's domain is fixed at creation) for the cross-domain case |
| Gaps | G-OPS-17, G-OPS-19, G-OPS-20, G-OPS-21, G-CLM-25, G-CRT-02, G-CRT-03 |

An operator drains **reports** into **bulk**. Unleased tasks (`queued`, `scheduled`, `blocked`) move at once and take the destination's queue-level settings; each is admitted against the destination's depth limits, and a task refused for depth is reported `limit_exceeded` while the others move (G-CLM-25). A move never takes a task from its worker: no lease is invalidated and nothing is requeued mid-flight. Rows never move between databases, so a task whose domain differs from the destination's is reported `domain_mismatch` (G-OPS-21).

## Setup
- **reports** and **bulk** are both in the `default` domain; **bulk** uses `tenant_fairness: fifo` and has no DLQ.
- `{task_1}` `queued`, `{task_2}` `scheduled` (`run_after = T0+5m`), `{task_3}` `blocked` on `{task_10}`. All tenant A, on **reports**, created without request-level `retry_policy`.

## Request
```http
POST /api/task_engine/v1/tasks/bulk/move HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "task_ids": ["{task_1}", "{task_2}", "{task_3}"], "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1" }
```

## Expected response
- `200 OK`, all `succeeded`.

```json
{ "results": [
  { "task_id": "{task_1}", "outcome": "succeeded" },
  { "task_id": "{task_2}", "outcome": "succeeded" },
  { "task_id": "{task_3}", "outcome": "succeeded" }
] }
```

## Side effects
- For the representative: task {task_1}.queue advances from **reports** to **bulk**; same for {task_2} and {task_3}. States are unchanged.
- history of {task_1} gains taskUpdated with `actor: "{admin}"`, `changes.queue` **reports** → **bulk**; same for {task_2} and {task_3} (G-OPS-19).
- Settings are resolved again with **bulk** as the queue: queue-level values (here all of them, since no request-level or type-level values were set) become **bulk**'s; request-level and type-level values would be kept (G-OPS-20). Each moved task's effective `retry_policy` is **bulk**'s; a later terminal failure ends `failed`, not `dead_lettered`, because **bulk** has no DLQ.
- timer queue_timeout for {task_1} is armed at T0+3600s (re-armed from the move, G-OPS-20).
- {task_1} is now served in **bulk**'s `fifo` order and counts against **bulk**'s concurrency limits when claimed.
- {task_1} leaves the queued set of **reports** and joins that of **bulk**; {task_2} and {task_3} move from **reports**' deferred set to **bulk**'s.
- Refused tasks are unchanged and gain no event.

## Notes
- DESIGN.md:715 (store the resolved result) and DESIGN.md:1121 (adopt the destination's retry policy) are reconciled by G-OPS-20: a move re-runs resolution with the destination, keeping request-level values (stored as sent) and type-level values above the queue level.
- A cross-domain destination is a per-task `domain_mismatch` (G-OPS-21), not the whole-request `400 TASK_DOMAIN_MISMATCH` of DESIGN.md:1224, because the tasks of one request may sit in different domains.
- Authorization outcomes (per-task `unauthorized` / `not_found`, `403 ACTION_DENIED` on an outright denial) are as in [1.01](1.01-positive-bulk-cancel-per-task-outcomes.md) (G-OPS-14).
- The destination is one queue for the whole request, so an unregistered or `dead_letter` destination refuses the whole request (`404` / `400 DEAD_LETTER_QUEUE`), not a task (G-CRT-02, G-CRT-03).
