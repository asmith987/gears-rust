# Bulk cancel authorizes and applies each task on its own and reports one outcome per task

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-bulk-ops` (PRD.md:1156-1163) · `cpt-cf-task-engine-fr-task-cancel` (PRD.md:344-352) · `cpt-cf-task-engine-fr-authz` no existence oracle (PRD.md:918) · PRD.md:1497 · DESIGN.md:550, :551, :1016, :1114, :1119, :1199 |
| Phase | p2 |
| Test level | Both — E2E per-state outcomes; integration per-task authz rows |
| Gaps | G-OPS-14, G-OPS-16, G-WIRE-08, G-WIRE-12 |

A tenant user cancels several tasks in one call. Each task is authorized and applied on its own, with the same rules as a single cancel, so the allowed ones are cancelled even though others are refused. The HTTP status is `200`; the outcomes are in the body, in request order (G-WIRE-12). Only a caller the PDP denies `cancel` outright gets `403` for the whole request (G-OPS-14). Per-task outcomes must not become an existence oracle: a task the caller may not read is reported exactly like a missing ID; `unauthorized` is only for tasks the caller may read but not act on.

## Setup
- `{task_1}`: `queued` on **reports**, created by `{creator_a}`.
- `{task_2}`: `queued` on **reports**, created by `{creator_a2}`. PDP lets `{creator_a}` `read` it but denies `cancel`.
- `{task_3}`: an ID that matches no task.
- `{task_4}`: `completed`, created by `{creator_a}`.

## Request
```http
POST /api/task_engine/v1/tasks/bulk/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "task_ids": ["{task_1}", "{task_2}", "{task_3}", "{task_4}"], "mode": "requested", "reason": "duplicate batch" }
```

## Expected response
- `200 OK`. One result per ID, in request order.

```json
{ "results": [
  { "task_id": "{task_1}", "outcome": "succeeded" },
  { "task_id": "{task_2}", "outcome": "unauthorized" },
  { "task_id": "{task_3}", "outcome": "not_found" },
  { "task_id": "{task_4}", "outcome": "invalid_state" }
] }
```

## Cases

Each row is one task in a bulk cancel by `{creator_a}` unless it names another caller; a test may send it alone or alongside the representative IDs.

| Case | Task (differs from the representative) | Expected outcome | Notes |
|---|---|---|---|
| cancellable queued task | `{task_1}` | `succeeded`; task {task_1} state is cancelled, result_code cancelled; history of {task_1} gains taskCancelled with `actor: "{creator_a}"`, `result_code: cancelled`; {task_1} leaves the queued set | |
| readable, cancel denied | `{task_2}` | `unauthorized`; unchanged | |
| missing ID | `{task_3}` | `not_found` | |
| foreign tenant's task | `{task_9}`: `queued` on **reports**, tenant B; `{creator_a}` cannot read it. Sent with `{task_1}` and `{task_3}`, `mode: requested` | `not_found`, the same outcome as `{task_3}` with no other field that tells them apart; {task_9} unchanged, no event recorded on it | PRD.md:918, DESIGN.md:1016 |
| terminal task | `{task_4}` | `invalid_state`; unchanged | |
| running task, `graceful` | `{task_5}`: `running` on **reports**, created by `{creator_a}`, held by `reports-7f9c-1`; request `mode: "graceful"` | `cancel_requested`: the task was only flagged. task {task_5} state is running, cancel_requested is true; timer cancel_grace for {task_5} is armed at T0+60s (`cancel_grace_period_secs`, DESIGN.md:2155); history of {task_5} gains taskCancelRequested with `mode: graceful`, `actor: "{creator_a}"`; the worker learns of it at its next heartbeat (`cancel_requested: true`). A queued task in the same `graceful` request ends at once: `succeeded`, taskCancelled | DESIGN.md:551; G-OPS-16, G-WIRE-08 |
| no `cancel` grant at all | caller `<readonly-a-token>` (`{reader_a}`: task `read` only); representative body | `403` `permission_denied`, `context.reason: "ACTION_DENIED"`, for the whole request; no per-task results; nothing changes | G-OPS-14 |

## Side effects
- Per row. Refused tasks are unchanged.

## Notes
- DESIGN.md:1236 ("Bulk per-task authorization denied → `permission_denied` 403") is removed by G-OPS-14: per-task denials are `unauthorized` / `not_found` (DESIGN.md:1119); only an outright PDP denial of `cancel` on the base type gives `403 ACTION_DENIED`.
- `succeeded` means the task ended; a leased task that was only flagged reports `cancel_requested` (G-OPS-16), as a single cancel answers `202` (CONVENTIONS §5.5, G-WIRE-08).
- Whether duplicate IDs in one request are allowed is not said.
- The size limit shared by all bulk operations is in [Bulk too large](1.05-negative-bulk-too-large.md).
