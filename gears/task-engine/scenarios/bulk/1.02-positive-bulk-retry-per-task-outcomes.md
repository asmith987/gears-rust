# Bulk retry re-enqueues `dead_lettered` and `failed` tasks one by one and refuses the rest per task

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-bulk-ops` (PRD.md:1156, :1160, :1161) · `cpt-cf-task-engine-fr-dead-letter` re-enqueue rules (PRD.md:801, :803-811) · `cpt-cf-task-engine-fr-queue-depth` admission (PRD.md:451) · DESIGN.md:545, :756, :991, :1116, :1119 |
| Phase | p2 |
| Test level | Both — E2E for the state and depth rows (use non-retryable codes to reach dead_lettered fast); integration for the authorization rows (action-level PDP policies) |
| Gaps | G-OPS-14, G-OPS-17, G-CLM-25, G-RTY-12, G-RTY-20, G-WIRE-12 |

After a downstream outage, an operator retries the failed work in one call. Each task gets the full re-enqueue: budgets reset, result cleared, context kept, lifetime restarted, back to `queued` on its source queue. Each task is authorized and applied on its own, so a refused task, including one refused by a depth limit, does not stop the others (G-CLM-25). Only an outright PDP denial of `admin` refuses the whole request (G-OPS-14). The per-task re-enqueue rules (state, dedup, supersession, depth, domain) live in [dead-letter/](../dead-letter/1.03-positive-reenqueue-dead-lettered-or-failed-task.md).

## Setup
- `{task_1}`: `dead_lettered` from **reports** (`dead_lettered_from` = **reports**), `attempt: 4`, `retry_count: 3`.
- `{task_2}`: `failed` on **bulk** (no DLQ), `attempt: 4`.
- `{task_3}`: `completed`.
- `{task_4}`: `cancelled`.

## Request
```http
POST /api/task_engine/v1/tasks/bulk/retry HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
Content-Type: application/json

{ "task_ids": ["{task_1}", "{task_2}", "{task_3}", "{task_4}"] }
```

## Expected response
- `200 OK`.

```json
{ "results": [
  { "task_id": "{task_1}", "outcome": "succeeded" },
  { "task_id": "{task_2}", "outcome": "succeeded" },
  { "task_id": "{task_3}", "outcome": "invalid_state" },
  { "task_id": "{task_4}", "outcome": "invalid_state" }
] }
```

## Side effects
- For every `succeeded` task: `retry_count` and `liveness_requeues` are 0, `attempt` is unchanged (4 in the representative), `result` is null, `dead_lettered_from` is null, `terminal_at` is null, a passed `sla_deadline` is null (a future one is kept), `context` is kept (G-RTY-12).
- Refused tasks are unchanged.

## Notes
- Single-task re-enqueue and its refusals (state, dedup, supersession, domain, parent ended) are covered in `dead-letter/`.
- DESIGN.md:1236 is removed (G-OPS-14): per-task denials are outcomes (DESIGN.md:1119); `403 ACTION_DENIED` only when the PDP denies `admin` on the base type outright.
- A depth refusal is the per-task outcome `limit_exceeded` (G-CLM-25, G-OPS-17); no `Retry-After` is given per task. Bulk move uses the same outcome ([1.04](1.04-positive-bulk-move-per-task-outcomes.md)).
- A task whose single re-enqueue would be refused by a precondition (`TASK_DOMAIN_MISMATCH`, `PARENT_FINISHED`, `STALE_ORDER`) is reported `invalid_state` (G-RTY-20).
