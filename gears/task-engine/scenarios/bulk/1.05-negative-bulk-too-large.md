# A bulk request over the size limit is rejected as a whole

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-bulk-ops` (PRD.md:1161) · PRD.md:1498 |
| Phase | p2 |
| Test level | E2E |
| Gaps | G-OPS-15, G-SEC-21, G-WIRE-14 |

At most `bulk_max_ids` IDs per request (default 1,000, G-OPS-15). A larger request is refused before any task is touched, so the caller can split it.

## Setup
- The body lists 1,001 task IDs `{task_1}` … `{task_1001}`, all `queued` and cancellable by `{creator_a}`.

## Request
```http
POST /api/task_engine/v1/tasks/bulk/cancel HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
Content-Type: application/json

{ "task_ids": ["{task_1}", "{task_2}", "…", "{task_1001}"], "mode": "requested" }
```

## Expected response
- `400 Bad Request`, `invalid_argument`, one field violation on `/task_ids` with reason `BATCH_TOO_LARGE`; no `context.reason`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "At most 1000 task IDs per bulk request",
  "instance": "/api/task_engine/v1/tasks/bulk/cancel",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/task_ids", "description": "1001 IDs given; the limit is 1000", "reason": "BATCH_TOO_LARGE" } ] }
}
```

## Side effects
<!-- No side effects: the request is refused before any write. -->

## Notes
- The limit is the config key `bulk_max_ids` (default 1000) and the code gets a row in DESIGN's error table (G-OPS-15); until the doc edit it is in the PRD only (PRD.md:1498).
- The same limit applies to `reprioritize`, `retry` and `move`. A 1 MiB body limit (`max_request_body_bytes`) is separate and gives `413`.
