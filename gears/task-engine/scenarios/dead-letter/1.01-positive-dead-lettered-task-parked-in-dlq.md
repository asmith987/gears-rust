# A dead-lettered task is parked in the dead-letter queue and records where it came from

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-dead-letter` (PRD.md:799, :801) · `cpt-cf-task-engine-fr-state-result-enums` (PRD.md:1036) · DESIGN.md:2938-2939, :2949-2950 · `task_dead_lettered.v1` schema |
| Phase | p2 |
| Test level | E2E — non-retryable error → DLQ at once |
| Gaps | G-SEC-11, G-SEC-15 |

When a task on a queue with a dead-letter queue ends in failure, `finalize()` sets `state = dead_lettered`, `dead_lettered_from` = the source queue, and `queue` = the DLQ (DESIGN.md:2938-2939). The state says the task ended and can be re-enqueued; the queue says where it is parked (PRD.md:801). The result code is that of the failure that sent it there.

## Setup
- `{task_1}` ran out of retries on **reports** and was dead-lettered at `T0+230s`, as in [Terminal error outcomes, exhausted-with-dlq](../retry/1.03-positive-error-without-retry-ends-failed-or-dead-lettered.md).
- `{admin}` may `read` tasks of `{tenant_a}`.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```

## Expected response
- `200 OK`.
- `state: dead_lettered`, `queue` = **dead_letter**, `dead_lettered_from` = **reports**, `result.result_code: error`, `terminal_at` set, `assignment: null`.

## Notes
- The task stays in the database of the domain of **reports**; the **dead_letter** queue is not routed (PRD.md:801, :1176).
- `GET /tasks/{id}/events` shows `taskDeadLettered` with `queue`, `dead_letter_queue`, `from_queue` and `result_code: error` (`queue` added by G-SEC-11).
- A task behind a tenant barrier whose `dead_lettered_from` queue is `operated_by: platform` can be read by an operator with barrier `Ignore`; one from a tenant-operated queue cannot (G-SEC-15).
