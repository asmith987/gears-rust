`POST /admin/tasks/{id}/reenqueue` succeeds only for a `dead_lettered` or `failed` task ([1.03](1.03-positive-reenqueue-dead-lettered-or-failed-task.md)), for a caller with `admin`, and when the task can be admitted again. Every refusal rolls back: the task keeps its state, result and budgets, and nothing is published. This file is the home for every re-enqueue refusal.

- **State.** Only `dead_lettered` and `failed` can be re-enqueued; `completed` and `cancelled` cannot (PRD.md:803), and re-enqueue is defined only from those two states (DESIGN.md:545), so it must not double as a way to reset budgets of live work. An invalid transition is `failed_precondition`, violation `{ type: STATE, subject: STATE }` (DESIGN.md:1234). A child whose parent has ended cannot come back either (`PARENT_FINISHED`, G-WAI-24).
- **Permission.** Re-enqueue needs the `admin` action (PRD.md:801, DESIGN.md:1128); a caller that may read the task gets `403` `ACTION_DENIED`, one that may not gets the same `404` as a missing task (PRD.md:918, DESIGN.md:1199).
- **Admission.** In order (PRD.md:808-810, DESIGN.md:733): the dedup identity must be free, the supersede group must not have a newer order value, the queue depth must have room (re-enqueue is an admission, not a re-entry, DESIGN.md:558), and the target queue (the source queue, or the optional `queue` body field) must route to the task's domain (G-RTY-20).

## Setup
- `{task_1}`: **render** on **reports**, `completed` with result `success` at `T0+60s` (representative case; each row sets its own starting state).
- `{admin}` has `admin` on tasks of `{tenant_a}`.

## Request
```http
POST /api/task_engine/v1/admin/tasks/{task_1}/reenqueue HTTP/1.1
Host: api.example.com
Authorization: Bearer <admin-token>
```

## Expected response
- `400 Bad Request`, `failed_precondition`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.failed_precondition.v1~",
  "title": "Failed Precondition",
```

## Notes
- stale-order: if the newer task were still live it would also hold the dedup identity; the identity check runs first (PRD.md:808-809, DESIGN.md:733) and the answer is `409` as in **dedup-taken**.
- depth-full: the per-tenant check reads the latest sampled count; `Retry-After` is `retry_after_secs` (30) jittered in [15, 30] (G-SEC-03). The bulk form (`POST /tasks/bulk/retry`) reports a depth refusal per task as `limit_exceeded` (G-CLM-25, [bulk/1.02](../bulk/1.02-positive-bulk-retry-per-task-outcomes.md)). Other depth refusals live in [limits/depth](../limits/depth/1.02-negative-queue-depth-full-by-dimension.md).
- domain-mismatch: during the move (source still in the queue's domain set) the same request succeeds in `eu`. Without a body the field violation names `/queue`, the field that would pick another queue.
- A `queue` field naming an unregistered queue gets `404`, a `dead_letter` queue `400 DEAD_LETTER_QUEUE` on `/queue`, as on create (G-CRT-02, G-CRT-03, G-RTY-20). A bulk retry reports the precondition refusals of this file (`TASK_DOMAIN_MISMATCH`, `PARENT_FINISHED`, `STALE_ORDER`) per task as `invalid_state` (G-RTY-20, [bulk/1.02](../bulk/1.02-positive-bulk-retry-per-task-outcomes.md)).
