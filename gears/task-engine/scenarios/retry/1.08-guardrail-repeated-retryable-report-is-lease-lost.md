# Repeating a retryable failure report gets LEASE_LOST and spends no second retry

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retry` (PRD.md:785) · `cpt-cf-task-engine-fr-lease-fencing` (PRD.md:722) · DESIGN.md:574, :576, :734, :736, :1208 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-EXE-16, G-RTY-05 |

A worker whose `complete` response was lost sends the same retryable failure again. The first call already moved the task to `scheduled` and cleared the lease token (DESIGN.md:574). Idempotent completion replay applies only when the task is **terminal** with the same token (DESIGN.md:736), so the repeat gets `409 LEASE_LOST`, and `retry_count` stays at 1. The engine keeps no replay state for non-terminal reports; the SDK treats this `LEASE_LOST` as "already applied" (G-RTY-05, G-EXE-16).

## Setup
- Run [1.01](1.01-positive-retryable-error-schedules-retry.md); the worker did not receive its response. `{task_1}` is `scheduled`, `retry_count: 1`.

## Request
At `T0+31s`, byte-for-byte the request of 1.01:
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "RENDER_TIMEOUT",
    "message": "renderer timed out",
    "fault": "dependency",
    "retryable": true
  }
}
```

## Expected response
- `409 Conflict`, `aborted`, `context.reason = "LEASE_LOST"`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.aborted.v1~",
  "title": "Aborted",
  "status": 409,
  "detail": "lease is no longer held",
  "instance": "/api/task_engine/v1/tasks/{task_1}/complete",
  "trace_id": "<trace>",
  "context": { "resource_type": "gts.cf.core.tasks.task.v1~", "resource_name": "{task_1}", "reason": "LEASE_LOST" }
}
```

## Notes
- Decided (G-RTY-05, G-EXE-16): the repeat gets `LEASE_LOST` and this is documented. The SDK, after its own retryable failure or release whose response was lost, treats `LEASE_LOST` as applied: a debug log, no `lease.lost` signal, no retry (DESIGN.md:703). Terminal completions stay replayable ([idempotent completion replay](../worker/fencing/1.02-positive-idempotent-completion-replay.md)).
- SDK-side handling is an integration test of the SDK; this E2E scenario checks only the wire answer.
