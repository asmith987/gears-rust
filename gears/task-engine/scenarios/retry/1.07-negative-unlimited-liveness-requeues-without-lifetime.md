# Unlimited liveness requeues are refused without a lifetime timeout, and always for tenant-owned types

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-type-trust` (PRD.md:1010) · `cpt-cf-task-engine-fr-retry` (PRD.md:786) · DESIGN.md:715, :2196, :2201 |
| Phase | p1 |
| Test level | E2E |
| Gaps | G-CRT-05, G-RTY-06 |

`max_liveness_requeues: 0` is unlimited, "bounded only by the lifetime timeout" (PRD.md:786). Unlimited is above any numeric cap (G-RTY-06), so it is allowed only for platform types, and only when an effective lifetime timeout bounds it. The representative case is a platform type on a queue with no lifetime: nothing bounds the requeues, so the create is refused `400` naming the setting (PRD.md:1010).

## Setup
- The **default** queue has `lifetime_timeout_secs: null` (`schemas/instances/…default.v1.json`); **cleanup** and **render** declare no `timeouts` trait.
- **relay** queue `gts.cf.core.tasks.queue.v1~acme.reports._.relay.v1`: like **reports**, but `retry_policy.max_liveness_requeues: 0` and `lifetime_timeout_secs: 86400` (allowed at registration because it has a lifetime).

## Request
```http
POST /api/task_engine/v1/tasks HTTP/1.1
Host: api.example.com
Authorization: Bearer <platform-worker-token>
Content-Type: application/json
Idempotency-Key: 5e2c-cleanup-a

{
  "type": "gts.cf.core.tasks.task.v1~cf.platform._.tenant_cleanup.v1~",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.default.v1",
  "input": { "tenant_id": "{tenant_a}" },
  "retry_policy": { "max_retries": 3, "max_liveness_requeues": 0, "strategy": "exponential",
                    "base_interval_secs": 5, "max_interval_secs": 300, "jitter_factor": 0.2, "non_retryable_codes": [] }
}
```

## Expected response
- `400 Bad Request`, `invalid_argument`, a field violation on `/retry_policy/max_liveness_requeues`.

```json
{
  "type": "gts://gts.cf.core.errors.err.v1~cf.core.err.invalid_argument.v1~",
  "title": "Invalid Argument",
  "status": 400,
  "detail": "max_liveness_requeues 0 (unlimited) requires a lifetime timeout",
  "instance": "/api/task_engine/v1/tasks",
  "trace_id": "<trace>",
  "context": { "field_violations": [ { "field": "/retry_policy/max_liveness_requeues",
      "description": "0 (unlimited) is allowed only together with a lifetime timeout", "reason": "TRUST_LIMIT" } ] }
}
```

## Notes
- A queue or type that declares `0` without a lifetime timeout is rejected when it is registered or configured (G-RTY-06); that refusal is not part of the create path and is not shown here.
