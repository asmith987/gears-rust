# A reported error that cannot be retried ends the task, dead-lettered with a DLQ and failed without one

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-retry` (PRD.md:781, :785, :792) · `cpt-cf-task-engine-fr-dead-letter` (PRD.md:801) · `cpt-cf-task-engine-fr-timeouts` terminal rule (PRD.md:524) · `cpt-cf-task-engine-usecase-retry` (PRD.md:1471) · DESIGN.md:536-538, :1381, :2938-2939, :2942 · queue schema `non_retryable_codes` · PRD.md:1484 |
| Phase | p1 (dead-letter routing p2) |
| Test level | E2E |
| Gaps | G-SEC-11 |

A reported error is retried only if the worker marks it `retryable` **and** its code is not in `non_retryable_codes` (PRD.md:781) **and** budget is left (`retry_count < max_retries`, DESIGN.md:538). Otherwise the terminal rule applies (PRD.md:524, :792): on a queue with a DLQ the task is dead-lettered, on a queue without one it ends `failed`; the result code is `error` either way (PRD.md:1036).

The representative case: **reports** lists `INVALID_REPORT`, so the failure is terminal although budget remains, and **reports** has a DLQ.

## Setup
- `{task_1}`: **render** on **reports** (retry as in [1.01](1.01-positive-retryable-error-schedules-retry.md): `max_retries: 3`, `non_retryable_codes: ["INVALID_REPORT"]`, DLQ **dead_letter**), `retry_count: 0`, running under `{lt_1}` (`attempt: 1`).
- **bulk** (`gts.cf.core.tasks.queue.v1~acme.reports._.bulk.v1`) has no DLQ and the same retry policy as **reports**.

## Request
At `T0+30s`:
```http
POST /api/task_engine/v1/tasks/{task_1}/complete HTTP/1.1
Host: api.example.com
Authorization: Bearer <worker-a-token>
Content-Type: application/json

{
  "lease_token": "{lt_1}",
  "result_code": "error",
  "error": {
    "domain": "acme.reports",
    "code": "INVALID_REPORT",
    "message": "report r-42 has no sections",
    "fault": "task",
    "retryable": true
  }
}
```

## Expected response
- `200 OK`, `state: dead_lettered`, `queue` = **dead_letter**, `dead_lettered_from` = **reports**, `retry_count: 0`.
- `result.result_code: error` with the reported error (PRD.md:1036).

```json
{
  "id": "{task_1}",
  "state": "dead_lettered",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1",
  "dead_lettered_from": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "retry_count": 0,
  "attempt": 1,
  "result": { "result_code": "error", "output": null,
              "error": { "domain": "acme.reports", "code": "INVALID_REPORT", "message": "report r-42 has no sections", "context": null, "fault": "task", "retryable": true },
              "warnings": [] },
  "terminal_at": "2026-11-03T10:00:30Z",
  "…": "other fields as in CONVENTIONS §5.1"
}
```

## Side effects
- Every case: no `taskRetrying` is recorded; `queue_global(<queue>)` and `queue_tenant(<queue>, tenant_a)` concurrency used change by `-1`; timer `lifetime` for `{task_1}` is removed (finalize step 5, DESIGN.md:2942).
- Representative case: task `{task_1}` state is `dead_lettered`; result_code is `error`; history of `{task_1}` gains `taskDeadLettered` with `queue` = **dead_letter**, `dead_letter_queue` = **dead_letter**, `from_queue` = **reports**, `result_code: error`, `actor: {worker_a}` (G-SEC-11); it is published to the task-events topic. No `taskFailed`.
