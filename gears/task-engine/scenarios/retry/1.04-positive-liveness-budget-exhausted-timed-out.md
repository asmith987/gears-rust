# Running out of liveness requeues ends the task timed_out

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-heartbeat` (PRD.md:678) · `cpt-cf-task-engine-fr-retry` (PRD.md:786) · DESIGN.md:540, :2800-2804 · `task_timed_out.v1` schema |
| Phase | p1 (DLQ routing p2) |
| Test level | Integration — many lease expiries |
| Gaps | G-RTY-01, G-RTY-02 |

A lease expiry with the `max_liveness_requeues` budget used up is not requeued: the task ends with result `timed_out` through the terminal rule (PRD.md:678, DESIGN.md:540). Retry budget left does not matter.

## Setup
- `{task_1}`: **render** on **reports**, created at `T0` with
  `"retry_policy": { "max_retries": 3, "max_liveness_requeues": 2, "strategy": "exponential", "base_interval_secs": 5, "max_interval_secs": 300, "jitter_factor": 0.2, "non_retryable_codes": [] }`.
- Two attempts already ended by session expiry: `liveness_requeues: 2`, `retry_count: 0`.
- Attempt 3 is `running` under `{lt_3}` in session `{session_3}` of `reports-7f9c-1`; its last heartbeat was at `T0+300s`, so `lease_until = T0+330s`. The process then dies.

## Exchange 1 — the session scan runs (no request)
At `T0+331s` the session scan expires `{session_3}` and runs `liveness_failure` for `{task_1}` (DESIGN.md:2759). The budget check `liveness_requeues < max_liveness_requeues` fails (2 < 2 is false), so it calls `finalize(timed_out, dlq_or_failed)` (DESIGN.md:2802).

## Request
At `T0+332s`:
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, `state: dead_lettered`, `result.result_code: timed_out`, `queue` = **dead_letter**, `dead_lettered_from` = **reports**, `liveness_requeues: 2`, `retry_count: 0`, `attempt: 3`.

```json
{ "id": "{task_1}", "state": "dead_lettered",
  "queue": "gts.cf.core.tasks.queue.v1~cf.core.tasks.dead_letter.v1",
  "dead_lettered_from": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
  "attempt": 3, "retry_count": 0, "liveness_requeues": 2,
  "result": { "result_code": "timed_out", "output": null, "error": null, "warnings": [] },
  "terminal_at": "2026-11-03T10:05:31Z", "…": "other fields as in CONVENTIONS §5.1" }
```

## Side effects
- task `{task_1}` state is `dead_lettered`; result_code is `timed_out`.
- lease `{lt_3}` is invalid (later calls get LEASE_LOST); `queue_global(reports)` and `queue_tenant(reports, tenant_a)` concurrency used change by `-1`.
- history of `{task_1}` gains `taskDeadLettered` (`result_code: timed_out`, `from_queue` **reports**, no `actor`) and `taskTimedOut` with `timeout_type: heartbeat`, `result_code: timed_out` (G-RTY-02); both are published.
- Blacklist (p3): the expiry still counts as one liveness failure for `reports-7f9c-1` on **reports** (DESIGN.md:2804).

## Notes
- `timeout_type` mapping (G-RTY-02): a session expiry gives `heartbeat`; an assignment deadline or an expired hand-off gives `assignment`. If attempt 3 had instead missed its assignment deadline, or been a reassignment that was never accepted, the outcome is the same with `timeout_type: assignment` (DESIGN.md:540).
- The transition table (DESIGN.md:540) is authoritative; the state diagram (DESIGN.md:466-513) gains the missing `claimed`/`running` → `dead_lettered`/`failed` edge (G-RTY-01).
