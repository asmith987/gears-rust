# A queue or lifetime timeout ends the task timed_out, dead-lettered with a DLQ and failed without one

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-timeouts` (PRD.md:517, :521, :524, :526) · DESIGN.md:524, :538, :541, :543, :561, :2733-2734, :2942 · `task_timed_out.v1`, `task_failed.v1` schemas · PRD.md:1515 |
| Phase | p1 (DLQ routing p2) |
| Test level | Both — E2E with 1–2 s per-task timeouts |
| Depends on | Proposals › Queue operations › Admin queue hold — cases **lifetime-on-held-queue** and **queue-timeout-on-held-queue** only |
| Gaps | G-RTY-08, G-OPS-07 |

The queue timeout and the lifetime timeout are timer-wheel rows. When one fires, the timer wheel calls `finalize(timed_out, dlq_or_failed)` (DESIGN.md:2733-2734): the task ends with result `timed_out` through the terminal rule (PRD.md:524), dead-lettered on a queue with a DLQ, else `failed`.

- The **queue** timeout ends a task that waited in `queued` too long (PRD.md:517).
- The **lifetime** timeout is measured from creation and ends the task "even if retries remain" (PRD.md:521). It overrides retry and lease handling (DESIGN.md:543) and fires whatever state the task is in.
- Both keep firing while the queue is held: held time counts (G-OPS-07, G-RTY-08).

Representative case: the lifetime fires while the task waits for a retry.

## Setup
- `{task_1}`: **render** on **reports**, created at `T0` with `"timeouts": { "lifetime_timeout_secs": 120 }`; timer `lifetime` for `{task_1}` is armed at `T0+120s`.
- Claimed at `T0+1s`, started at `T0+2s` with `{lt_1}`; at `T0+117s` it completes with the retryable `RENDER_TIMEOUT` error of [the retry scenario](../retry/1.01-positive-retryable-error-schedules-retry.md): `state: scheduled`, `retry_count: 1` of 3, `run_after` in `[T0+121s, T0+122s]`.

## Exchange 1 — the lifetime timer fires (no request)
At `T0+120s`, while the task is `scheduled`, the `lifetime` timer calls `finalize(timed_out, dlq_or_failed)` (DESIGN.md:2734).

- Representative case: timer `scheduled` for `{task_1}` is removed and never fires; timer `lifetime` is completed; the task leaves tenant A's deferred set; history of `{task_1}` gains `taskTimedOut` (`timeout_type: lifetime`) and `taskDeadLettered` (`result_code: timed_out`, no `actor`); both are published.

## Notes
- Held queues: timers keep firing and held time counts toward the queue timeout, because a queue timeout measures staleness (PRD.md:517). This reverses the proposal's leaning; decided in G-OPS-07 / G-RTY-08. An operator holding a queue longer than its queue timeout gets `timed_out` tasks.
- Lifetime after unlimited liveness requeues: [retry 1.05](../retry/1.05-positive-unlimited-liveness-requeues-end-at-lifetime.md). Lifetime and session expiry both due: [1.06](1.06-guardrail-concurrent-deadline-detectors-act-once.md).
