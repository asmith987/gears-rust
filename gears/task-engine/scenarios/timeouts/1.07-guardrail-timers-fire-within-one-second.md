# Deadlines fire no earlier than due and within one second after

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-nfr-timer-accuracy` (PRD.md:1258-1262) · `cpt-cf-task-engine-fr-timeouts` (PRD.md:528) · DESIGN.md:806, :2082 · ADR-0003:39, :77 · PRD.md:1477-1478 |
| Phase | p1 |
| Test level | Integration — timer precision |
| Gaps | G-RTY-09, G-EXE-10 |

This guardrail fixes how timeout scenarios measure time. Under normal load every deadline fires within 1 s of its due time (PRD.md:1260), and never before it. Durable timers come from the timer wheel; assignment, execution and session deadlines come from scans that run every `lease_scan_interval_ms` (1000, DESIGN.md:2082).

## Setup
- A controllable clock and a test hook that runs the timer wheel and both scans on demand, plus a soak run on real time.
- `{task_1}`: **render** on **bulk**, created at `T0`, unclaimed; timer `queue_timeout` due at `T0+3600s`.
- `{task_2}`: **render** on **reports**, claimed at `T0+1s`, so `execution_deadline = T0+901s` (set by the claim, G-EXE-10).

## Exchange 1 — just before due
At `T0+3599.9s` (all loops run): `GET /tasks/{task_1}` → `state: queued`. At `T0+900.9s`: `GET /tasks/{task_2}` → `state: running`.

## Exchange 2 — just after due
At `T0+3601s`:
```http
GET /api/task_engine/v1/tasks/{task_1} HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200 OK`, `state: failed`, `result.result_code: timed_out`, `terminal_at` in `[T0+3600s, T0+3601s]`.
- Likewise `{task_2}` at `T0+902s`: `state: dead_lettered`, `terminal_at` in `[T0+901s, T0+902s]`.

## Side effects
- Each `taskTimedOut` carries a time no earlier than its due time.
- Soak run (real clock): with 100,000 active tasks holding deadlines, at least 99 % of transitions land within 1 s of due (PRD.md:1262), measured from event times; DESIGN §4.3 has no timer-lag metric (only `te_timer_channel_size`, DESIGN.md:2288), G-RTY-09.

## Notes
- Tests compare `terminal_at` (or the event time) with the due time; they do not sleep for exact amounts.
- ADR-0003:77 confirms the bound with 10,000 active timers, PRD.md:1262 with 100,000 active tasks (G-RTY-09).
