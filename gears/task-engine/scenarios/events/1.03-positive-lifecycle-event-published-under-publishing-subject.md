# A lifecycle event is published with the history's ID, the owner tenant, and the engine's publishing subject

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-event-publishing` (PRD.md:879-889) · PRD.md:1542 · DESIGN.md:875-903 · ADR-0016:79, :93, :101 · `schemas/types/…task_completed.v1~.schema.json` |
| Phase | p1 |
| Test level | Both — E2E consume from broker; integration publishing subject |
| Gaps | G-SEC-09, G-SEC-10, G-SEC-11 |

Events are published by the engine, never on behalf of the caller. The broker sees the publishing subject as producer, the task's owner tenant as tenant, the task as subject and its concrete type as subject type, and the same event ID the history holds (G-SEC-09). Until the broker can publish across a barrier (#5492), the engine enqueues no broker events for tenants behind a barrier; their history stays complete (G-SEC-10).

## Setup
- `{task_1}` (**render**, tenant A) completed by `{worker_a}` at `T0+40s`; its history entry is `{evt_5}`.
- `{te_publisher}`: the engine's root-tenant publishing subject (`event_producer.credentials`).

## Expected broker publish
- One event on topic `gts.cf.core.events.topic.v1~cf.core.tasks.task_events.v1`, produced by `{te_publisher}`:
```json
{
  "id": "{evt_5}",
  "type": "gts.cf.core.events.event.v1~cf.core.tasks.task_completed.v1~",
  "tenant_id": "{tenant_a}",
  "subject": "{task_1}",
  "subject_type": "gts.cf.core.tasks.task.v1~acme.reports._.render.v1~",
  "data": { "task_id": "{task_1}", "queue": "gts.cf.core.tasks.queue.v1~acme.reports._.render.v1",
            "actor": "{worker_a}", "result_code": "success", "attempt": 1, "resource_refs": [] }
}
```

## Side effects
- `event taskCompleted for {task_1} is published to the task-events topic`.
- The broker's `produce` checks run against `{te_publisher}`, never `{worker_a}`.

PRD.md:1542 is deferred until #5492, after which this row becomes a publish with `tenant_id = {tenant_c}` produced by `{te_publisher}` (G-SEC-10) |

## Notes
- Today's `event_broker_sdk` stamps its own `id` and a fixed `subject_type` (DESIGN.md:892-903). p1 ships `TypedEvent::event_id()` and `TypedEvent::subject_type()` (#5491, written by the Task Engine team); there is no fallback (G-SEC-09). The test needs #5491 merged.
- `data` carries no output (`url`) — the completed schema has no output field.
- Barrier row: the broker checks a publish's tenant with `BarrierMode::Respect` only until #5492 adds an opt-in `Ignore` (DESIGN.md:890), so the engine skips the publish instead of having it refused and dead-lettered (G-SEC-10).
- `data` uses `actor`, not `created_by`/`requested_by` (G-SEC-11).
