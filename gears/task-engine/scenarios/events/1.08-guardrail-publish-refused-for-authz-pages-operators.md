# A publish the broker refuses for authorization changes no task state and raises an alert

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-event-publishing` (PRD.md:889) · PRD.md:1542 · DESIGN.md:889, :2292 · ADR-0016:79, :101 |
| Phase | p1 |
| Test level | Integration — broker authz refusal + alert |
| Gaps | G-SEC-10 |

A refused publish is a deployment fault (a grant is missing), not a task error. The outbox row is dead-lettered, the task carries on, the history stays complete, and operators are paged.

## Setup
- The `produce` grant of `{te_publisher}` on `gts.cf.core.events.event.v1~cf.core.tasks.*` is removed.

## Exchange 1 — create
- `POST /tasks` by `{creator_a}` → `201`, `{task_1}` `queued`.

## Exchange 2 — claim and complete
- `{worker_a}` claims, starts and completes `{task_1}` → each `200`; `state: completed`.

## Side effects
- History of {task_1} gains `taskCreated`, `taskClaimed`, `taskStarted`, `taskCompleted`.
- `event taskCreated for {task_1} is not published`; neither is `taskCompleted`.
- `metric te_outbox_dead_letters{domain="default"}` rises (gauge) and pages operators.
- The gateway's `/readyz` stays ready.

## Notes
- The broker answers `NotAuthorizedToProduce` or `TenantIdNotAuthorized` (DESIGN.md:889). Restoring the grant does not re-send dead-lettered rows by itself; recovery is the outbox's dead-letter handling.
- Tasks of tenants behind a barrier do not reach this path: until #5492 the engine enqueues no broker events for them (G-SEC-10).
