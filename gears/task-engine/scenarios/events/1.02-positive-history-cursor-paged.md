# The history is cursor-paged with a capped page size and can be filtered by event type

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-event-history` (PRD.md:868) · PRD.md:1075 · DESIGN.md:1108, :1161, :1176 |
| Phase | p1 |
| Test level | E2E |
| Depends on | Proposals › API reads and responses › Bounded responses (accepted: `GET /tasks/{id}/events` is cursor-paged with a page-size limit and filters) |
| Gaps | G-OPS-05, G-RTY-03, G-SEC-07, G-SEC-25 |

A long-running task can collect thousands of events (progress, checkpoints, retries). Before the accepted change the endpoint returned the complete history in one response. Now the history is read in pages, a caller asking for more than the limit gets one capped page and a cursor, and a filter returns only the types the caller needs.

## Setup
- `{task_1}` has 1,200 events, of which 3 are `taskRetrying`.

## Request
```http
GET /api/task_engine/v1/tasks/{task_1}/events?limit=50 HTTP/1.1
Host: api.example.com
Authorization: Bearer <creator-a-token>
```

## Expected response
- `200`; 50 items, `page_info.next_cursor = {cursor_1}`, `page_info.limit = 50`.

<!-- No side effects: reads only. -->

## Cases

| Case | Differs from the representative request | Expected | Notes |
|---|---|---|---|
| first page | (representative) | 50 items, `next_cursor = {cursor_1}`, `limit = 50` | |
| next page | `?limit=50&cursor={cursor_1}` | the next 50 events, none repeated. Walking every page returns all 1,200 events exactly once, in order | |
| event-type filter | `?$filter=event_type eq 'taskRetrying'` | exactly the 3 `taskRetrying` events, in order; each carries the full `error` | G-RTY-03 |
| event-type list | `?$filter=event_type in ('taskCreated', 'taskRetrying')` | the `taskCreated` event and the 3 `taskRetrying` events, in order | |
| time range | `?$filter=timestamp ge 2026-11-03T10:05:00Z and timestamp lt 2026-11-03T10:06:00Z` | only the events in that minute, in order | |
| oversized limit | `?limit=5000` | 100 items, `page_info.limit = 100`, `next_cursor` set | clamped like search (DESIGN.md:1161), not refused |
| default limit | no `limit` | 25 items, `page_info.limit = 25` | REST guideline default (G-SEC-25) |
| filter changed on a cursor | `?$filter=event_type eq 'taskFailed'&cursor={cursor_1}` where `{cursor_1}` came from an unfiltered page | `400`, `invalid_argument`, violation on `cursor`, `FILTER_MISMATCH` | |
| zero limit | `?limit=0` | `400`, `invalid_argument`, field violation on `$top` (`INVALID_LIMIT`) | the ToolKit names the canonical spelling |

## Notes
- Paging follows the REST paging guideline (`guidelines/DNA/REST/QUERYING.md`) through the ToolKit OData extractor: `limit`/`cursor`, `$filter` on `event_type` (`eq`, `in`) and `timestamp`, default 25, cap 100, oldest first by event ID, no `$orderby` (G-SEC-07, G-SEC-25). `GET /queues/{id}/events` pages the same way (G-OPS-05).
