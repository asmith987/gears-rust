# An event the engine causes itself carries no actor

| | |
|---|---|
| Requirement | `cpt-cf-task-engine-fr-event-history` (PRD.md:868) · DESIGN.md:875 · `schemas/types/…task_timed_out.v1~` |
| Phase | p1 |
| Test level | E2E — short per-task queue timeout, check history actor |
| Gaps | G-SEC-11, G-WIRE-10 |

`actor` names the subject whose API or worker call caused the event. Timers, scans, retention and cascades act for the engine, so their events have no actor, and nothing is attributed to the last caller.

## Setup
- `{task_1}` (**bulk**: `queue_timeout_secs: 3600`, no DLQ) is created at `T0` and never claimed.

## Expected outcome
- At `T0+3600s` the task ends `failed` with `result_code: timed_out` (no DLQ, PRD.md:524).
- History of {task_1} gains `taskTimedOut` with `payload.timeout_type = "queue"` and no `actor` (the item's `actor` is `null`).

## Side effects
- `history of {task_1} gains taskTimedOut with timeout_type = queue`.
- `event taskTimedOut for {task_1} is published to the task-events topic` (in the `lifecycle` preset).

## Notes
- Event schemas name the causing subject `actor` everywhere; `taskCreated.created_by` and `taskCancelRequested.requested_by` are renamed (G-SEC-11). Engine-caused events such as `taskTimedOut`, `slaBreached` and `waitTimedOut` have no actor, and the history item's `actor` is `null` (G-WIRE-10).
- Which terminal event(s) a queue timeout records (`taskTimedOut` and also `taskFailed`?) is for the timeouts area ([../timeouts/](../timeouts/)).
